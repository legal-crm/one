# Project Rules

## 배포 규칙
- 사용자가 "배포해"라고 하면 **Vercel 배포**와 **GitHub 배포(git add, commit, push)** 를 **둘 다** 수행한다.
- 순서: GitHub push → Vercel 프로덕션 배포 (또는 동시 진행)
- **git push 시 반드시** `$env:GITHUB_TOKEN = "";` 를 앞에 붙여 실행한다. (Antigravity 세션의 더미 토큰이 gh CLI 인증을 덮어쓰는 문제 방지)

## 디자인 품질 규칙 (taste-skill 기반 v1.0)

> 출처: [taste-skill](https://github.com/Leonxlnx/taste-skill)에서 본 프로젝트에 적합한 핵심 원칙만 추출.
> 이 규칙은 **새 코드 생성 시 가이드라인**이며, 기존 코드를 자동 변경하지 않는다.

### Rule 1. 인터랙티브 상태 완결성

모든 UI 컴포넌트는 다음 4가지 상태를 고려한다:

1. **로딩 상태**: Supabase 등 비동기 API 호출 영역에는 최종 레이아웃 형태의 **스켈레톤 로더**를 사용한다. 단순 원형 스피너(`animate-spin`)는 지양한다.
   - **예외**: `data.ts`의 Mock/동기 데이터를 즉시 렌더링하는 영역에는 스켈레톤이 불필요하다.
2. **빈 상태(Empty)**: 데이터가 없을 때 "어떻게 채울 수 있는지" 안내하는 아이콘 + 설명 + 액션 버튼 구성을 제공한다.
3. **에러 상태**: `window.alert()`를 사용하지 않는다. 대신:
   - 폼 검증 에러 → **인라인 메시지** (입력 필드 아래)
   - 일시적 알림 → **Toast** (`sonner` 라이브러리 사용)
   - 심각한 에러 → **에러 카드** (복구 버튼 포함)
4. **터치 피드백**: 버튼/카드의 `:active` 상태에 `scale(0.98)` 또는 `translateY(-1px)` 등 물리적 눌림 피드백을 적용한다. (기존 `.press-scale` 클래스 활용)

### Rule 2. 버튼 & CTA 품질 규칙

1. **명도 대비 필수 (WCAG AA)**: 모든 버튼 텍스트는 배경 대비 **4.5:1 이상**(본문) / **3:1 이상**(18px+ 대형 텍스트)을 충족한다.
   - 다크 배경(`bg-slate-950` 등)에서 `text-slate-600` 이하는 **금지**. 최소 `text-slate-400` 이상을 사용한다.
2. **버튼 줄바꿈 금지**: 데스크톱에서 버튼 텍스트는 반드시 **1줄**에 표시한다.
   - CTA 버튼에 `whitespace-nowrap`을 적용한다.
   - 모바일 터치 타겟은 최소 `min-h-[44px]`을 보장한다.
3. **중복 의도 CTA 금지**: 같은 뷰포트(한 화면) 안에서 동일 의도의 버튼을 중복 배치하지 않는다.
   - 예: "상담 시작" + "무료 상담" + "문의하기" → 하나로 통일
   - **예외**: 랜딩페이지의 스크롤 퍼널 앵커 CTA (Hero 상단 → 중간 → Final 하단에 동일 CTA 반복)는 허용한다.
4. **폼 대비 검증**: 입력 필드, placeholder, 포커스 링, 에러 텍스트 모두 WCAG AA 대비를 충족한다.

### Rule 3. 랜딩 섹션 다양성 & Eyebrow 절제

1. **섹션 레이아웃 반복 금지**: 동일 레이아웃 패밀리(예: 3열 카드 그리드)는 **2연속까지만** 허용. 3번째 연속은 반드시 다른 패턴으로 교체한다.
   - 대안 패턴: Split(좌우 분할), 타임라인, 가로 스와이프, 전체폭 인용, 인터랙티브 시뮬레이터
2. **지그재그 교대 제한**: "좌-이미지 + 우-텍스트" → "좌-텍스트 + 우-이미지" 교대 레이아웃은 최대 2연속까지.
3. **Eyebrow 절제**: 섹션 헤드라인 위의 소문자/uppercase 라벨(eyebrow)은 **3섹션당 최대 1개**. 페이지에 9개 섹션이 있다면 eyebrow는 최대 3개.
   - eyebrow 없이 헤드라인만으로 충분한 경우가 대부분이다.
4. **Hero 뷰포트 규율**:
   - 헤드라인은 데스크톱에서 **최대 2줄**, 부제(subtext)는 **20단어 이내**
   - CTA는 스크롤 없이 보여야 한다
   - Hero 상단 패딩은 `pt-24` (≈6rem) 이하
5. **네비게이션**: 데스크톱에서 **반드시 1줄**. 높이 최대 80px.

### Rule 4. 카피 자기감사 (한국어 법률 플랫폼용)

새 텍스트를 생성한 후, 출력 전에 다음을 자기검증한다:

1. **과장/단정적 표현 금지**: "전격 면책", "100% 보장", "기적의 솔루션", "획기적 탕감" 등의 광고성 수식어는 사용하지 않는다. (변호사법 광고 규정 준수)
2. **AI 특유의 부자연스러운 문구 감지**: 뜻이 불명확한 포장형 문구, 과도한 은유, 맥락 없는 감성적 표현은 평이한 한국어로 교체한다.
3. **가짜 정밀 숫자 금지**: 근거 없는 통계("92% 성공률", "4.1배 효과")는 사용하지 않는다. 실제 데이터 또는 `<!-- mock -->` 명시가 필수.
4. **하나의 문체 유지**: 같은 페이지에서 기술적 톤과 감성적 톤을 혼용하지 않는다.
5. **보존 용어**: 플랫폼 고유 기능명(`스텔스 가명`, `스텔스 보증`, `100% 익명`)과 `Disclaimers.tsx`의 법적 안내문구는 표준 용어로 유지한다. 이를 AI 과장 문구로 오인하여 삭제하지 않는다.

### Rule 5. 카드 & 그림자 일관성

1. **Border-Radius 3단계 계층** (하나의 스케일을 페이지 전체에서 일관되게 적용):
   | 용도 | Radius |
   |------|--------|
   | 페이지/모달 컨테이너 | `rounded-3xl` |
   | 섹션/그룹 카드 | `rounded-2xl` |
   | 인풋/개별 아이템/버튼 | `rounded-xl` |
   | 뱃지/칩 | `rounded-lg` |
   | 아바타/원형 요소 | `rounded-full` |
   - `rounded-[200px]` 같은 하드코딩은 금지. 위 계층 중 하나를 선택한다.

2. **그림자 토큰 우선**: `src/index.css`에 정의된 시맨틱 토큰을 우선 사용한다.
   - 기본: `shadow-xs`, `shadow-sm`, `shadow-md`, `shadow-lg`, `shadow-xl`
   - 브랜드: `shadow-premium`, `shadow-brand-sm`, `shadow-brand-md`
   - 인터랙티브: `shadow-glow`, `shadow-glow-hover`
   - 순수 검정 `shadow-black/30` 같은 하드코딩 그림자는 지양한다.

3. **카드 남용 방지**: 카드(`border` + `shadow` + `rounded`)는 실제 계층 구분이 필요할 때만 사용한다. 단순 그룹핑은 `border-t`, `divide-y`, 또는 여백(negative space)으로 처리한다.
