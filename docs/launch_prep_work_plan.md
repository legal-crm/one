# 마이김변 오픈 준비 작업 계획서 (통합본)

> 상위 문서: `docs/launch_master_plan.md` (서비스 출시 기획서). 이 문서는 그중 개발 작업의 세부 계획이에요.

- **기준일:** 2026-10-23
- **상태:** 기획 단계. 승인 전에는 구현하지 않아요.
- **구성:** 기획 v1~v4와 지금까지 받은 답변을 한 문서로 합쳤어요. 메모하신 26개 항목과 외부 문서 2건을 트랙으로 나눴어요 (10-24에 S·G·M 트랙 추가, 지금 11개).

## 1. 확정된 결정

| 구분 | 결정 |
|:---|:---|
| 진행 방식 | 기획·계획을 먼저 끝내고, 그 뒤에 구현 |
| 변호사 20명 | 명단은 사용자가 제공. 실제로 가입한 변호사만 '변호사 찾기'에 노출 |
| 상담 사례 | '예시'로 작성해 노출. 실제 사례가 생기면 일괄 삭제 |
| AI 진단 범위 | ① 변호사가 의뢰인에게 보내는 AI 진단 보고서 ② 법원 서류 작성 시 변제금 계산 |
| 의뢰인 화면 수치 | 예상 변제금·감면율을 보여주지 않음 (변호사가 보낸 보고서는 예외) |
| 공유 리포트 | 변호사가 보낸 보고서만 공유 가능 |
| 카톡 항목 | 메모 오기. 알림톡 구현 점검으로 바꿈 |
| 보안 | 통합어드민과 변호사 어드민에서 각각 설정. 고정 IP 없음. Vercel Pro는 필요하면 전환 |
| 실제 보정서 | 사용자가 `실제서류/보정서/`에 넣을 예정 |
| 안드로이드 | Android SDK로 APK를 빌드해 직접 설치. 테스트 폰 있음 |
| E2E 테스트 | 운영 환경에서 테스트 계정으로 진행 |
| 비용 | 경쟁사 요금을 조사한 뒤 조율 |
| 기본 특약 (10-24) | "기각 시 50% 환불"을 계약 위저드 기본 특약에서 **뺌** (사무소가 직접 넣는 선택 조항으로만) |
| 서버 저장 (10-24) | 업무 데이터는 **전부 서버 저장** (동기화·기록 보존). 브라우저 저장소는 화면 설정·캐시·초안 자동저장에만 |
| 출시 전 필수 실무 기능 (10-24) | G 트랙 중 **서버 백업·복원**, **예약 발송 스케줄러**만 출시 전. 나머지는 출시 후 |
| 영업 DB 수당 (10-24) | 예상 수당(Commission) 기능 **삭제**. 파트너사 탭은 **10-29 사용자 요청으로 '거래처(광고대행사)' 관리로 재구성**(리드를 위탁 수집해 보내 주는 대행사, SL-15~SL-17) |
| 공개 요청 (10-24) | 법률 위배로 **폐지 확정**. 단 코드에 아직 남아 있어 제거 작업 필요 (A-6) |
| HWPX 범위 (10-24) | **모든 양식** 데이터 채움 출력. PDF는 최종 다운로드 때 필요 |
| 변호사용 외부 AI 질의창 (10-24) | 만들지 않음 |
| 실제 결정문·사례 마케팅 (10-24) | 쓰지 않음. 예시·일반 정보만 |
| 세금 범위 (10-24) | 변호사가 낸 광고비에 대한 세금계산서 발행·관리만 |

- **현황:** 외부 AI(Gemini)로 개인정보가 나가는 경로는 진술서 AI, 통화 녹음 요약(음성), OCR 6종, 마케팅 생성이에요. 코파일럿은 외부 AI를 호출하지 않아요.
- **P-1. 전송 경로 점검 (1단계)**
  - 경로마다 정리해요: 무엇을 보내는지, 꼭 필요한지, 어디에 저장되는지, 원본은 언제 폐기되는지.

  - 개인정보 처리방침에 AI 처리 위탁이 들어갔는지 확인해요.
  - OCR과 음성은 보내기 전에 비식별화할 수 없어요. 약관 확인, 전송 최소화, 즉시 폐기로 관리해요.

  - NER 모델은 보완용 선택 기능으로만 둬요.
  - 의뢰인에게는 '가족·회사 이름은 가린 채 정리돼요'라는 안내와 가린 항목 수를 보여줘요.

### CM. 사건 관리 등뼈 — 이어지는 고객·사건 관리 (10-29 추가)

상세: `docs/launch_plan/20_case_management_flow_plan.md`. 지금 사건 관리는 단계별 작업 화면 6개를 한 장에 모은 것이고 단계 사이가 이어지지 않아요. 사건 = 상담 요청 번호라 사람 단위가 없고, 단계 기준이 네 벌(상태 8·13단계·화면 6·잠금)이라 '다음 단계로'가 저장되지 않으며 상태→단계가 한 칸씩 늦어요. 계약해도 서류 목록이, 접수해도 기일·할 일·안내가, 개시결정해도 변제 일정이 안 생기고, 상태 변경 알림톡은 쓰지 않는 칸반에서만 나가며, 단계 화면의 '알림톡/문자 발송'은 변호사 브라우저 메모예요(4단계 동의 요청은 가짜). 제안서 수임료·계약·사건번호·인가결정일이 다음 단계로 안 넘어가고, 6단계 연체는 저장 안 되는 숫자예요. 목록은 남의 공개 요청·삭제·시험 사건을 보여 주고 직원 제한이 없어요. 사건 하나가 jsonb 한 덩어리·한 번만 읽기·통째 덮어쓰기이고, 의뢰인은 기기 사본을 읽어요. 종결은 '취소' 하나, 결정일 = 오늘, 다시 열기·보관·5년 파기가 없어요. 경쟁사(리걸프렌즈)는 고정 사건 카드·순서대로 놓인 업무·작업에 따라 바뀌는 진행현황·사건번호 → 진행 자동 갱신·의뢰인 앱 기일·납입 알림, Clio는 단계 이동 때 할 일 자동 배정·의뢰인용 단계 이름이에요.

### ST. 설정 — 내 설정·사무소 설정, 서버 저장 (10-29 추가)

상세: `docs/launch_plan/21_settings_review.md`. 설정 화면 10개 중 서버 저장·실제 사용이 되는 것은 '내 프로필 편집'(실패 표시 없음)과 '보안·기기' 세션 목록뿐이에요. 'AI 및 상담 스타일 프로필'은 브라우저에만 저장되고 읽는 곳이 없어 금지 표현 필터·고지 삽입 안내가 사실과 달라요. 알림 연동은 연결 기본값 `true`·가짜 Chat ID로 처음부터 '연결됨'이고, 토큰은 탭 저장소라 브라우저를 닫으면 사라지며, 발송은 탭이 열려 있을 때 브라우저에서만 나가고 텔레그램에 지역·채무액·소득이 가요. 사무소명이 4곳(프로필·법인 명칭 카드·알림톡·광고 사업자 정보)에 있고 서식·알림톡은 광고 사업자 정보(브라우저)를 읽어요. 도장은 만들어도 서버·문서에 안 가고 자동 날인 토글을 읽는 곳이 없어요. ### OP. 통합어드민 운영 — 대시보드·상담 요청 관제·변호사 심사·계정 관리·보안 관제 (10-29 추가)

'광고 상품'의 신청 버튼은 창이 '사업자·세금계산서' 탭 안에 있어 반응이 없고, 소수점 할인가를 잘못 읽어 메인 배너 12개월·상단 노출 6개월이 10배로 계산되며, 변호사 화면은 VAT를 빼고 관리자 화면은 VAT 포함으로 봐서 입금액과 세금계산서가 어긋나요. 남은 구좌는 고정된 가짜 숫자예요. 주문은 브라우저에 먼저 저장되고(서버 실패 숨김) 변호사 화면은 서버를 읽지 않아요. 입금 확인은 주문 상태만 바꾸고 고객 화면이 보는 `lawyers.ad_tier`를 바꾸지 않으며, 만료일은 버튼 누른 시각 기준이고 만료 처리·갱신·대기 주문 거절이 없어요. 사업자 정보는 브라우저에만 있고, 변호사 '세금계산서 보기'는 항상 403, 관리자 계산서 합계는 글자 이어붙이기, 팝빌은 설정이 없으면 운영 모드예요. 상품 문구에 '추천 변호사'·'지역 전담'·'리포트 제공'·'2지역 10% 할인'(없는 기능)이 남아 있어요.
