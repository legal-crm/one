## 0. 한눈에 보는 결론 (10-29 OP-Q1~Q7 추천안대로 결정으로 개편 방향 확정)

**다섯 메뉴 중 서버 기준으로 제대로 움직이는 것은 '변호사 승인'과 '세션 목록·계정 전면 차단'뿐이에요.** 나머지는 브라우저 사본을 읽거나, 화면만 바꾸거나, 처음부터 동작하지 않는 표시예요.

1. **대시보드 숫자 대부분이 시험 데이터예요.** 첨부 화면의 '상담 신청 9건'은 운영에 넣는 사건 관리 시험 사건 9건(`STAGE_TEST_REQUEST_IDS`)이고, '계약 체결 4건·체결률 44%'도 그 9건 중 4건(서류·접수·계약 상태)이에요. '신청 채무 총액 7.3억'도 시험 사건 채무 합계가 섞여 있어요. 서버에서 지워진 요청도 브라우저 사본에서 안 지워져 계속 세어져요.
2. **회원 수·가입 추이·회원 모니터링은 관리자 브라우저 목록이에요.** 회원 행은 의뢰인 자기 브라우저에서만 만들어지고 서버 `members` 테이블은 쓰는 코드가 없어요. 그래서 운영 관리자 화면의 회원은 사실상 0명이고, **회원 '정지·탈퇴'는 의뢰인·변호사에게 전혀 전달되지 않아요.** 화면 문구("즉시 모든 포털의 로그인 세션이 끊기고")는 사실과 달라요.
3. **관리자가 상담 요청 원문·재무 정보를 전부 받아요.** 이름·전화번호는 화면에서 가리지만, 관리자 브라우저가 `consult_requests` 전체 칸(실명·전화·소득·채무·배우자 재산·도박/투자 손실·본문)을 받아 브라우저에 저장하고, 상세 화면에 재무표·본문 전체를 보여 줘요. 제로날리지 원칙(관리자는 서류·상담 원문 열람 불가)은 상담 요청 자체에는 적용돼 있지 않아요.
4. **'장기 미응답 → 오픈 매칭으로 재공개' 버튼이 남아 있어요.** 10-24에 폐지한 공개 요청을 관리자가 다시 여는 기능이고, '매칭' 문구도 금지어예요. 응답 기한(LD-Q2 2영업일)·의뢰인 안내는 없어요.
5. **변호사 심사에 반려·보완 요청이 없어요.** 승인·정지만 있고 사유 저장·변호사 알림이 없어, 변호사는 대기·반려·정지를 모두 같은 '⏳ 심사 대기' 화면으로 봐요. 정지해도 이미 로그인한 변호사 화면은 다시 로그인할 때까지 그대로이고, 정지하면 승인 이력(`approved_at`)이 지워져요. '등록번호 확인' 배지는 대조 기록이 아니라 승인 여부와 같은 뜻이고, **승인 전 대기자의 등록번호도 공개 조회돼요.** 초대받은 직원이 '승인 대기 변호사'로 섞여 사이드바 배지 '3'에 들어가요.
6. **보안 관제의 '이상 징후'는 영원히 0이에요.** 감지 코드가 없고 위치 칸은 늘 비어 있어요(해외 차단 불가). 단일 '강제 종료'는 상대 브라우저가 따라 줄 때만 끊기고(60초 확인, 안내는 '15초'), 사용자가 자기 세션 행을 다시 'active'로 바꿀 수 있어요. 로그인 기록은 이 브라우저 50건뿐이고, 관리자 조치 기록은 자유 문구라 누가 무엇을 바꿨는지 찾기 어려워요. 허니팟 기록 화면은 '매칭 정책' 탭에 있어요.
7. **가짜 '실시간' 표시:** 헤더·사이드바 '실시간 운영 모니터링 가동 중', 보안 '정상 운영' 배지는 상태와 무관한 고정 표시예요. 실제 갱신은 60초 폴링·Realtime이고, 'DB·인증 서버 정상'은 인증 서버 한 곳만 확인해요. 오류 수집·가동 감시 도구는 없어요.

**개편 방향:** 통합어드민을 '운영자가 매일 처리할 일'을 중심으로 다시 짜요. ① 모든 숫자를 서버 집계로(시험 데이터 제외), ② 관리자 열람 범위를 상담 요청 '운영 정보'로 줄이고 원문은 신고 처리 때만 사유를 남기고 열기, ③ 심사·회원·세션 조치가 서버 상태를 바꾸고 변호사·의뢰인 화면에 바로 반영, ④ 응답 기한·신고·개인정보 요청·보안 경고를 '오늘 처리할 일' 한 목록으로, ⑤ 모든 관리자 조치를 바뀐 값과 함께 기록.

## 3. 개편 설계

### 3-1. 공통 바탕: 서버를 기준으로 (OP-1·OP-2)

- **시험 데이터 제외(OP-1, HM-1과 같은 작업):** 운영 빌드에서 `STAGE_TEST_REQUEST_IDS` 주입 중단(시험이 필요하면 별도 시험 계정·식별 접두어로 서버에 만들고 통계에서 제외), 관리자 지표는 `is_test` 표시된 행 제외.
- **관리자 데이터는 서버만(OP-2):** 관리자 화면은 App 전역 `requests`·`members`를 쓰지 않고 관리자 전용 RPC로 페이지 단위 조회. 관리자 브라우저에 상담 요청·회원 정보를 저장하지 않음(메모리만). 지금의 '병합만 하고 지우지 않는' 방식 대신 서버 결과로 교체.
- **집계 함수:** `admin_platform_metrics(p_from, p_to)` — 상담 요청 상태별·기간별 수, 정리 완료(OP-4 이벤트) → 요청 → 첫 응답 → 상담 시작 → 계약 상태 흐름, 첫 응답 시간 분포, 응답 기한 초과 수, 승인 변호사 수·대기 수(직원 제외), 광고 입금·노출(AD 서버 값), 회원 수(OP-9). 매일 새벽 `platform_daily_metrics` 스냅샷(G-1)으로 추이·전기 비교.
- **관리자 조치는 RPC로만:** 모든 쓰기(심사·정지·숨김·회원 상태·메모·정책)를 SECURITY DEFINER 함수로, 함수 안에서 `admin_actions`(조치자 uid·이메일·조치·대상·이전 값·이후 값·사유·IP·시각, 추가만)에 기록. 기존 `admin_audit`은 이 표로 통일.

### 3-2. 대시보드 → '오늘 처리할 일' + 지표 (OP-3)

- **처리할 일(맨 위):** 변호사 심사 대기(경과일·1~2영업일 약속 넘긴 것 강조), 보완 요청 회신, 승인 뒤 변경 재확인(LD-Q5), 광고 입금 대기·소재 심사·만료 임박(AD), 1:1 문의 미답변, 신고 미처리, 응답 기한 넘은 요청, 개인정보 요청(기한 D-n), 보안 경고, 서버·외부 서비스 이상. 각 줄 → 해당 화면으로.
- **지표:** 기간 선택(오늘·7일·30일·이번 달), 전기 대비, 시험 데이터 제외 표시. 카드: 정리 완료 / 상담 요청 / 첫 응답(중앙 시간) / 상담 시작 / 계약 이후 상태 / 승인 변호사 / 광고 매출(공급가 기준, AD) / 노출 중 광고(실제 노출 기준).
- **'변호사별 실적' → '변호사 응답 현황':** 받은 요청·응답률·중앙 응답 시간·기한 초과 건수. 정렬 기본 = 기한 초과 많은 순(운영 개입이 필요한 순). **계약 수 순위는 빼요**(광고 가치를 계약으로 보여 주지 않는 AD 결정·제34조 오해 방지, OP-Q6).
- **'신청 채무 총액' 카드 삭제**(운영에 쓰는 값이 아니고 시험·지워진 요청이 섞임). 필요하면 채무 구간별 분포(1억 미만·1~3억…)만.
- **상태 표시:** '실시간 가동 중' 대신 '마지막 갱신 ○초 전 · 새로고침'. 서버 상태 카드는 `api/health`(DB 쿼리·함수·팝빌·Gemini 키·CODEF·Turnstile 키 유무, 관리자만) + 외부 가동 감시(L6) 결과.

### 3-3. 의뢰인 모니터링 → '상담 요청 관제' (OP-5~OP-7)

- **이름:** '의뢰인 모니터링' → **'상담 요청 관제'**(관리자가 의뢰인 개인을 감시하는 것처럼 읽히지 않게).
- **열람 범위(OP-5, OP-Q1):** 관리자 전용 뷰 `admin_consult_overview` — 요청 번호·가명·상태·생성/갱신 시각·지정 변호사 수·응답 수·첫 응답 시각·시·도·채무 구간·진입 경로·숨김·신고 여부·기한. 실명·전화·재무 상세·본문은 기본으로 내려보내지 않아요. **신고나 스팸 검토 때만** '원문 보기'를 눌러 사유를 고르고(신고 처리·스팸 판단·분쟁 확인·법령 요청), 그때 본문·필요 항목만 서버 함수가 내려주며 `admin_actions`에 남겨요. 재무표·DTI·퇴직금 반영 문구는 삭제.
- **응답 기한(OP-6, OP-Q2):** 지정 요청마다 기한 = 요청 시각 + 2영업일(LD-Q2). 넘으면 ① 의뢰인 화면·알림 "선택한 변호사 중 아직 답이 없는 분이 있어요. 다른 변호사를 고를 수 있어요"(자리 반환 LD-1), ② 해당 변호사에게 상기 알림 1회, ③ 관리자 목록 '기한 초과'. **'오픈 매칭으로 재공개' 버튼·RPC 삭제**(A-6).
- **상태 변경 제한:** 관리자가 고칠 수 있는 것은 숨김/해제와 '운영 종료(사유)'뿐. 계약·상담 상태는 당사자 기록으로만 바뀌어요(CM-3).
- **신고함(OP-7):** `consult_reports`(신고자 역할·요청/대화 번호·유형: 추가 비용 요구·연락 두절·부적절 언행·스팸 요청·개인정보·기타·내용·첨부) → 관리자 처리(접수 → 확인 중 → 소명 요청 → 조치 완료/기각, 결과 안내). 대화 원문은 신고자가 첨부한 부분만 보고, 관리자가 대화방 전체를 여는 기능은 만들지 않아요(제로날리지). 의뢰인 대화방·변호사 상담 요청 화면에 '신고하기'.
- **관리자 메모:** 서버 `admin_notes`(관리자만, 대상 요청·변호사·회원).

### 3-4. 변호사 심사 (OP-8)

- **심사 대기열(서버):** `admin_list_lawyer_applications` — `lawyer_accounts` 기준(프로필 저장 실패 가입자도 보임), 직원 초대 가입자는 제외(RB-2). 상태: 서류 미제출 / 심사 대기 / 보완 요청 / 승인 / 반려 / 정지 / 탈퇴. 제출 일시·경과 영업일 표시.
- **심사 화면:** 등록증(비공개 저장소, 승인 뒤에도 열람) · 실명·등록번호·등록 연도 대한변협 대조 칸(대조일·대조자 자동 기록, LD-5) · 사업자번호는 서버가 국세청 상태를 다시 조회(팝빌 `check-corp`, 관리자만) · 공개 최소 조건 체크(LD-Q4) · 소개 문구 금지 표현 경고(M-9, '[운영자 판단]').
- **처리 버튼:** 승인 / 보완 요청(항목 체크 + 메모) / 반려(사유 선택 + 메모) / 정지(사유·기간 선택). 모두 `lawyer_review_events`(추가만)에 남기고 `approved_at`을 지우지 않아요.
- **변호사 쪽:** 대기 화면을 상태별로 나눠요 — '심사 중(○영업일째, 1~2영업일 안내)' / '보완이 필요해요(항목·메모, 다시 제출)' / '승인되지 않았어요(사유·문의)' / '이용 정지(사유·기간·문의)'. 결과는 이메일 + 앱 안 알림, 계정 상태는 실시간 구독으로 바로 반영. 잘못된 법조항 문구('변호사법 제34조 … 자격 검증 의무') 삭제.
- **정지:** 서버 승인 해제 + `admin_revoke_auth_sessions` + 변호사 찾기 숨김 + 진행 중 상담 요청 의뢰인에게 "이 변호사는 지금 상담을 받을 수 없어요" 안내와 자리 반환. 사무소 사건 데이터는 사무소 소유라 지우지 않아요.
- **공개 범위:** `lawyers` 익명 조회를 '승인된 공개 프로필'만으로 좁혀요(대기·반려·정지 행과 등록번호 비공개).
- **등록증 이미지 보관(OP-Q4):** 승인·반려 확정 30일 뒤 이미지 삭제, 대조 기록(등록번호·대조일·대조자)만 보관.
- **정리:** '이달 매칭수'·'정식 파트너'·'매칭' 문구 삭제(받은 요청·응답률로), '🤖 AI 유료 기능 관리' → '부가 기능 이용'(15장 과금 모드의 변호사별 예외), 메모 덮어쓰기 버그, 관리자 브라우저 평문 저장 삭제.

### 3-5. 회원 모니터링 → '계정 관리' (OP-9~OP-11)

- **서버 출처(OP-9):** 관리자 전용 API(서비스 롤, 기존 함수 경로 안 라우트)가 `auth.users`(가입일·마지막 로그인·로그인 수단) + `client_aliases`(가명) + `lawyer_accounts` + `staff_members`를 합쳐 페이지 단위로 내려줘요. 이메일·전화는 마스킹, 검색은 가명·계정 번호·이메일 앞부분.
- **계정 상태(OP-10):** `account_status`(uid·상태 active/suspended/withdrawn·사유·기간·조치자). 정지 → 세션 폐기 + 로그인 때 서버 확인(의뢰인·변호사 공통) + 주요 RLS 도우미 `is_account_active()`. 화면 문구는 실제 동작대로.
- **휴면 기능 삭제(OP-Q5):** 2023년 개정으로 1년 미이용자 분리보관(유효기간제) 의무가 없어진 것으로 알고 있어요(R6 자문 때 확인). 대신 보유 기간 자동 파기(미연결 1년·탈퇴 즉시·종결 5년, CM-9와 같은 작업)를 서버 작업으로 돌리고, 파기 예정 30일 전 안내·파기 기록(`privacy_purge_log`, 무엇을 몇 건 지웠는지만).
- **탈퇴:** 의뢰인 본인 탈퇴(마이페이지) + 관리자 처리 공통 함수 — 계정 삭제, 상담 요청·메시지 파기, 사무소로 넘어간 사건은 사무소 보관 규정에 따름(안내 문구 R6 확인).
- **개인정보 요청함(OP-11):** `privacy_requests`(열람·정정·삭제·처리정지·동의 철회, 접수일·처리 기한 = 접수 + 10일, 담당·결과·안내일). 의뢰인 마이페이지·변호사 설정·1:1 문의에서 접수, 대시보드 처리할 일에 D-n.
- **활동 기록:** 서버가 확인한 사용자·역할만 표시(브라우저가 써 넣는 이름·역할 표시 중단), 계산기·Q&A 열람 같은 행동 추적 항목은 빼고 계정 이벤트(가입·로그인·정지·탈퇴·요청 생성)만.
- **'파트너 회원'** → '변호사·직원'.

### 3-6. 보안 & 세션 관제 (OP-12~OP-15)

- **세션 무결성(OP-12):** `user_sessions` UPDATE 트리거 — 본인은 `last_active_at`과 'active → revoked'만 바꿀 수 있고 `user_role`·`ip_address`·`is_suspicious`·되살리기는 거부. 등록 때 Supabase 세션 번호(`auth.jwt()->>'session_id'`)를 함께 저장해 **단일 강제 종료도 그 로그인 세션만 서버에서 폐기**(`admin_revoke_auth_session`). 직원은 'STAFF'로 등록(RB-2), 날짜는 한국 시간, ipify 조회 삭제(서버 헤더만).
- **이상 징후 감지(OP-13, OP-Q3):** 세션 등록을 서버 경로로 옮겨 국가(`x-vercel-ip-country`)를 기록하고, 서버가 규칙으로 표시 — 처음 보는 기기·국가, 짧은 시간 안 국가 변경, 로그인 실패 급증, 동시 세션 과다, 허니팟 반복 IP. 경고는 처리할 일 목록 + 관리자 텔레그램/이메일(이름 없이 건수·링크). **자동 차단은 관리자 계정의 해외 접속만**, 변호사·직원은 사무소 정책(RB-7)으로.
- **보안 정책 화면(OP-14, A-2):** 플랫폼 기본값 — 관리자: 2단계 인증 필수(지금도), 새 기기는 다른 관리자 승인 또는 이메일 확인, 해외 차단, 미활동 30분. 변호사 사무소 기본값: 대표 2단계 인증 필수·직원 기본 필수(RB-Q 결정), 새 기기 알림. 사무소는 더 강하게만 바꿀 수 있음.
- **관리자 조치 기록 화면(OP-15):** `admin_actions` 조회(기간·조치자·종류·대상), 바뀐 값 비교, 월 1회 점검 표시(RB 결정과 같은 방식). 로그인 기록은 서버(`audit_logs` 로그인 이벤트) 기준으로, 이 브라우저 기록 삭제.
- **기록 위조 막기:** `audit_logs` 익명 직접 INSERT 막기 → 허니팟·정리 완료·익명 이벤트는 요청 제한이 있는 서버 경로로만. 표시 역할은 서버 확인값만. `copilot_audit_logs` 조회 범위를 사무소로(CV).
- **보관:** 세션 1년, 관리자 조치·보안 기록 2년(RB 활동 기록 2년과 같게), 정리는 서비스 롤 절차 + 정리 기록.
- **위치:** 허니팟 기록을 이 메뉴로 옮겨요. 'Kill-Switch'·'Lockdown'·'Current Device' 같은 영어 문구 한글로, 가짜 '정상 운영'·'실시간 세션 활성 중' 배지 삭제, 'my김변 본사 관제센터' → '마이김변 운영'.

### 3-7. 화면 공통 (OP-16)

이모지 삭제(카드·옵션·제목), 10~11px 글자 → 14px 이상, 44px 터치, `rounded-[200px]`·없는 클래스(`text-slate-350`·`text-rose-450/455`·`border-slate-750`·`py-0.2`·`bg-*-650`·`bg-yellow-550`) 정리, 어두운 배경 위 `text-slate-600` 대비, 영어 머리말('CLIENT INFO MONITORS'·'DETAILS'), 헤더 '통합 통합' 오타, 로딩 스켈레톤·오류 카드·빈 상태 안내, 페이지 번호 전부 나열 → 앞뒤 5개.

## 6. 완료 기준

- 운영 대시보드·목록에 시험 사건이 없고, 같은 기간 숫자가 어느 관리자 기기에서나 같아요. 서버에서 지운 요청은 다음 갱신 때 화면에서도 사라져요.
- 대시보드 맨 위 '처리할 일'에서 심사 대기·입금 대기·문의·신고·기한 초과·개인정보 요청·보안 경고를 모두 볼 수 있고, 누르면 해당 화면이 열려요.
- 관리자 브라우저 저장소에 상담 요청의 실명·전화·재무 정보가 없어요. 원문을 열면 사유와 함께 조치 기록에 남아요.
- 지정 요청이 2영업일 동안 응답이 없으면 의뢰인 화면에 '다른 변호사 고르기' 안내가 뜨고 자리가 돌아와요. '오픈 매칭' 문구·버튼·RPC가 코드에 없어요.
- 의뢰인이 대화방에서 신고하면 관리자 신고함에 들어오고, 처리 결과가 의뢰인에게 안내돼요.
- 변호사 가입자를 '보완 요청'하면 변호사 대기 화면에 항목·메모가 보이고 다시 제출할 수 있어요. 승인하면 변호사가 다시 로그인하지 않아도 1분 안에 포털이 열려요. 정지하면 1분 안에 '이용 정지' 화면으로 바뀌고 로그인 세션이 서버에서 끊겨요. 승인 이력은 남아요.
- 직원 초대 가입자는 심사 목록·배지에 없어요. 승인 전 변호사 행·등록번호는 익명으로 조회되지 않아요.
- 회원을 정지하면 그 사람이 다른 기기에서 로그인해도 막히고, 화면 문구가 실제 동작과 같아요. '휴면' 버튼이 없어요.
- 사용자가 자기 세션 행을 'active'로 되돌리거나 역할을 바꾸려 하면 서버가 거부해요. 단일 강제 종료가 그 로그인 세션을 서버에서 끊어요.
- 관리자 조치 기록 화면에서 '누가·언제·무엇을·이전 값 → 이후 값·사유'를 찾을 수 있어요. 익명으로 `audit_logs`에 직접 쓸 수 없어요.
- 화면에 '실시간 가동 중'·'정상 운영' 같은 고정 배지, 이모지, 10~11px 글자, 금지 문구('배정'·'매칭'·'파트너')가 없어요.
