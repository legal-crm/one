1. **분리 원칙:** 마이김변 업무폰 앱·서버·DB·계정·키는 LeadMaster와 아무것도 공유하지 않아요. LeadMasterApp 소스는 복사하지 않고 새 프로젝트로 작성해요. 마이김변 코드에 남아 있는 LeadMaster 이식 흔적(테이블 4개, 구글 드라이브 업로드, 'LeadMaster 100% 호환' 주석·문구)은 정리해요(2장, CL-0).

3. **새로 만드는 것:**
   - **마이김변 업무폰 앱(가칭):** 등록된 의뢰인·리드 번호와의 통화·문자만, 통화가 끝나면 바로 올려요. 휴대폰 기본 통화 녹음 파일을 찾아 전자지문과 함께 자동 업로드하고, 통화 직후 메모·다음 연락 예약을 받아요.

   - **AI:** 화자 구분·단어 단위 시각이 붙은 대화록 + 이름·번호를 가린 요약, 버전으로 쌓기.

## 3. 법적 기준 (출시 전 R6 자문 확인 대상)

1. **녹음 자체:** 통신비밀보호법은 '타인 간' 대화의 녹음·청취를 금지해요. 대화 당사자의 녹음은 이 법 위반이 아니라는 게 대법원 판례예요(대법원 2006. 10. 12. 선고 2006도4981). 사무소 직원이 자기 통화를 녹음하는 것은 당사자 녹음이에요. 당사자 녹음에도 상대 동의를 요구하는 개정안이 발의된 적이 있지만 시행 법률은 아니에요. 출시 전에 다시 확인해요. [참고: 국내 녹음 법률 요약](https://www.recordinglaw.com/ko/world-laws/world-recording-laws/south-korea-recording-laws/)
2. **저장·AI 변환은 개인정보 처리예요.** 녹음을 서버에 보관하고 구글 AI로 변환하면 수집·이용 고지, 처리 위탁, 국외 이전 고지 대상이에요. 역할은 기존 결정(L4)대로 **사무소 = 개인정보처리자, 마이김변 = 수탁자**.
3. **비밀유지(변호사법 제26조)·제로날리지:** 통합관리자는 통화·문자·녹음·대화록을 열 수 없어야 해요(저장소 포함). 지금 026 정책은 관리자도 열 수 있어 고쳐요.
4. **증거로 쓸 때:** 원본 녹음과 같은 파일이라는 점(전자지문 일치)을 보여 줄 수 있어야 해요. 법원에 내는 녹취록은 보통 따로 작성해요. **AI 대화록은 업무 참고용**으로 표시해요.
5. **직원 개인정보:** 앱이 직원 휴대폰의 통화·문자를 다루니 직원에게 알리고 동의를 받아요. 등록 번호만 올리므로 직원 사생활 통화는 서버로 가지 않아요.
6. 사무소 내부 업무 기록이라 알선·광고 원칙과 무관해요. 브리핑에도 '전담·배정·탕감' 같은 금지어나 변제금·탕감률 판단을 넣지 않아요.

## 4. 사건 화면·서버 설계

### 4-1. 화면 (변호사 어드민 › 사건 관리)

```
┌ 사건 머리(기존): 가명·실명(공개 후) · 사건 유형 · 단계 · [📞 업무폰으로 걸기] [💬 문자] ────────────────┐
├ 고객 종합 브리핑 (변호사용 · AI 정리 · 확인 전/확인함) — 접기·펼치기 · 복사 · 근거 통화 n건 ───────────┤
│ 1~6단계 화면 (기존)                                 │ 오른쪽 패널 380px (1280px 미만은 서랍)       │
│                                                     │ [소통 기록] [녹음·대화록] [메모] [할 일]      │
│                                                     │ 소통 기록: 최근 통화·문자·알림톡 10건, 필터    │
│                                                     │ 녹음·대화록: 플레이어 + 요약/대화록 + 검색     │
│                                                     │ [크게 보기] → 가운데를 '소통 기록' 전체 화면으로 │
└─────────────────────────────────────────────────────┴───────────────────────────────────────────┘
```

- **소통 기록 전체 화면:** 왼쪽 대화창형 타임라인(통화·문자·알림톡·채팅 요약·제안서 발송·계약 서명·서류 요청·단계 변경, 유형 필터·검색), 오른쪽 문자 템플릿·발송 상태, 선택한 통화의 녹음·대화록. 통화 줄에는 방향·길이·회선·기기(직원)·녹음 유무·메모 표시.
- **녹음·대화록:** 서버 서명 주소(5분)로 `<audio>` 재생, 대화록 시각을 누르면 그 위치로 이동. 요약 / 대화록 탭, 검색, 화자 이름 바꾸기(화자 1 → '사무소'·'의뢰인'), '메모로 보내기'(통화와 연결, 중복 방지), '수정본 만들기'(AI 원본 유지). 대화록 위에 "AI 자동 변환 · 원본 녹음이 기준".
- **고객 종합 브리핑 칸:** 상황 요약 / 확인된 사실 / 확인 필요 / 다음 할 일 / 특이사항. 버전 저장, '다시 만들기'·'확인함', 문장마다 근거 통화 링크.
- **메모:** 서버 테이블(S), 유형(상담·통화·보정·일반) + 연결 통화. 'thread' 유형 유실 수정.
- **할 일:** 사건 할 일·일정(일정 탭·퀵툴 미니 일정과 같은 데이터, T-5). 앱의 '다음 연락 예약'이 여기로 들어와요.
- **지우는 것:** 고정 생계비표·'예상 탕감률'(의뢰인 정보는 '의뢰인 정리 자료' 카드 I-4로), 가짜 통화 길이 180초, `select-none`.
- **설정 › 업무폰 (새 화면):** 'QR로 연결', 기기 목록(직원·기기 이름·앱 버전·마지막 접속·대기 업로드·올리지 못한 녹음), 해지, 대표 승인(A-2), 사무소 정책(자동 대화록 켬/끔, 녹음 업로드 네트워크 '와이파이만/모두', 앱 문자 발송 허용·하루 한도·발송 금지 시간, 직원 고지 문구), 앱 설치 파일 내려받기(로그인한 사무소만).
- **등록 요청함:** 앱에서 "이 번호 등록"을 누른 번호 목록 → 사건·리드에 연결하거나 무시.
- **영업 DB(리드)도 같은 부품**을 써요. 리드 → 사건 전환 시 기록을 복사하지 않고 연락처 연결을 옮겨요.

### 4-3. 기기 API (`api/device.js`, 새 서버 함수 1개 → 함수 9개, Pro 전환 결정과 무관하게 한도 안)

| 경로 | 하는 일 |
|:---|:---|
| `POST /api/device/pair` | QR 코드 + 기기 정보 → 기기 등록(대표 승인 대기 또는 승인됨), 기기 토큰(256비트 난수, 서버엔 해시만) 발급 |
| `POST /api/device/session` | 기기 토큰 → 1시간짜리 접속 토큰(사무소·기기·직원 정보 포함, 서버 비밀값 서명). 해지된 기기는 거절 + '데이터 지우기' 지시 |
| `POST /api/device/heartbeat` | 앱 버전·권한 상태·대기 건수·시계 차이 보고, 정책·최신 버전 받기 |
| `GET /api/device/contacts?since=` | 사무소 연락처 번호 해시 목록(사무소별 소금값 + SHA-256), 바뀐 것만 |
| `GET /api/device/lookup?h=` | 번호 해시 1건 → 표시용 정보(가명·단계·다음 할 일) |
| `POST /api/device/logs` | 통화·문자 기록 묶음(최대 200건), 기기 기록 키로 중복 무시, 받은 키 목록 회신 |
| `POST /api/device/recordings/init` → `complete` | 녹음 등록 → 서명 업로드 주소 발급 → 업로드 후 지문·크기 보고 → 서버가 지문 재계산·비교 → 대화록 작업 등록 |
| `POST /api/device/notes` | 통화 메모·다음 연락 예약 |
| `POST /api/device/register-request` | 모르는 번호 등록 요청(번호·통화 시각) |
| `GET /api/device/commands`, `POST …/commands/{id}/result` | 명령 받기(푸시 누락 대비), 결과 회신 |
| `POST /api/device/unpair` | 앱에서 연결 해제 |

- 모든 경로: 접속 토큰 확인, 기기별 요청 수 제한(`_lib/rate-limiter.js`), 개인정보는 로그에 남기지 않음.
- 푸시: 마이김변 전용 Firebase 프로젝트의 FCM(HTTP v1, 서버 환경변수 `FCM_SERVICE_ACCOUNT`). 푸시에는 "새 명령 있음"만 담고 내용은 앱이 API로 받아요.
- 녹음 업로드: Supabase Storage 서명 업로드 주소. 1시간 통화 녹음은 약 30MB 안팎(기종·음질마다 다름)이라 일반 업로드로 시작하고, 끊김이 잦으면 이어 올리기(TUS) 방식을 붙여요. 저장소 파일 크기 한도는 Pro 설정에서 올려요.

### 4-4. 녹음 → 대화록 → 요약

1. 서버 지문 확인이 끝나면 작업 큐에 등록(사무소 설정 '자동 대화록', 기본 켬). 처리는 서버 함수 또는 예약 작업(G 스케줄러)에서 해요.
2. **대화록:** `gemini-3.5-transcribe`, 화자 분리 + 단어 단위 시각. 이 기능을 켜면 한 요청이 30분까지라 긴 녹음은 30분 단위로 나눠 이어 붙여요. 화자 분리와 용어 사전은 함께 못 써서 용어 보정은 요약 단계에서 해요. [Gemini 3.5 Transcribe](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-transcribe)
3. **요약:** 대화록 글의 의뢰인·가족·채권자 이름과 번호를 역할 토큰으로 가리고(P-7) 요약 모델에 보낸 뒤 되돌려 저장. 음성은 가릴 수 없으니 유료 등급 키(R8)만 써요. 100MB가 넘는 요청은 Files API. [Files API](https://ai.google.dev/gemini-api/docs/files)
4. 지금의 3MB 제한, 프롬프트의 이름·번호 평문, 화면의 'Gemini 3.5' 문구는 없애요. 브라우저에서 AI를 부르지 않아요.

### 4-5. 증빙

- **전자지문:** 녹음(기기·서버 SHA-256), 기록(내용 지문), 대화록 버전(원본 녹음 지문 포함). 블록체인 대신 서버 전자지문으로 한 기존 결정과 같은 방식.
- **변경 불가:** 기록·녹음·AI 원본은 사무소 사용자가 고치거나 지울 수 없어요. 잘못 연결된 기록은 '연결 변경'(이력), 대화록 수정은 새 버전. 삭제는 보관 기간 만료 자동 파기 또는 대표 '파기 요청'(사유·2단계 인증)만, 지문·파기 기록은 남겨요. 분쟁 중 사건은 '분쟁 보존'.
- **열람 기록:** 재생·내려받기·내보내기·대화록 열람.
- **증빙 내보내기(CL-10):** 사건·기간 → ZIP(원본 녹음 + 통화·문자 목록 PDF(일시·방향·길이·회선·기기·지문) + 대화록 PDF('AI 자동 변환' 표시) + 지문 목록 파일). PDF는 H-7 글자 PDF 엔진.

### 4-6. 문자·알림톡

- 정형 안내(서류 요청·기일·납부)는 팝빌 알림톡·문자로 서버 발송(CL-Q4 추천), 개별 대화 문자는 업무폰 앱 직접 발송.
- 발송 상태(대기·업무폰 전달·발송 완료·도착·실패) 표시, **실제 결과가 온 뒤에만 '보낸 문자'로 기록**.
- 템플릿은 사무소 단위, 변수(가명·사건번호·기한·계좌), 금지 표현 검사. 기존 시드 '회생파산 전담센터' 삭제.
- 새 통화 요약 알림은 내용 없이 "○○ 사건 새 통화 요약 + 링크"만(텔레그램·이메일 알림 설정 사용).

### 4-7. 고지·보관

- **처리방침·약관(A-3):** 통화 기록·문자·녹음·AI 대화록 항목, 수탁자(Supabase·Google), 국외 이전, 보관 기간.
- **의뢰인 고지:** CL-Q3. **직원 동의:** 앱 첫 실행과 웹 기기 연결 때 한 번씩, 동의 기록 서버 저장.
- **보관:** 기존 결정(L7) 연결 안 된 리드 1년, 사건 종결 후 5년. 사무소가 더 짧게 정할 수 있어요. 파기는 G 스케줄러, 파기 기록 보관.

### 5-3. 통화·문자 수집 흐름

1. **연락처 목록:** 연결 직후와 6시간마다(웹에서 연락처가 바뀌면 푸시로 즉시) 번호 해시 목록을 받아 기기 안에 보관. 해시는 번호를 그대로 들고 있지 않으려는 최소화 장치이고, 번호 수가 적어 완전한 비밀은 아니에요. 그래서 그 사무소 번호만 내려 주고 해지 시 지워요.
2. **통화 종료 감지:** 전화 상태 변경 방송 수신기(앱이 꺼져 있어도 안드로이드가 깨워 주는 예외 방송)로 '통화 끝남'을 받으면 3초 뒤 급한 작업을 예약 → 통화 기록에서 새 항목을 읽어요. 상시 실행 알림은 기본으로 쓰지 않고, 삼성 기기에서 놓치는 경우가 확인되면 '상시 실행 모드'(작은 고정 알림)를 켤 수 있게 해요.
3. **문자:** 받은 문자는 수신 방송으로 즉시, 보낸 문자는 문자 저장소 변경 감지 + 15분 보정 작업으로 읽어요. MMS는 글자만(첨부 업로드는 ⚪).
4. **고르기:** 번호 정규화(`+82`→`0`, 숫자만) → 해시 → 목록에 있는 번호만. 수집 회선이 아닌 SIM의 기록은 버려요.
5. **보낼 목록:** Room에 기기 기록 키(통화 기록 ID + 시각)와 함께 저장 → 업로드 → 서버가 받은 키만 지움. 실패하면 지수 대기 후 재시도, 네트워크가 돌아오면 자동 전송. 처음 연결 때는 **연결 시점 이후 기록만**(과거 기록은 등록 요청에서 30일 범위로만).
6. **유형:** 수신·발신·부재·거절·차단을 구분하고, 문자도 받음·보냄·발송 실패를 구분해요.
7. **시계:** 기기 시각과 서버 수신 시각을 함께 저장하고, 하트비트에서 2분 넘게 차이 나면 앱·웹에 경고.

### 5-4. 녹음 자동 업로드

1. **찾기:** 미디어 저장소(오디오) 변경 감지 + 통화 종료 1분 뒤 확인. 대상 폴더는 기종별 목록(삼성 기본 녹음 폴더 등)을 앱에 두고, 테스트 폰에서 실제 경로·파일명을 확인해 채워요. 사용자가 진단 화면에서 폴더를 직접 고를 수도 있어요.
2. **맞추기:** 녹음 파일의 생성·수정 시각이 통화 종료 ±2분 안 + 길이 차이 5초 안 + (있으면) 파일명의 번호·이름 일치. 후보가 둘 이상이거나 없으면 '올리지 못한 녹음'으로.
3. **지문·업로드:** 파일을 읽으며 SHA-256 계산 → `recordings/init` → 서명 주소로 업로드 → `complete`(지문·크기) → 서버 재계산 결과가 같으면 '확인됨'. 다르면 '불일치'로 남기고 다시 올려요.
4. **휴대폰 원본:** 지우지 않아요(기본). 사무소 정책으로 '서버 확인 후 휴대폰 녹음 삭제'를 켤 수 있지만 기본은 끔.
5. **네트워크:** 기본 '모두', 사무소 정책으로 '와이파이만'. 대기 중인 녹음은 홈 상태 카드에 표시.

### 5-5. 걸려 온 전화 알림 · 통화 후 메모

- 등록 번호가 걸려 오면 번호 1건 조회(2초 제한) → 우선 알림 "마이김변 · ○○(가명) · 4단계 신청·접수 · 다음 할 일: 보정서 제출 D-3". 잠금 화면에는 "마이김변 의뢰인 전화"만. 다른 앱 위에 그리는 팝업은 출시 때 쓰지 않아요(⚪ 검토).
- 통화가 끝나면 "통화 메모 남기기 · 다음 연락 예약" 알림 → 통화 메모 화면. 쓰다 나가도 임시 저장돼 사라지지 않아요.

### 5-6. 웹 → 업무폰 명령

- **전화 걸기:** 웹 '업무폰으로 걸기' → 그 직원의 기기 1대에 푸시 → 앱이 알림 표시 → 누르면 다이얼러에 번호 입력(자동 발신 안 함, `CALL_PHONE` 권한 없음) → 결과(열림·만료) 회신.
- **문자 보내기 (CL-11, CL-Q4):** 웹에서 내용 작성(금지 표현 검사 통과) → 기기 1대 → 앱이 문자 발송 기능으로 직접 발송(긴 문자 분할, 수집 회선 SIM) → 보냄·도착 결과 회신 → 그때 '보낸 문자' 기록. 사무소 정책의 하루 한도·발송 금지 시간(기본 21시~8시)을 앱과 서버가 함께 지켜요.

### 5-7. 보안

- 앱 안에 비밀값(DB 키·계정·비밀번호) 0. 기기 토큰은 Keystore로 암호화 보관.

## 8. 완료 기준
