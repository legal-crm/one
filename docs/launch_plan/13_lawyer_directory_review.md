## 0. 한눈에 보는 결론

1. **구조 자체는 타당해요.** '체크 먼저'는 변호사가 정리된 사실관계를 받게 하고(첫 상담 품질), 의뢰인이 직접 입력한 사실만 전달하므로 비변호사 판단 문제(제109조)도 피해요. '최대 3명'은 개인정보를 꼭 필요한 변호사에게만 주고, 폐지한 '공개 요청·견적 경쟁' 구조로 돌아가지 않게 하는 장치예요. 광고비가 정액이고 같은 등급 안 무작위 순서라 알선(제34조) 문제도 없어요.
2. **그런데 규칙이 지금 화면에서만 지켜지고 실제로는 새요.**
   - 3명 제한은 **상담 요청 1건마다** 적용돼요. 체크를 다시 하면 새 요청이 생겨 또 3명을 고를 수 있어 사실상 무제한이에요. 재요청 대기 시간(`matching_config`)도 로그인 안 한 요청에만 걸려요.
   - 서버는 의뢰인이 `selected_lawyer_ids`·`request_type`·`status`를 마음대로 바꾸는 걸 막지 않아요. API로 4명 이상, 승인 안 된 변호사, `'open'`(폐지한 공개 요청)도 넣을 수 있고, DB 정책이 아직 `'open'` 요청을 **모든 승인 변호사에게 보여 줘요**(012).
   - 체크 선행도 화면에서만 확인해요. 서버는 정리 자료 없는 요청을 막지 않아요.
   - 변호사가 답하지 않거나 거절해도 자리가 돌아오지 않아요. 의뢰인은 '취소'를 직접 눌러야 다른 변호사를 고를 수 있어요.
3. **'좋아요'는 그 기기 브라우저에만 저장돼요.** 다른 기기·로그인 후에는 사라지고, 체크 결과 화면이 좋아요 목록을 다른 방식(`secureGetItem`)으로 읽어 '좋아요한 변호사부터 보기'가 동작하지 않을 수 있어요. 좋아요와 요청 선택은 서로 별개라 "좋아요한 변호사 중 3명" 규칙은 코드에 없어요.
4. **변호사 화면 정보가 출시 수준이 아니에요.** 첨부 화면의 'amjone 변호사'(계정 이름), 사람 아닌 그림 사진(구글 계정 사진 자동 사용), '전국', 소개 "Google 계정으로 가입 신청된 변호사입니다."(DB에 저장된 글), 사무소명 없음. 프로필 창은 사무소명이 비면 **가짜 법인명(`mockLawFirms`)을 채워** 보여 줘요. '등록번호 확인' 배지는 실제로는 '관리자 승인'과 같은 뜻이고, 'N년차'는 변호사가 직접 쓴 글에서 연도를 뽑아요.
5. **변호사 정보 등록에 광고 규정 위험이 있어요.** 프로필 편집기가 '누적 수임 건수·인가 성공률·평균 변제율'을 입력받아 공개 테이블에 저장하고, 편집기 미리보기에 '수임 N건' 배지를 보여 줘요. 소개·한 줄 문구에 금지 표현 검사가 없고, 승인 뒤 고친 내용은 검토 없이 바로 공개돼요. 사진은 원본을 글자(base64)로 공개 행에 넣어 방문자마다 수 MB를 내려받아요.
6. **광고가 목록과 연결돼 있지 않고, 무료 등록이 '광고'로 표시될 수 있어요.** 광고 주문이 노출 등급(`adTier`)을 바꾸지 않고, 무료 '기본등록'(`basic`)을 광고로 세며, '지역 광고'는 지역 조건을 읽지 않아요. 판매 문구의 "지역 필터 적용 시 최상단 노출"은 구현되지 않은 약속이에요.
7. **정적 `/lawyers` 페이지는 다른 내용을 보여 줘요.** 운영에서 주소로 들어오면 이 페이지가 먼저 나와요. "나의 채무관리 변호사", **"현재 상담 접수 가능 상태 확인"(없는 기능)**, 푸터 '대표이사'·서울 주소(R9·R10과 다름)가 있어요.
8. **개선 방향:** 규칙을 서버로 옮기고(의뢰인 1명당 진행 중 3명, 자리 자동 반환, 승인 변호사만), 좋아요를 서버에 저장하고, 공개 최소 조건(실명·사무소·본인 사진·소개)을 채운 승인 변호사만 보이게 하고, 실적 수치 입력을 없애고, 변호사가 '상담 받는 중/잠시 쉼'을 켜고 끌 수 있게 해요.

## 1. 지금 흐름

```
[의뢰인] 변호사 찾기 (로그인 없이 열람)
  ├─ 체크 전: 안내 "상담 요청 전에 내 상황 체크(약 3분)가 필요해요"
  │    └─ 카드 '상담 요청' → 그 변호사를 기억(화면 메모리에만) → 내 상황 체크 시작
  │         → 끝나면 결과 화면 '상담 요청' → 그 변호사 동의 창
  ├─ 체크 후(정리 자료가 있는 요청이 있으면): "여러 명 골라 요청하기" → 선택 바(최대 3 − 이미 요청한 수)
  │    → 로그인 안 했으면 고른 변호사를 30분 보관 → 로그인 → 동의 창
  └─ 동의 창(제3자 제공: 받는 변호사·항목·보관 기간) → 동의 → selectedLawyerIds에 추가 → 의뢰인·변호사 안내문
[변호사] 요청 목록 → 정리 자료 검토 → 제안서 → 의뢰인이 '상담 시작'을 눌러야 1:1 대화
```

- '좋아요'(하트)는 이 기기 `localStorage`에 저장돼요. 목록 위 '즐겨찾기만'으로 걸러 보거나, 체크를 끝낸 뒤 좋아요한 변호사가 있으면 그 목록부터 보여 주려는 코드가 있어요.
- 정렬은 같은 등급 안 무작위예요. 다만 변호사 찾기 탭을 다시 열 때마다 순서가 바뀌어 화면 설명 '방문 세션마다 1회'와 달라요.

## 3. 수익성

- **수익원은 정액 광고뿐**(상단 노출·지역·메인 배너). 문의 건수에 따라 돈을 받을 수 없으니 광고 가치는 '노출'과 '프로필을 본 횟수'로 설명해야 해요.
- **3명 제한과 광고 가치:** 요청 1건이 최대 3명에게만 가니 변호사가 많아질수록 한 변호사가 받는 문의 비율은 줄어요. 그래서 상단 광고 자리(최대 6명)의 희소성이 광고 가치를 만들고, 같은 등급 안 무작위라 작은 사무소도 기회가 같아요. 이 구조는 유지해요.
- **지금 광고가 팔기 어려운 이유:** ① 광고 주문이 노출로 이어지지 않음 ② '지역 광고'가 지역을 읽지 않음 ③ 무료 기본등록이 '광고'로 섞여 유료 광고와 구분이 흐림 ④ 남은 구좌 숫자 고정값 ⑤ 노출·조회 리포트 없음. ①~④는 출시 전, ⑤는 출시 후(M·D-3).
- **리포트(출시 후):** 사무소에 '목록 노출 수·프로필 조회 수·상담 요청 받은 수·응답한 수'를 보여 줘요. 요금은 이 숫자와 연동하지 않아요(제34조). 변호사끼리 비교하는 순위표는 만들지 않아요.
- **공급 측면:** 오픈 기준 승인 변호사 10명(L1). 지금 1명이라 '최대 3명'·'즐겨찾기'가 의미 없고 목록이 비어 보여요. 변호사 0~2명일 때 빈 상태 화면("지금 등록된 변호사는 n명이에요")을 준비해요.

## 4. 논리성 (화면 문구·숫자)

| 위치 | 지금 | 문제 | 바꿀 것 |
|:---|:---|:---|:---|
| 머리 '등록 변호사 N명' | 광고 변호사 포함 전체 수 | 아래 '등록 변호사' 구역(무료만)과 같은 이름, 다른 숫자 | 머리는 '승인 변호사 N명', 아래 구역은 '변호사' |
| '정렬: 무작위 · 광고 0건 포함' | 광고가 0이어도 표시 | 쓸모없는 문장 | 광고가 있을 때만 '광고 n건 포함' |
| 무작위 설명 | '세션마다 1회' 주석 | 탭을 열 때마다 바뀜 | 순서 기준을 브라우저 세션에 저장 |

### 5-2. 목록 구성

- 상단 '광고 변호사'(top, 최대 6) → '광고 · 지역 변호사' → '변호사'(무료). 구성은 좋아요. 고칠 것: `basic`(무료)을 광고로 세지 않기, 지역 광고는 **고른 지역과 광고 지역이 같을 때만** 그 지역 결과 맨 위에, 광고 구역 쪽수 나누기.

## 8. 법·광고 규정 점검 (R6 외부 자문 확인 대상)

- **변호사법 제34조(알선):** 정액 광고비, 문의 건수·수임과 무관, 의뢰인이 직접 선택, 같은 등급 안 무작위 → 지금 구조는 알선 아님. 유지 조건: 순서를 광고비·문의 수·응답률로 정하지 않기, 체크 결과로 변호사를 골라 주지 않기, '추천·전담·매칭' 표현 없기(광고 상품 문구 '추천 변호사' 섹션·'지역 전담'도 고침, D-3).
- **변호사 광고 규정:** 변호사가 직접 쓴 소개도 변호사 광고예요. 결과 보장·성공률·과장·비교 표현, 변협 등록 없는 '전문' 표기가 문제 돼요. 플랫폼이 실적 숫자를 입력받고 배지로 보여 주면 플랫폼이 그 광고를 만들어 준 모양이 돼요 → 실적 칸 삭제, 금지 표현 검사, '전문' 별도 칸.
- **플랫폼 이용 관련 경과:** 대한변협 광고 규정의 플랫폼 관련 조항 일부가 헌법재판소에서 위헌으로 결정(2022. 5. 26. 2021헌마619)됐고, 법무부 변호사징계위원회가 2023년 로톡 가입 변호사 징계를 취소했어요. 정액 광고형 플랫폼 이용 자체는 허용되는 방향이지만, 규정 개정·해석이 이어지고 있어 정식 오픈 전 자문 변호사(R6)와 최신 규정 원문을 확인해요.
- **개인정보:** 동의 창이 받는 변호사·항목·보관 기간을 보여 주는 지금 방식 유지. 3명 제한은 최소 제공 근거로 처리방침에도 적어요.
- **표시광고:** 무료 등록을 '광고'로 표시하거나, 유료 광고를 광고 표시 없이 섞는 것 모두 피해요.

## 9. 개선안 요약 (설계)

```
[변호사 찾기]
 머리: 승인 변호사 N명 · 계약 전 스텔스 가명 상담 · 진행 중 최대 3명
 안내: (체크 전) "변호사를 먼저 골라 좋아요를 눌러 두세요. 상담 요청은 내 상황 체크를 마친 뒤 보낼 수 있어요(보통 n분)"
       (체크 후) "진행 중 m/3명 · 응답 없음·거절이면 자리가 자동으로 돌아와요"
 검색·지역(시·도 + 비대면 가능)·분야 칩·좋아요만
 [광고 변호사] (상단 광고, 조건 없을 때)
 [광고 · ○○ 지역] (지역을 골랐고 그 지역 광고가 있을 때)
 [변호사] 무작위(세션 고정), 10명씩
 카드: 본인 사진 · 실명 · 사무소 · 사무소 지역/비대면 · 분야 · 소개 2줄 · 등록번호 대조 배지(대조 기록 있을 때) · 상담 받는 중/쉼 · 좋아요 · 프로필 · 상담 요청
```

- **상담 요청 규칙(서버):** 진행 중 합계 3명 = 요청 보냄·제안서 받음·비교 상담 중 상태의 변호사 수. 거절·응답 기한 경과·의뢰인 취소·다른 변호사로 확정 시 빠짐. 한 변호사에게 같은 상담을 다시 보내지 않음.
- **응답 기한(LD-Q2 결정):** 요청 받은 뒤 2영업일 안에 '검토 중' 또는 제안서·거절. 지나면 '응답 없음'으로 자리 반환, 의뢰인에게 "○○ 변호사가 답하지 않아 다른 변호사를 고를 수 있어요" 알림, 변호사 화면엔 '기한 지남' 표시.
- **변호사 쪽:** 요청 받기 켜기/끄기, 동시에 받는 새 요청 상한(사무소 설정, 기본 없음), 거절 버튼(사유 선택: 분야 아님·업무 과다·기타, 의뢰인에겐 사유 없이 '이번엔 어렵다'만).
- **좋아요:** 로그인 후 서버 저장, 기기 저장분 합치기, 체크 결과 화면에서 좋아요 목록 먼저.

- **LD-1 서버 규칙:** 요청 추가 서버 함수(승인 변호사·진행 중 3명·정리 자료·동의 확인), 의뢰인의 `selected_lawyer_ids`·`request_type`·`status`·`max_participants` 직접 수정 차단, `lawyer_can_view_request`의 `'open'` 조건 삭제·기존 행 정리(A-6 서버), 저장 실패 표시.
- **LD-2 공개 데이터:** 공개용 변호사 뷰(승인 + 공개 최소 조건, 공개 칸만), 원본 테이블 익명 조회 차단, 사진 저장소 이전·줄이기, 운영 DB의 시스템 문구 소개·'전국'·계정 이름 정리.
- **LD-3 공개 최소 조건 (LD-Q4 결정):** 실명·사무소명·사무소 시·도·본인 사진·분야 1개 이상·소개 50자 이상 + 승인. 미충족 변호사에겐 '프로필 완성하면 목록에 보여요' 안내와 남은 항목.
- **LD-4 프로필 등록 개편:** 가입 마법사, 실적 칸 삭제(기존 값 지움), 지역·분야 선택형, 자격 연도 칸, '전문' 별도 칸, 금지 표현 검사(경고 + 관리자 검토 목록), 승인 뒤 핵심 항목 재확인(LD-Q5), 구글 사진 자동 사용 중단.
- **LD-5 배지·표시 정리:** '등록번호 확인'은 대조 기록이 있을 때만(관리자 화면에 대조 날짜·대조자 입력), 'N년차'는 확인된 연도만, 가짜 법인명 채우기 삭제, `basic` 광고 표시 제거, 머리·구역 이름·'광고 0건' 문구, 세션 고정 무작위.
- **LD-6 지역·검색:** 시·도 + 비대면 가능 필터, 분야 칩, 검색에 분야·지역 포함, 로딩 스켈레톤, 등록 0~2명 빈 상태.
- **LD-7 흐름 연결:** 체크 전 고른 변호사 세션 저장·이어 가기, 좋아요 읽기 불일치 수정, '약 3분' 실측값, 변호사 쪽 안내문 용어('의뢰인 정리 자료'), 요청 제목 가명.
- **LD-8 정적 `/lawyers` 페이지:** 없는 기능 문구 삭제, 실제 흐름(체크 → 좋아요·선택 → 3명 → 동의) 설명, 푸터 A-8 기준.

**🟡 출시 직후**
- **LD-9 응답 기한·자리 반환·거절 (LD-Q1·Q2):** 2영업일 기한(G 스케줄러), 의뢰인·변호사 알림, 거절 사유.
- **LD-10 좋아요 서버 저장·상담 받는 중/쉼 (LD-Q3·Q6).** 지역 광고 노출 연결은 D-3(출시 전)와 함께.

**⚪ 출시 후:** 사무소용 노출·조회·요청·응답 리포트(요금 연동 없음), 변호사 개별 프로필 정적 페이지(M2, 04 기획서), 프로필 사진 얼굴 확인 보조.

## 11. 결정 (10-29, 추천안대로)

| 번호 | 질문 | 결정 |
|:---:|:---|:---|
| LD-Q1 | 3명 제한 기준 | **의뢰인 1명당 '진행 중' 변호사 최대 3명**(상담 요청 건수와 무관). 거절·응답 기한 경과·취소·다른 변호사 확정이면 자리 반환 |
| LD-Q2 | 변호사 응답 기한 | **2영업일.** 지나면 '응답 없음'으로 자리 반환 + 의뢰인 알림 |
| LD-Q3 | 좋아요 저장 | **로그인 후 서버 저장**, 로그인 전 기기 저장분은 로그인 때 합치기. 좋아요 수 제한 없음, 요청은 좋아요 여부와 관계없이 가능 |
| LD-Q4 | 목록 공개 최소 조건 | **승인 + 실명·사무소명·사무소 시·도·본인 사진·분야 1개 이상·소개 50자 이상.** 미충족이면 목록에 안 보이고 변호사에게 안내 |
| LD-Q5 | 승인 뒤 프로필 수정 | **실명·사무소명·사진·등록번호는 관리자 확인 전까지 이전 값 유지**, 소개·분야·연락처·상담 시간은 즉시 반영 + 변경 내역 관리자 표시, 금지 표현은 경고 후 관리자 검토('[운영자 판단]') |

| LD-Q7 | 실적 수치(수임 건수·성공률·변제율) 입력 | **삭제**(입력 칸·저장값 모두). 소개글에 쓰는 것도 금지 표현 검사 대상 |

## 12. 완료 기준

- API로 4번째 변호사 추가·승인 안 된 변호사 추가·`'open'` 설정·정리 자료 없는 요청이 모두 거절돼요. 여러 기기에서 동시에 골라도 진행 중 3명을 넘지 않아요.
- 체크를 다시 해 새 상담을 만들어도 진행 중 합계는 3명이에요. 변호사가 거절하거나 2영업일이 지나면 자리가 돌아오고 알림이 가요(LD-9).
- 익명 조회로 승인 안 된 변호사·비공개 칸·실적 수치가 보이지 않아요. 변호사 목록 응답 크기가 사진 원본 없이 변호사 10명 기준 100KB 이하.
- 목록 카드에 계정 이름·구글 그림 사진·시스템 문구 소개·가짜 법인명 0건, 공개 최소 조건 미충족 변호사 0명.
- '등록번호 확인' 배지는 대조 기록이 있는 변호사만, '광고' 표시는 유료 광고만, '광고 0건' 문구 없음, 탭을 다시 열어도 순서 같음(같은 세션).
- '인천'을 고르면 인천 사무소 변호사가 나오고, '비대면 가능' 필터가 동작해요.
- PC에서 누른 좋아요가 로그인한 휴대폰에서도 보여요(LD-10).
- 정적 `/lawyers`와 앱 화면의 설명·기능이 같고, 푸터 사업자 정보가 A-8 기준이에요.
- 프로필 편집기에 실적 입력 칸 0개, 금지 표현을 넣으면 경고가 뜨고 관리자 검토 목록에 올라가요.
