## 0. 한눈에 보는 결론 (10-29 CT-Q1~Q7 추천안대로 결정으로 개편 방향 확정)

**두 탭에서 서버에 저장되고 다른 기기에 보이는 것은 '1:1 문의(의뢰인)'와 허니팟 기록뿐이에요.** 나머지는 관리자 브라우저에만 저장되거나, 저장해도 읽는 곳이 없거나, 새로 고치면 기본값으로 돌아가요.

1. **콘텐츠는 관리자 브라우저에만 저장돼요.** 칼럼·상담 사례·후기·배너·공지·팝업을 고치면 관리자 브라우저 저장소에만 들어가고, 다른 기기의 의뢰인은 코드에 들어 있는 시드 콘텐츠를 봐요. 서버 저장용 `cmsService`는 다 만들어져 있지만 **불러 쓰는 파일이 0개**예요. 화면 안내는 "영구 발행", "실시간 제어"예요.
2. **운영 사이트에 가상 변호사 명의 글이 나와요.** 시드 칼럼 6건·상담 사례는 실제로 없는 변호사 이름·사진(스톡 사진)으로 쓰여 있고, '탕감'·'전액 탕감'·'변호사 매칭'·'최대 90% 탕감'·'추천 답변'·'100% 비밀 유지'·'원천 차단'·가짜 조회수가 들어 있어요. 변호사 광고 규정과 플랫폼 원칙(매칭·추천 없음) 모두에 걸려요. 상담 사례는 지워도 다음 실행 때 시드가 다시 합쳐져 되살아나요.
3. **공지 시드가 사실과 달라요.** '탕감액 계산기'(금지어), '변호사 매칭 및 수임 분석 서비스', 없는 '20분 영상상담 종료', '신용정보원 마이데이터', 미래 날짜·가짜 조회수.
4. **메인 배너는 어디에도 표시되지 않아요**(고객 화면이 안 읽음). '프리미엄 광고 관리'는 저장도 안 되고 고객 화면과도 연결이 없어요(새로 고치면 사라짐). '진단 문항'은 코드에서 꺼져 있는 죽은 화면이에요.
5. **변호사가 보낸 '마이김변 문의'는 관리자에게 오지 않아요**(변호사 브라우저 저장). 의뢰인 1:1 문의는 서버로 정상 동작하지만 답변해도 의뢰인에게 알림이 없고, 첨부 파일 원본이 관리자 브라우저에 저장되며, 분류 이름에 '진단 결과'·'변호사 매칭'이 있어요.
6. **'매칭 정책' 탭의 저장은 대부분 가짜예요.**
   - 재요청 대기 시간(쿨다운)은 관리자 브라우저에만 저장되고, 의뢰인 쪽 확인은 비로그인 임시 요청에만 걸려요. '정책 저장' 버튼은 알림만 띄워요.
   - 홈페이지 설정의 주소·사업자번호·대표자명·**이용약관·개인정보처리방침**은 새로 고치면 기본값으로 덮어써지고, 읽는 화면이 없어요. 실제 약관은 정적 파일(`tos.html`·`privacy.html`)이고 버전·시행일·재동의가 없어요.
   - 고객 푸터·정적 페이지는 코드에 고정된 잘못된 회사 정보('my김변컴퍼니'·'주식회사'·'대표이사'·서울 주소·'통신판매중개자')를 보여 줘요.
   - '법률 기준'(회생 계산 기준표)은 관리자 브라우저에만 저장되고, **열 때마다 2025·2026 값을 기본값으로 덮어써** 고친 값이 되돌아가요. 법원 서식·퀵툴·제안서 계산은 이 표를 읽지 않아요.
7. **서버 테이블은 이미 있어요.** `news_articles`·`client_qas`·`success_reviews`·`main_banners`·`notices`·`platform_config`·`popup_config`·`matching_config`·`rehab_policy_settings`에 '누구나 읽기·관리자만 쓰기' RLS(025)가 있어요(운영 DB 실행 여부는 확인 필요). 앱이 이 테이블을 쓰지 않을 뿐이에요.

**개편 방향:** 콘텐츠·정책을 모두 서버에 두고 **'초안 → 검사 → 미리보기 → 게시(예약) → 내리기'** 흐름과 버전·변경 기록을 붙여요. 시드 콘텐츠는 운영에서 빼고, 플랫폼 글은 '마이김변 편집팀' 이름으로 새로 써요. '매칭 정책' 탭은 **'플랫폼 설정'**으로 이름을 바꾸고 상담 요청 정책·회사 정보·약관(버전·시행일·재동의)·기능 표시·법률 기준표·부가 기능 과금으로 나눠요. 칼럼은 마케팅 기획(M)의 원본 허브와 같은 데이터로 묶어 정적 페이지·사이트맵까지 자동 반영해요.

## 3. 개편 설계

### 3-1. 콘텐츠 서버화와 게시 흐름 (CT-1·CT-3)

- **저장:** 기존 표를 칸이 있는 구조로 바꿔요(지금은 `id + data jsonb`). 공통 칸: `status`(초안·검토 필요·예약·게시·내림), `publish_at`·`unpublish_at`, `audience`(고객·변호사·둘 다), `is_example`, `sort_order`, `version`, `author_label`, `updated_by`, `updated_at`. 공개 화면은 '게시 중'만 읽는 뷰(`public_*`)로.
- **`cmsService` 새로 쓰기:** 서버만 기준, 실패는 호출한 화면에 돌려줌(지금처럼 브라우저에 먼저 쓰고 오류를 콘솔에만 남기는 방식 금지, 6-1 원칙). 고객 화면은 서버에서 읽고 브라우저 사본은 캐시로만.
- **흐름:** 작성 → **금지 표현 검사**(M-9 공통 사전, '[운영자 판단]' 경고 → 고쳐서 게시 / 사유 남기고 게시 — 사용자 방침대로 권고형, ST-6과 같은 검사기) → 미리보기(고객 화면 모양) → 지금 게시 / 예약 → 내리기. 바뀔 때마다 버전 저장·이전 버전 되돌리기, `admin_actions` 기록(OP-2).
- **이미지:** 공개 콘텐츠는 Supabase 저장소 공개 버킷 `site-media`(올릴 때 WebP 변환·가로 1600px·1MB 제한), 문의 첨부는 비공개 버킷 + 짧은 서명 주소. base64 저장 금지.

### 3-2. 시드 정리와 작성자 원칙 (CT-2, CT-Q1)

- 운영 번들에서 칼럼·상담 사례·배너·공지·후기·광고 시드를 모두 빼요(개발 환경 전용). 운영은 빈 상태 + 채우는 방법 안내로 시작.
- **작성자:** 플랫폼이 쓰는 칼럼·예시 사례는 **'마이김변 편집팀'**. 실존하지 않는 변호사 이름·사진은 어디에도 쓰지 않아요. 외부 자문 변호사(R6)가 실제로 검토한 글에만 '법률 검토: ○○ 변호사(검토일)'(MK-Q 결정과 같음).
- **예시 상담 사례(D-2):** 30건을 새로 쓰고 '예시' 배지·`is_example`, 실제 사례가 생기면 '예시만 일괄 내리기'. 상담 사례 답변 칸은 변호사 이름 대신 '일반 정보 안내'.
- 시드를 다시 합치는 코드(App 574~583)와 후기 시드 되돌림(585~598) 삭제.

### 3-3. 칼럼 = 마케팅 원본 허브 (CT-4)

- SPA '법률 정보'와 정적 `public/articles/*.html`을 **한 데이터**로: 칼럼을 게시하면 Deploy Hook으로 정적 페이지·사이트맵·RSS·`llms.txt`를 다시 만들고 IndexNow 전송(04 기획서 M-4와 같은 작업). 예시 상담 사례 페이지는 `noindex`(MK 결정).
- 칼럼 칸: 분류·요약·본문(마크다운)·대표 이미지·근거 법령/자료 링크·검토자·최종 수정일. 배지 'HOT/NEW/BEST'는 삭제(근거 없는 순위 표현).

### 3-4. 배너·공지·팝업 (CT-5·CT-6·CT-7)

- **메인 배너 → 'Hero 브랜드 배너'(01 1-B):** 데스크톱·모바일 이미지, 제목·부제·버튼 문구·링크, 노출 기간, 순서, 슬라이드 중 광고 비율 상한. 광고 소재는 AD-5 소재 심사함이 따로 관리하고 고객 화면은 `active_ad_placements`와 합쳐 보여 줘요. **'프리미엄 광고 관리' 화면은 삭제**(AD-8).
- **공지:** 대상(고객·변호사·직원), 위치(공지 목록·변호사 홈 공지 칸·종 알림·상단 띠), 기간, 중요 고정, 조회 수는 서버 집계(사람 기록 없이 수만). 변호사 '오늘의 업무' 고정 배너 대체(HM-6).
- **팝업:** 서버 저장·명시적 '저장'·미리보기, 대상·기간·하루 보지 않기, 이미지 저장소. 운영 점검 안내 띠(서비스 점검 예정 시각)는 🟡.

### 3-5. 문의함 통합 (CT-8, CT-Q4)

- **한 화면에서 의뢰인·변호사·비회원 문의:** 변호사 '마이김변 문의'도 서버 API로(지금 안 옴). 상태 4개(접수·확인 중·답변 완료·종결), 담당자, **처리 기한**(접수 + 2영업일, 평일 10~18시 운영 결정과 맞춤), 기한 넘으면 '오늘 처리할 일'(OP-3).
- **답변 알림:** 회원은 앱 안 알림 + 이메일, 비회원은 연락처를 남겼으면 문자 1회(팝빌, "문의에 답변이 등록됐어요. 문의번호로 확인해 주세요" — 내용은 안 보냄), 없으면 조회 안내만.
- **첨부:** 비공개 저장소·서명 주소, 관리자 브라우저에 원본 저장 금지(App 676~680 삭제).
- **분류 정리:** '진단 결과' → '정리 결과·계산기', '변호사 매칭' → '변호사 찾기·상담 요청', 새 분류 '개인정보 요청'(→ OP-11 요청함으로 넘기기)·'신고'(→ OP-7 신고함으로 넘기기)·'광고·결제'(변호사).
- **답변 문구함:** 자주 쓰는 답변(금지 표현 검사 통과분), 답변 수정·삭제 기록.

### 3-6. 후기 (CT-9, CT-Q6)

- 출시 때 **빈 상태**(결정대로). 이름 '성공후기' → '이용 후기'.
- 관리자 직접 등록은 동의 기록(동의일·방법·동의서 파일) 없으면 게시 불가, **채무 금액·감면 칸 삭제**(광고 규정·의뢰인 수치 비노출).
- 실제 후기 수집(출시 직후): 사건 종결 의뢰인에게 사무소가 '후기 요청' → 의뢰인 작성(가명·별점 없이 글, 수치 입력 불가) → 관리자 검수 → 게시. 변호사는 자기 후기를 고치거나 숨길 수 없고 '답글'만.

### 3-7. 변호사 공개 Q&A 답변 (CT-10, CT-Q2)

- 서버 저장(S 트랙 계획대로), 답변 칸 아래 금지 표현 검사(경고·사유), **검사에 걸리지 않으면 바로 게시, 걸린 답변은 관리자 '검토 필요' 목록**에서 내리기·수정 요청. 답변자 표시는 실제 변호사 공개 프로필 연결(광고 규정상 변호사 본인 이름 표시는 필요).
- 질문은 출시 때 관리자(예시 사례)만, 의뢰인 공개 질문 받기는 출시 후 검토.

## 6. 완료 기준

- 관리자가 공지·칼럼·배너·팝업을 게시하면 다른 기기·비로그인 의뢰인 화면에 1분 안에 보이고, 내리면 사라져요. 저장 실패는 화면에 보여요.
- 운영 사이트·번들에 시드 칼럼·상담 사례·후기·배너·공지·광고 문구가 없고, 실존하지 않는 변호사 이름·사진이 0건이에요. 상담 사례를 지우면 다시 생기지 않아요.
- 게시 전에 금지 표현이 표시되고, 그대로 게시하면 사유가 기록돼요. 이전 버전으로 되돌릴 수 있어요.
- 칼럼을 게시하면 정적 칼럼 페이지·사이트맵·RSS에 반영돼요.
- Hero 슬라이더에 관리자 브랜드 배너와 승인된 광고가 기간대로 나오고, '프리미엄 광고 관리' 화면이 없어요.
- 변호사가 '마이김변 문의'를 보내면 관리자 문의함에 들어오고, 답변하면 변호사·의뢰인에게 알림이 가요. 관리자 브라우저에 첨부 원본이 저장되지 않아요.
- 고객 푸터·회사 소개·정적 페이지·JSON-LD의 상호·대표·주소·사업자번호·통신판매업 번호가 플랫폼 설정 한 곳의 값과 같고, 'my김변컴퍼니'·'주식회사'·'대표이사'·서울 주소가 0건이에요.
- 이용약관을 새 버전으로 예고하면 공지가 나가고, 시행일 이후 로그인한 회원에게 재동의 화면이 뜨며, 동의 기록에 버전이 남아요. 이전 버전을 열람할 수 있어요.
- 재요청 대기 시간을 바꾸면 서버가 바로 그 값으로 확인하고, 로그인 의뢰인에게도 적용돼요.
- 법률 기준표를 열어도 값이 바뀌지 않고, 저장하면 변제계획 편집기·퀵툴·제안서·고객 계산기가 같은 값을 써요.
- 두 탭에 이모지·`rounded-[200px]`·없는 클래스·'매칭'·'견적'·'진단' 문구가 없어요.
