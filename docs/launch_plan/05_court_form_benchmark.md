- **조사 방법:** 사용자 제공 계정으로 3개 서비스에 직접 로그인해 테스트 사건(`TEST홍길동`)을 만들고, 자료 업로드·입력·출력까지 실행했어요. 받은 PDF·CSV는 파일 구조(글자 여부·폰트·용량·쪽수·열 구성)를 직접 분석했어요. 결과 파일은 `references/competitor-2026-10/`(커밋 제외)에 보관.

## 0. 결론 먼저

1. **우리 최종 PDF는 '사진 PDF'예요.** 서식 작성기의 '단일 PDF'는 화면을 캡처한 JPEG를 A4에 붙여요. 글자 검색·복사가 안 되고, 폰트가 사용자 PC에 따라 달라지고, 한 쪽에 0.3~0.8MB라 30쪽이면 10MB를 넘을 수 있어요. 경쟁 3사는 모두 **글자가 살아 있는 PDF(폰트 내장)** 를 만들어요(22쪽 215KB 수준).
2. **출력 경로가 4개로 흩어져 있고 서로 달라요.** ① 서식 작성기(캡처 PDF) ② 인쇄 창 방식(사용자가 직접 'PDF로 저장') ③ 전자소송 묶음 서비스(ZIP·20MB 분할, 그런데 영문 안내 표지 삽입·한글 불가 폰트) ④ HWPX(빈 양식). 문서 순서도 경로마다 달라요.
3. **채권자목록 CSV 열 구성이 경쟁사와 전혀 달라요.** 경쟁 2사의 CSV는 둘 다 `체크(기본값 F)`로 시작하는 전자소송 양식 구조인데, 우리는 자체 16열이에요. 업로드가 거절될 가능성이 높아요. 10-29 조사(8장): 회생은 13열 당사자형 CP949, 파산은 18열이 맞는 형식이에요.
4. **작성기의 계산·저장에 결함이 있어요.** 작성기는 자체 계산식(다섯 번째 엔진)을 써서 현재가치·우선채권 2단계를 반영하지 않고, 재산·자료제출·중지명령 입력은 저장되지 않으며, 주민번호가 초안에 저장돼요(L8 위반). '110~140p 완성본'은 항상 0쪽, 'HWPX'는 빈 양식인데 버튼 설명은 "자동 주입"이라고 해요.
5. **가장 큰 기능 격차는 '자료 자동입력'** (디던비): 서류 묶음 PDF를 올리면 쪽별로 분류 → 값 추출 → '검수 필요' 표시 → 채권자목록·재산목록·수입까지 자동 반영. 우리는 부채증명서 읽기 기능이 없어요(10-29 확인: `/api/ocr`는 사건·가족관계·보정만, 26 기획서).

| 생성 방식 | 서버에서 HTML → PDF (wkhtmltopdf) | 서버에서 HTML → PDF (mPDF) | **법원 양식 PDF에 입력칸(AcroForm)을 만들어 채움** (화면에서 PDF 위에 직접 입력, 자료제출목록 1장에 입력칸 164개) | 브라우저 화면 캡처(html2canvas) → JPEG → PDF |

## 6. 개선 계획 (H 트랙에 반영)

### 🔴 출시 전 (H-7 ~ H-10)

- **H-7. 텍스트 PDF 엔진 (H-5 대체):** 미리보기와 같은 HTML을 **폰트를 내장한 글자 PDF**로 만들어요. 문서별 PDF·전체 PDF·ZIP을 한 엔진으로. 쪽 나눔(표 머리 반복), 쪽 번호, 책갈피(문서별), 파일명 `이름_개인회생_서류명_날짜.pdf`. 방식은 CF-Q1 결정(10-29): 서버 HTML → PDF(헤드리스 크롬, 폰트 내장), 1~2장 고정 양식은 입력칸 PDF 채우기 허용.
- **H-8. 출력 경로 하나로:** 작성기·인쇄 창·묶음 서비스·HWPX가 **같은 문서 목록·순서 정의 하나**를 써요. 묶음 서비스의 영문 표지·Helvetica 제거, '110~140p 완성본'은 서식 PDF + 의뢰인이 낸 증빙 PDF를 실제로 합치게 고치거나 버튼을 내려요. HWPX 버튼 설명은 실제 동작대로(H-1 완료 전까지 '빈 공식 양식'). 용량 기준은 공식값(8-3)으로: 파일당 20MB(19MB에서 분할), 총 100MB(90MB부터 경고, 지금 50MB 기준 교체), 서식·주장 문서와 증빙은 서로 다른 파일로(규칙 제8조③). 묶음 화면의 '텍스트 레이어 내장'·'회생위원 뷰어 1:1' 문구는 H-7 완료 전까지 내려요.
- **H-9. 전자소송 CSV 정합성 (10-29 형식 확정, 8장):** 회생 = 13열 당사자형 CP949(`체크(기본값 F),구분,채권자목록번호,구분번호,채권자명,인격구분,도로명주소1(도로명 건물번호까지),도로명주소2(상세주소),우편번호,휴대전화번호,전화번호,팩스번호,이메일`), 파산 = 18열(BK-3). 금액·원인·주민번호 칸 삭제, 주소를 건물번호까지/상세주소로 나눠 저장(채권자 주소록도), 인격구분(`국가`·`지방자치단체`·`법인`·`자연인`) 칸 추가, 보증인은 `보증인(대위변제자)` 행 + 구분번호. 지어낸 기본값 삭제, 비어 있으면 출력 전 경고. 대표번호 `02-` 보정 유지. 포털 양식 파일을 받으면 번호 표기·날짜·인코딩만 최종 확인.
- **H-10. 작성기 데이터·계산 정리:** 작성기 계산을 통합 엔진(`repaymentCalculationEngine`, B-3·B-6)으로 바꾸고, 회차 구간별 변제예정액표·현재가치(J·K·L) 표기를 넣어요. 모든 입력값 서버 저장 + 자동저장 + 이력(S 원칙), 주민번호는 출력 창에서만 입력하고 저장 안 함(L8), 가짜 기본값 삭제, 직접 타이핑은 '입력값으로 반영'되거나 막기.
- **출력 전 검증 게이트 (H-3 확장):** 필수 미입력·자리표시자(`YYYY.MM.DD`, `○○`) 잔존·합계 불일치·현재가치 < 청산가치·최저변제액 미달이면 **출력 버튼 옆에 사유 목록**(고위험은 출력 차단, 나머지는 경고 후 진행). 로패스처럼 미입력 날짜가 그대로 찍히는 일을 막아요.

### 8-3. 파일 용량·형식 (공식 확인)

전자소송포털 '전자소송준비 > 전자문서 작성' 안내(2026-10-29 확인):

- **파일 하나 20MB 초과 불가**, 넘으면 여러 파일로 나눠 낼 수 있음. **첨부파일 총용량 100MB 이하.**
- **아이디 하나당 임시저장 총 500MB.** 넘으면 임시저장이 안 돼서 '나의서류'에서 지워야 해요. 사무소 계정 하나로 여러 사건을 작성할 때 문제가 될 수 있어요.
- 문서 형식: HWP, HWPX, DOC, DOCX, PDF, TXT, XLS, XLSX, BMP, JPG, JPEG, GIF, TIF, TIFF, PNG. PDF가 아니면 PDF로 자동 변환돼서 결과 확인이 필요해요. 스캔 이미지는 PDF로 바꿔서 내요.
- **민사소송 등에서의 전자문서 이용 등에 관한 규칙 제8조**: ③ 주장·증거 등은 별도 파일로 나눠 내고 하나로 합치면 안 돼요. ④ 직접 작성한 전자문서(서증 제외)는 **글자 검색·추출이 가능한 파일**로 내야 해요(2017 신설). → 지금 서식 작성기의 그림 PDF는 이 조항에 맞지 않아요. CF-Q1(글자 PDF)의 법적 근거예요.
- 참고: 2016~2021년 기사에는 10MB 제한이 나오고, 2025년 차세대 전자소송 개통 뒤 20MB로 늘었다는 글이 있어요. 서증 '총 20MB'라는 2026-01 블로그 글도 있지만 포털 공식 안내와 달라 쓰지 않아요.

**우리 코드와 비교:** 파일당 20MB(`pdfQualityService` `COURT_FILE_SIZE_LIMIT`, 19MB 여유 분할)는 맞아요. 총용량 50MB(`COURT_TOTAL_SIZE_LIMIT`, `CourtBatchFilingService`)는 근거가 없어서 **공식 100MB**로 바꾸고 90MB부터 경고해요. `BatchFilingPackagingModal`의 '텍스트 레이어 내장', '회생위원 뷰어 1:1' 문구는 사실과 달라서 H-7 완료 전까지 내려요.

### 8-4. 결론 (H-9·BK-3에 반영)

- **회생 CSV = 채권자(기본정보)용 13열 당사자형, CP949**(디던비 형식). 금액·원인은 넣지 않고 채권자목록 PDF에 둬요. 보증인은 `보증인(대위변제자)` 행 + 구분번호.
- **파산 CSV = 18열 채권자목록형**(두 회사 일치). 발생원인은 번호(①~④), 금액은 숫자만.
- 공통: 첫 열 `F`, 주소는 '도로명 건물번호까지' / '상세주소'로 나눔, 우편번호 필수, 전국대표번호는 `02-` 붙임(투더코어 안내), 엑셀로 열었다 저장하면 깨진다는 안내 유지, 빈 값을 지어내지 않고 출력 전 경고.
- **남은 확인 1건 (CF-Q2 축소):** 변호사 계정으로 전자소송 개인회생·파산 '파일첨부방식'의 채권자(기본정보) 화면에 들어가 **양식 내려받기 파일 2개만** 받아 주세요(제출할 필요 없음). 받으면 8-2의 '확정 필요' 3가지(번호 표기·날짜 형식·인코딩)를 정해요. 받기 전에도 위 형식으로 개발은 시작할 수 있어요.
