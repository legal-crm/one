## 0. 한눈에 보는 결론

1. **143종 중 실제로 '작성'이 되는 서식은 2종뿐이에요.** 재산목록(D5102)·수입지출(D5103)만 전용 입력 화면이 있어요. 나머지 141종은 같은 범용 화면 하나로 열리고, 고칠 수 있는 칸은 '신청취지'·'신청이유' 글상자 두 개뿐이에요. 입력 항목 정의(`questionnaireSchema`)를 쓰는 서식은 0개예요.
2. **작성한 내용이 저장되지 않아요.** 범용 화면은 저장 기능이 없어서 닫으면 사라져요. 'AI 사유 자동 보강'은 AI를 부르지 않고 미리 써 둔 문장으로 바꿔요.
3. **다운로드는 법원 양식에 맞지 않아요.** 'HWPX'는 빈 공식 양식을 그대로 내려받고(데이터 0개 주입), PDF는 브라우저 인쇄 창의 'PDF로 저장'뿐이에요. 규칙 제8조④(직접 작성한 문서는 글자 검색 가능 파일)와 05 기획서의 글자 PDF 결정(CF-Q1)이 아직 반영되지 않았어요.
4. **전자소송 묶음과 연결돼 있지 않아요.** 허브 서식(위임장·보정서·금지/중지명령·송달장소 신고서 등)은 '전자소송 일괄 결합실'에 들어가지 않아요. '전자소송 패키지에 첨부' 버튼은 아무것도 첨부하지 않는데 "추가했습니다" 성공 안내가 떠요. 서식마다 붙어 있는 제출 순서 칸(`courtOrderSlot`, 약 40종)은 어디서도 읽지 않아요.
5. **같은 서식을 그리는 화면이 3개예요.** 허브 범용 화면, '13종 법원서식 에디터', 4단계 '서식 미리보기'(`CourtFormHtmlBuilder`)가 개시신청서·진술서·채권자목록·변제계획안을 각자 다르게 그려요. 허브에서 '개인회생신청서'를 열면 데이터가 채워진 13종 에디터가 아니라 빈 공식 양식 HTML이 열려요.
6. **의뢰인 작성 요청은 의뢰인에게 닿지 않아요.** '모바일 요청'은 변호사 브라우저에만 저장되고, 보내는 링크(`/mobile-doc?token=`)는 열리는 화면이 없어요. 알림톡도 실제로 보내지 않고 문구만 복사해요.
7. **의뢰인 마이페이지에서 쓴 진술서·재산·수입지출이 서버에 저장되지 못해요.** 사건 기록(`crm_clients`) 보안 규칙이 "로그인 사용자 = `client_id`"일 때만 허용하는데, `client_id`에는 상담 요청 번호(`req-…`)가 들어가요. 의뢰인 저장은 거절되고, 의뢰인 화면은 서버의 사건 기록을 읽지도 않아요. 회생동행(나홀로·타 사무소) 작성분은 기기에만 저장돼요.
8. **공식 신청 필수 서류 중 허브에 없는 것이 있어요.** 회생 정식 채권자목록 카드가 없고(코드 D5106 카드가 '파산 및 면책신청서'로 잘못 붙어 회생 채권자목록 파일을 내려줌), 파산 신청 필수 7종 중 진술서·채권자목록·재산목록·현재의 생활상황·수입지출·자료제출목록 카드가 없어요. 변제계획안 제출서, 송달장소 및 송달영수인 신고서(제목이 '변경신청서'로 붙음), 담당변호사 지정서, 소송구조신청서, 재산조회신청서, 불출석사유서, 예납금 관련 신청서도 없어요.

### 2-4. 스마트 추천

- 입력: 상담 때 정리한 소득·채무·직업·주거·혼인·압류 여부, 사건 상태. 규칙은 고정 규칙(무작위 없음).
- **파산 여부를 '소득 0원 또는 채무 5억 초과'로 추정**해요(06 기획서 BK-1에서 제거 결정).
- **추천 코드 6개가 목록에 없어서 조용히 빠져요:** 기본 신청서(100001 회생, 100002 파산) → **본신청서가 한 번도 추천되지 않아요.** 급여소득자 금지명령 121150(지금은 D5114-1), 영업소득자 금지명령 121140, 그 외 숨김 규칙의 100001~100003·121140·121150·121170·133110·135036.
- 화면의 '추천 3'은 기혼 의뢰인 기준(위임장 + 배우자 보정서 2종)이에요. 금융자료제공동의서는 모바일 목록에만 넣고 화면에는 안 나와요.

## 6. 의뢰인 작성 연계

### 6-1. 흐름별 점검

| 흐름 | 요청 | 의뢰인 화면 | 저장 | 변호사에게 돌아옴 | 서식에 반영 |
|:---|:---|:---|:---|:---|:---|
| 허브 '모바일 요청' (5종) | 변호사 브라우저 localStorage + 안내 문구 복사(알림톡 미발송) | `MobileDocFillView` — 의뢰인 앱에 화면이 붙어 있지 않고 `/mobile-doc` 주소도 없음 | 기기 저장 | 같은 브라우저에서만 '완료' 표시 | ❌ 입력값·서명을 읽는 곳 없음 |
| 진술서 | 독촉 문구 복사만 | 마이페이지 서류함 '진술서' (구조화 입력·자동 임시저장) | `crm_clients` 저장 시도 → **보안 규칙에 막힘** | 변호사 '진술서 동기화' 화면에서 검토·반영 | ⚠ HTML 미리보기에는 반영(데이터가 도착할 때만) |
| 재산목록 D5102 / 수입지출 D5103 / 100만 원 소명표 | 요청 기능 없음 | 마이페이지 서류함 | 같은 문제 | 상태값 '변호사에게 제출' | ⚠ 같은 조건 |
| 서류 요청(`requestDocument`) | 기능은 있으나 **화면에서 부르는 곳 없음** | '지금 할 일' 개수 계산만 (의뢰인은 서버를 안 읽어서 0) | - | - | - |
| 보정 추가서류 요청 | 보정 센터 안 별도 목록 + 문구 복사 | 읽는 화면 없음 | 보정 초안 안 | - | - |
| 위임장 서명 | 없음 (원격서명은 계약서·약관만) | - | - | - | - |

### 6-2. 원인 (근본 문제 3개)

1. **사건 기록 보안 규칙 키가 맞지 않아요.** migration 011의 `crm_clients` 규칙은 `auth.uid() = client_id`일 때 의뢰인을 허용하는데, 행 키는 상담 요청 번호예요. 의뢰인의 읽기는 빈 결과, 저장은 거절돼요. 이후 이 규칙을 고친 마이그레이션은 없어요.
2. **의뢰인 화면은 서버 사건 기록을 읽지 않아요.** 마이페이지는 이 기기 사본(`getCrmClientSync`)만 봐요. 그래서 변호사가 남긴 서류 요청·반려 사유·사건번호가 의뢰인에게 안 보여요.
3. **의뢰인 저장이 행 전체를 덮어써요.** 저장이 사건 기록 한 줄 전체(메모·활동·서류·확장 데이터)를 올리는 방식이라, 규칙을 열기만 하면 의뢰인 기기의 오래된 사본이 변호사 작업을 덮어쓸 수 있어요. → 의뢰인 작성분은 **별도 테이블(작성 요청·제출)** 로 받는 게 안전해요.

그 밖에: 요청이 없으면 공유 키 `'client-self'`로 저장(한 브라우저의 여러 사용자 섞임), 제출 후 검토·승인·반려 상태 없음, 진술서 반영 성공 문구가 "법원 신청서류에 반영"으로 과장, 변호사 개시신청서 편집 화면이 **주민번호 13자리 전체를 저장**(L8 위반).

### 6-3. 회생동행(마이김변 계약 없는 사건)

나홀로·타 사무소 이용자도 진술서·재산·수입지출·소명표를 쓸 수 있지만 **전부 기기 저장**이고, 출력은 브라우저 인쇄뿐이에요. 면책신청서는 빈 HWP 내려받기뿐(작성기 H-0은 미구현).

## 8. 개선 계획 (개발 계획서 H-11~H-14, S 트랙 보강)

### 🔴 출시 전

- **H-11. 서식 허브 정리 (정직한 표시 + 바른 연결)**
  - 카드마다 상태를 사실대로: `작성기`(데이터 채움 + 글자 PDF) / `빈 공식 양식`(내려받기만) / `양식 준비 중`. 'AUTO-FILING PRO'·'대법원 정식 HWPX 전자소송 양식 & 발급/작성 자동화' 같은 문구는 실제 동작대로.
  - 잘못 붙은 서식 바로잡기(2-3), 범용 화면의 이름 부분 일치 대신 **코드로만** 서식 연결.
  - 핵심 서식 카드(개시신청서·진술서·채권자목록·재산목록·수입지출·변제계획안·위임장·금지/중지명령·자료제출목록)는 **13종 에디터의 해당 탭으로 열기** — 렌더러를 하나로(H-8과 함께).
  - 가짜 기본값 삭제(사건번호 50284, 서초대로 254, 서울회생법원), 비면 '미입력' 표시 + 출력 전 경고(H-3).
  - 'AI 사유 자동 보강' → '기본 문안 불러오기'로 이름 변경, 문안을 평이한 실무 문체로 교체(외부 자문 검토 대상). '과거 모범 선례' 안내 문구 삭제(사무소가 직접 저장한 선례만 표시하도록 출시 후 전환).
  - 첨부서류 목록을 서식별로(레지스트리 `defaultEvidenceList`), 탭 이름 '전용' → '회생', '파산' (공통 포함 표시).
  - 스마트 추천: 사건 유형 값 사용(BK-1), 없는 코드 6개 교체(본신청서 → D5100 / 파산 신청서, 금지명령 → D5114-1·D5114-2).
  - '작성 테스트'는 실제 요청을 만들지 않는 미리보기로, '전자소송 패키지에 첨부'는 H-12 완료 전까지 숨김.
- **H-12. 서식 작성 공통 엔진 (입력 항목 정의 + 저장 + 글자 PDF)**
  - `questionnaireSchema`를 실제로 사용: 서식마다 입력 항목(형식·필수·도움말)을 정의하고, 사건 기록에서 자동으로 채울 항목을 지정(채권자·가족·소득·재산).
  - 1차 대상(출시 전, FH-Q1 결정): 신청 필수 회생 10종·파산 9종 + 금지·중지명령 + 보정서 상위 10종(배우자 부양·소득없음, 최저생계비 조정, 누락 채권자 추가, 전세보증금 형성, 실제 급여액, 영업 평균소득, 급여압류적립금 투입, 소액채무·부채증명, 개시 전 대위변제).
  - 작성 내용은 서버(사건별 서식 초안 테이블) 저장 + 자동 임시저장 + 수정 이력.
  - 출력은 H-7 글자 PDF 엔진(문서별 PDF, 파일명 규칙), HWPX는 H-1 순서대로.
  - 나머지 서식은 '빈 공식 양식' 표시로 유지하고 출시 후 묶음별로 작성기 전환.
- **H-13. 전자소송 묶음 연결**
  - 작성 완료된 서식이 결합실 목록에 자동으로 들어감(제출 순서는 `courtOrderSlot` → H-8 단일 순서 정의). 회생 14 슬롯 + 파산 슬롯(BK-2).
  - 서식 PDF와 의뢰인이 낸 증빙은 서로 다른 파일(규칙 제8조③), 파일당 20MB·총 100MB 확인, 진술서 슬롯 번호 통일.
  - 5단계 보정 대응에서 허브 보정서를 바로 열고, 작성한 보정서가 보정 제출 묶음에 들어가게.
- **H-14 (S 트랙과 함께). 의뢰인 작성 요청 서버화**
  - 새 테이블 `client_form_requests`(요청: 사건·서식·항목 정의·마감일·상태) + `client_form_submissions`(제출: 입력값·서명 이미지·첨부·제출 시각), RLS는 `consult_requests.client_id` 연결로 의뢰인 본인 / 담당 사무소, 관리자 제외(제로날리지).
  - 상태: 요청됨 → 작성 중 → 제출됨 → 반려(사유) / 반영됨. 반영하면 서식 초안(H-12)의 해당 항목에 값이 들어가고, 변호사가 바꾼 값과 의뢰인이 낸 원본을 둘 다 보관.
  - 의뢰인 화면: 마이페이지 서류함에 **'작성 요청' 카드 한 곳**으로 모음(진술서·D5102·D5103·소명표도 이 카드로). 알림톡 링크는 로그인(스텔스 가명 계정) 후 해당 요청으로 이동하고, 로그인 없는 토큰 링크로는 개인정보 입력을 받지 않아요(FH-Q2 결정). 지금의 `/mobile-doc?token=` 방식과 `MobileDocFillView`의 토큰 조회는 폐기해요.
  - 진술서·D5102·D5103·소명표의 기존 저장 경로를 같은 방식으로 이전 — `crm_clients` 행 전체 덮어쓰기 금지.
  - 실제 알림톡 발송(팝빌 템플릿 등록 필요), 마감 전 리마인더는 G 트랙 예약 발송.
  - 회생동행 작성분도 서버 저장(BK-8·S 트랙과 함께), '`client-self`' 공유 키 제거.
  - 변호사 개시신청서 편집의 주민번호 13자리 저장 제거(L8: 출력할 때만 입력).
