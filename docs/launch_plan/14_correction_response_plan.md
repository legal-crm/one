## 0. 한눈에 보는 결론

1. **신청 서류 순서는 실제 접수본과 거의 같아요.** 10건 모두 '신청서 → 주민등록·가족관계 → 채권자목록 + 부채증명 → 재산목록 + 재산 소명 → 수입지출 + 소득 소명 → 진술서 + 진술서 첨부 → 변제계획안 → 금지명령 → 위임장·경유확인서 → 자료제출목록' 순서예요. 우리 묶음 순서(`REHAB_14_STANDARD_ORDER` R00~R13)도 같은 뼈대예요. 다만 **진술서 첨부(무상거주확인서·건강보험 자격득실·국민연금 가입내역)를 재산 소명(R06)에 넣고, 변제계획안 제출서가 없고, 퇴직연금·카드사별 계좌 조회 같은 실제로 늘 들어가는 서류가 체크리스트에 없어요.**
2. **서류 준비 체크리스트가 사건 사실을 읽지 않아요.** 조건이 글로만 적혀 있어 자가·무상거주 사건에도 임대차계약서를 요구하고, 발급일 확인이 없고, 묶음에 넣을 때 파일 이름 글자로 칸을 고르며(건강보험 → 재산 소명), 시스템 서식은 '준비됨'으로 표시되지만 ZIP에서 빠져요. 의뢰인이 올린 서류는 서버 저장이 거절돼요(010 기획서·07 기획서와 같은 원인).
3. **실제 보정은 '한 장짜리 서식'이 아니라 '번호 붙은 요구 목록'이에요.** 광주 12항목(세부 40여 개), 의정부 체크리스트형(약 30칸 + 요약보정서 방식 지정), 대구 1항목, 인천 3항목. 요구의 대부분은 **의뢰인만 줄 수 있는 자료와 설명**(보험 해약환급금, 100만 원 이상 입출금 사용처, 대출금 사용처, 5년 주거·재산 처분, 사업장 사진, 연도별 채무 증대 경위)이고, 나머지는 사무소가 고치는 것(채권자목록 문구, 변제계획안 생계비·가용소득·회생위원 보수·양육비 조항, 예납금)이에요.
4. **우리 보정 기능은 저장이 안 되는 작업 화면이에요.** 송달일·기간을 입력해도 저장되지 않고, 법원 보정명령 목록(`correctionOrders`)은 어디서도 채워지지 않아 대시보드·사건 목록·단계 판정·의뢰인 카드가 늘 비어 있어요. 보정권고 OCR은 운영에서 로그인 정보를 보내지 않아 401로 실패하고, 결과도 저장하지 않아요. 통장 소명표는 그 브라우저에만 있고, 의뢰인 쪽은 올리기 칸 1개뿐인데 사무소 화면이 그 파일을 읽지 않아요.
5. **경쟁사 중 리걸프렌즈가 가장 완성돼 있어요.** 보정 등록(송달일·제출기한 → 캘린더), 의뢰인 앱에 보정 서류 목록·발급 안내 표시, 의뢰인이 '발급 완료' 표시, 보정서 공개 여부 선택, 신청서 수정(채권자·재산·변제예정액·회생위원 보수), 표 7종 별지, 소명방법 번호 사건 전체 이어 매기기, 제출 후 잠금. 로패스는 '보정권고 분석'(필요한 서류·진술·보완 내용을 항목별 안내)과 금융거래 분류를 내세워요. **어느 곳도 '항목별로 의뢰인에게 요청 → 의뢰인이 그 항목에 바로 답 → 그 답이 보정서의 그 항목에 들어가는' 연결은 보여 주지 않아요.** 이게 우리가 만들 차별점이에요.
6. **개편 방향:** 보정을 '회차 → 항목' 서버 데이터로 바꾸고, 항목마다 담당(의뢰인/사무소)·필요 자료·표 양식·쉬운 말 안내를 붙여요. 의뢰인은 마이페이지 '보정 할 일'에서 항목 카드를 하나씩 끝내고(올리기·표 채우기·질문 답하기·못 내는 사유), 사무소는 검토 → 소명자료 번호 → **법원 항목 순서 그대로의 요약보정서 + 수정 목록 + 전자소송 묶음**을 한 번에 만들어요. 보정에서 자주 나온 항목은 다음 사건 서류 준비 단계에 '미리 받기'로 되돌려 보정 자체를 줄여요(DP-7).

## 2. 실제 보정권고 4건 분석

### 2-1. 법원별 형태

| 법원 | 형태 | 기한 | 항목 | 특징 |
|:---|:---|:---|:---|:---|
| 광주 | 번호 서술형 | 고정 날짜 | 12항목(세부 약 40개) + 주의사항 | 표 양식을 직접 제시(가용소득·보험·주거·재산 처분·수입상황표), "항목 순서대로 답하고, 내지 않는 항목은 이유를 적고, 이미 낸 자료는 서증 번호·쪽으로 가리키고, 설명과 소명자료를 함께" 요구, 바뀌지 않은 목록도 전부 다시 제출 |
| 의정부 | 체크리스트형 | 30일 | 약 30칸 | **'요약보정서 + 항목별 첨부(목록 차례)'** 방식 지정, 일부만 보정하면 기각될 수 있다고 안내, 첨부 서류는 2개월 이내 발급분 |
| 대구 | 단문 | 14일 | 1항목 | 수입지출 목록과 변제계획안의 생계비 불일치 (10-29 원인 후보: 생계비 원 단위 처리·적용 연도 — 실무준칙 제405호는 '개시신청 당시' 기준 중위소득, 추가생계비는 대구회생법원 2026-06-15 적용 의결. 27 기획서 LS-3·LS-4·10장으로 예방) |

- 4건 모두 회생위원 명의로 왔고, 전자소송 송달 봉투 쪽·인증번호 쪽이 앞에 붙어 있어요. 기한은 '송달받은 날부터 n일'과 '고정 날짜' 두 가지예요.
- 대구·인천은 **우리 계산 엔진·서식이 정확했다면 생기지 않았을 보정**이에요(생계비 값 불일치, 양육비 조항). 리걸프렌즈 화면에도 "2025년 4월 29일부터 장래 양육비가 있으면 월 변제금 표기 방식이 바뀌었다"는 안내가 있어요 → B-3·H-12에서 양육비 표기·10항 조항을 확인 항목으로 넣어요.

### 2-3. 법적 기준

- 법원이 정한 제출기한을 지키지 않거나 서류를 내지 않으면 개시신청이 기각될 수 있어요(채무자회생법 제595조 제2호, [국가법령정보센터](https://www.law.go.kr)). 그래서 안내는 사실대로 하되 겁주는 표현('기각 위험!')은 쓰지 않아요.
- 보정기간은 법원이 정한 기간이라 **불변기간이 아니고**, 사유가 있으면 연장을 신청할 수 있어요(민사소송법 제172조, 채무자회생법 제33조 준용). `taskTemplateService`의 '불변기한' 문구는 틀려요.
- 기간 계산: 송달일은 빼고 다음 날부터 세고, 마지막 날이 토요일·공휴일이면 다음 날(민법 제157조·제161조). 고정 날짜형은 그 날짜.
- 전자소송 제출: 파일당 20MB, 첨부 총 100MB(05 기획서 8장). 직접 작성한 보정서는 글자 검색 가능 파일(규칙 제8조④) → H-7 글자 PDF.

## 5. 개편 설계

### 5-1. 흐름

```
[법원 송달] 보정권고·명령 PDF
   │  변호사: 올리기(또는 대법원 사건 조회 감지 → 등록 안내)
   ▼
① 등록  회차·종류(보정권고/보정명령/이의 답변)·법원·송달일·기간(n일/고정 날짜)
         → 법원 기한 자동 계산 + 사무소 마감(기본 5영업일 전) → 캘린더·할 일·예약 알림
   ▼
② 항목 나누기  원문 번호(1, 가, ①) 기준으로 나눔 → 분류 초안 → 라이브러리 연결
         (필요 자료·발급 안내·표 양식·의뢰인 안내 문구·답변 문안) → 변호사가 확인·수정
   ▼
③ 요청  의뢰인 몫 항목 → 마이페이지 '보정 할 일' 카드 + 알림톡·담당자 카톡(KT-2)
         사무소 몫 항목 → 직원 할 일
   ▼
④ 받기·검토  의뢰인 제출 → 발급일·형식 확인 → 확인 완료 / 보완 요청(사유) → 소명자료 번호
   ▼
⑤ 작성  요약보정서(법원 항목 순서, 항목별 답변 + 소명자료 번호 + 별지 표 + 못 낸 사유)
         + 수정 목록(채권자목록·재산·수입지출·변제계획안·변제예정액표) 다시 만들기
   ▼
⑥ 묶음  보정서 PDF + 수정 목록 + 항목 순서 첨부(파일당 20MB, 총 100MB) → 전자소송 제출
   ▼
⑦ 기록  제출일·접수증 → 잠금 → 의뢰인에게 '제출 완료' + 사본(설정) → 다음 회차 대비
```

### 5-2. 서버 데이터 (S 트랙, RLS: 담당 사무소 / 의뢰인은 자기 몫 항목만 / 관리자 제외)

| 테이블 | 주요 칸 |
|:---|:---|
| `correction_orders` | 사건, 사무소, 회차, 종류, 법원, 발신(재판부/회생위원), 송달일, 기간 방식(일수/고정), 법원 기한, 사무소 마감, 상태(접수 → 항목 정리 → 의뢰인 요청 → 작성 → 검토 → 제출 → 완료 / 연장 신청), 원문 파일(비공개 저장소 경로·SHA-256), 연장 이력, 제출일·접수증 |
| `correction_items` | 회차, 원문 번호('3-가'), 원문 글, 분류, 라이브러리 항목, 담당(의뢰인/사무소/함께), 의뢰인 안내 문구, 필요 자료, 표 양식, 상태(요청됨 → 작성 중 → 제출됨 → 보완 요청 → 확인 완료 / 낼 수 없음), 답변 문안, 못 낸 사유, 소명자료 번호, 연결 파일, 검토자·시각 |
| `correction_item_library` | 플랫폼 기본(실제 보정 4건 + 실무 일반에서 만든 분류·안내·필요 자료·표·답변 문안) + 사무소 사본(사무소가 고쳐 쓰기) |
| `case_exhibits` | 사건 전체 소명자료 번호(소갑 제n호증 방식 또는 사무소 설정 번호), 처음 낸 서면, 파일, 쪽 |
| `bank_audit_rows` | 계좌, 일자, 입·출, 금액, 상대방, 사용처, 소명자료, 작성자(의뢰인/사무소) — 지금 브라우저 저장분 대체 |

- 의뢰인 요청은 **H-14의 `client_form_requests`·`client_form_submissions`를 그대로 써요**(요청 출처 = '보정', 항목 연결). 서류함 '작성 요청' 카드와 '보정 할 일'이 같은 데이터라 의뢰인 화면이 두 갈래로 나뉘지 않아요.
- 파일은 S 트랙 서류함 저장소(비공개 버킷, 올릴 때 SHA-256)를 함께 써요. base64를 JSON 칸에 넣지 않아요.
- 항목·답변·파일 변경은 기록(누가·언제·무엇)을 남겨요.

### 5-3. 의뢰인 화면: '보정 할 일'

위치: ~~마이페이지 내 사건 맨 위, 내 관리방 상단 띠~~ → **10-29 MY-Q1 결정으로 '내 사건' 사건 화면 '할 일' 탭(보정이 진행 중일 때 맨 위) + 허브 기한 띠 하나**(28 기획서 6-2·6-4). 알림톡·카톡 링크는 로그인 후 `/my/{사건ID}/todo`로(FH-Q2 결정).

- **머리:** "법원에서 보완 자료를 요청했어요" · 사무소 마감 날짜(법원 기한이 아니라 사무소 마감을 크게, 법원 기한은 작게) · 남은 항목 n개 · 담당 직원 이름·연락 버튼.
- **항목 카드 (하나에 할 일 하나):**
  - 제목은 쉬운 말("가입한 보험의 해약환급금 자료"), 아래 '왜 필요한가요?' 한 줄, '어디서 받나요?'(발급처·경로·준비물, Stage 3 발급 안내 재사용), 예시 그림.
  - 할 일 종류: **서류 올리기**(사진·PDF, 여러 장, 휴대폰 카메라) / **표 채우기**(5-4) / **질문에 답하기**(짧은 질문 여러 개, 예: "2021년에 채무가 늘어난 이유는?") / **사진 찍기**(사업장 내부 4·외부 2 같은 장수 안내) / **확인하기**(사무소가 고친 채권자 이름·금액이 맞는지 '맞아요/달라요').
  - '이 자료를 낼 수 없어요' → 사유 고르기(없음/발급 지연/기관 거절/기타) + 설명 → 사무소에 바로 알림. 사무소는 이 사유로 보정서 '못 낸 사유'를 쓰거나 연장 신청을 만들어요.
  - 상태: 해야 함 → 작성 중(자동 저장) → 보냈어요 → **보완이 필요해요(사무소 사유 표시)** → 확인됐어요.
- **법원 원문 보기**(CR-Q1): 사무소가 켜면 원문 PDF를 볼 수 있어요. 기본 화면은 쉬운 말 카드예요.
- **제출 뒤:** "사무소가 법원에 보정서를 냈어요(날짜)" + 사본 보기(CR-Q5) + "다음에 법원이 더 요청할 수 있어요" 안내.
- **문구 원칙:** 의뢰인 화면에 월 변제금·감면율을 계산해 보여 주지 않아요. 변제계획안 수정 결과는 변호사가 확정해 보낸 경우만 '사무소가 보낸 자료'로 보여요. '기각 위험' 대신 "기한 안에 내야 법원 심사가 이어져요".
- **회생동행(나홀로·타 사무소):** 같은 화면을 '내 보정 정리' 모드로 써요(항목 직접 입력, 표·질문 작성, 출력은 본인용 요약). 대리 사건이 아니라서 보정서 자동 작성은 하지 않고 정리표 PDF까지만 (CR-12, 출시 전 — CR-Q6 결정).

### 5-5. 변호사·직원 화면

- **5단계 '보정' 화면 한 곳으로 합침:** `Stage5CorrectionCenterView`와 `ComprehensiveCorrectionCenter`를 '회차 목록 → 회차 상세(항목 표)' 하나로. 회차 상세는 왼쪽 원문 PDF, 오른쪽 항목 표(번호·요약·담당·상태·소명자료·답변 여부).
- **항목 정리:** 원문 번호 기준 자동 나누기(규칙) → 분류 초안(AI 선택, CR-Q4) → 라이브러리 연결 → 의뢰인 안내 문구 확인 → '의뢰인에게 요청'(한 번에) / '직원 할 일로'.
- **검토:** 의뢰인 제출물 미리보기, 발급일·대상자·기관 확인 칸, '확인 완료'(소명자료 번호 자동) / '보완 요청'(사유 필수, 의뢰인 카드에 표시).
- **답변 작성:** 항목마다 라이브러리 답변 문안(변호사가 쓴 문안, AI 생성 아님) → 의뢰인 답·표 값 끼워 넣기 → 변호사 수정. 기존 제출 자료는 '이미 낸 자료 고르기'로 번호·쪽 참조.
- **수정 목록:** 변제계획 편집기·H-12 작성기로 이동해 고치면 회차에 '수정본'으로 연결. 법원이 요구하면(광주형) 바뀌지 않은 목록도 다시 묶음.
- **연장 신청:** 의뢰인의 '낼 수 없어요' 사유·발급 예정일을 불러와 보정기간 연장 신청서 작성(기간 직접, 1개월 고정 삭제) → 회차 상태 '연장 신청' → 결정되면 새 기한.
- **대시보드·사건 목록:** '보정 진행 중 n건', 사무소 마감 임박(D-3), 의뢰인 미응답(요청 후 2영업일), 단계 판정 c2는 `correction_orders` 기준.

### 5-7. AI 사용 (P 트랙 기준)

- 원문은 스캔 이미지라 이름·사건번호를 가린 뒤 보낼 수 없어요. 그래서 **OCR·항목 분류는 유료 등급 키 전용 + 원본 즉시 폐기(R8 결정 경로)**로만 보내고, 항목 답변 문안은 AI로 만들지 않아요(라이브러리 문안 + 변호사 작성).
- AI 결과는 '분류 초안'으로 표시하고 변호사가 확인하기 전에는 의뢰인에게 나가지 않아요.

### 5-8. 보정 예방 (서류 준비로 되돌리기)

- 회차가 끝나면 항목 분류를 사무소 통계(법원별·분류별 횟수)에 쌓아요. 개인정보는 넣지 않아요.
- 3단계 서류 준비에서 그 법원에 자주 나온 분류를 '미리 받으면 보정이 줄어요' 묶음으로 보여 줘요(예: 의정부 → 출입국 사실증명·100만 원 이상 입출금 표, 광주 → 보험 표·5년 주거 표). 의뢰인에게는 같은 표 양식(T1~T5)을 신청 전에 요청할 수 있어요.

## 8. 완료 기준

- 실제 접수본 10건의 서류 순서와 우리 묶음 순서가 같고(진술서 첨부 위치·변제계획안 제출서 포함), 자가·무상거주 사건에 임대차계약서 요구 0건, 발급 기준이 지난 서류는 표시돼요. 자료제출목록 체크가 올린 서류와 일치해요.
- 실제 보정권고 4건을 올리면 항목이 원문 번호대로 나뉘고(광주형 세부 항목 포함), 송달일 기준 법원 기한·사무소 마감이 맞게 계산돼 캘린더에 들어가요.
- 의뢰인이 휴대폰에서 로그인 → '보정 할 일' → 사진 올리기·표 채우기·'낼 수 없어요'를 하면, 사무소 PC 회차 화면에 바로 보이고, 보완 요청이 의뢰인 카드에 다시 보여요. 다른 의뢰인·관리자는 볼 수 없어요(RLS 시험).
- 요약보정서 PDF가 법원 항목 순서를 따르고, 항목마다 답변·소명자료 번호·별지·못 낸 사유가 있으며, 글자 검색이 되고, 묶음이 파일당 20MB·총 100MB 안이에요.
- 대시보드·사건 목록·단계 판정·의뢰인 카드의 보정 표시가 서버 회차와 같고, 브라우저를 바꿔도 작업이 그대로 있어요.
- 의뢰인 화면·알림 문구에 '기각 위험'·월 변제금·감면율 0건(변호사가 보낸 자료 제외), '불변기한' 0건.
- (CR-Q6 결정으로 추가) 의뢰인이 '낼 수 없어요'를 고른 항목으로 연장 신청서가 만들어지고, 연장 결정 날짜를 넣으면 기한·사무소 마감·알림이 다시 계산돼요. 대법원 사건 조회에서 보정이 감지되면 등록 안내가 떠요(자동 등록 없음).
- 통장 거래내역 PDF·엑셀을 올리면 기준 금액 이상 줄이 T2에 채워지고, 직원 확인 전에는 의뢰인에게 나가지 않아요.
- 3단계 서류 준비에서 관할 법원의 '미리 받기' 묶음이 보이고(출시 때는 기본 묶음), 회생동행 '내 보정 정리'로 나홀로 이용자가 정리표 PDF를 받을 수 있어요(보정서 자동 작성·판단 문구 0건). 사무소 통계·선례 보관함에 이름·사건번호가 0건이에요.
