## 0. 한눈에 보는 결론

1. **변호사가 고친 숫자가 의뢰인에게 가지 않아요.** 'AI 분석 → 변호사 직접 수정'에서 월 변제금·기간을 바꾸고 '즉시 반영하기'를 눌러도, 발송 데이터는 처음 계산값(`rehabCalcResult`)을 그대로 보내요. 소견 문장만 바뀌어요.
2. **같은 제안서인데 화면마다 숫자가 달라요.** 채팅 요약·비교표는 저장된 감면율(`reductionRate`)을 쓰고, 리포트 상단은 '총 채무 − 월 변제금 × 기간'으로 다시 계산해요. 저장 필드 이름도 서로 달라(`totalReduction` 저장, `estimatedReduction` 읽기) 감면액은 늘 재계산돼요. 만원 반올림 때문에 차이가 생겨요.
3. **의뢰인에게 처음 보이는 문장이 '탕감률'이에요.** 채팅 요약 첫 줄이 "• 예상 탕감률: X%"이고, 리포트 상단 4칸 중 2칸이 감면율·감면액이에요. 금지 용어('탕감'), 결과 단정("100% 전액 면제", "독촉 및 압류 즉시 전면 차단", "네, 100% 가능합니다!", "100% 비밀 보장됩니다!")이 고정 문구에 들어 있는데, 금지 표현 검사는 **변호사가 쓴 글만** 검사해서 이 문구는 걸리지 않아요(기본 금지 목록에 '100% 비밀 보장'이 있는데도 FAQ에 그대로 있음).
4. **'AI'라는 이름과 실제가 달라요.** 외부 AI를 부르지 않는 규칙 계산인데 'AI 분석 리포트', 'AI 7p 리포트', 'AI 정밀 사건 브리핑'으로 표시돼요. 또 일반 스튜디오는 AI 기능이 켜진 변호사에게 'AI 정밀분석 연동 (PRO)' 표시와 AI 확인 팝업을 띄우지만 실제로는 일반 제안서를 보내요.
5. **필요한 항목이 빠져 있어요.** 계산에 쓴 내 정보 요약(정정 요청), 숫자가 바뀔 수 있는 이유, 실비 내역(인지대·송달료·회생위원 보수), 예상 기간·일정, 준비 서류, 제안 유효기간, 다음 할 일이 일반 제안서에는 없어요. **파산 제안서는 아예 없어요**(모든 문구·계산이 회생 기준, BK-Q1과 충돌).
6. **처음 겪는 의뢰인에게 어려워요.** 청산가치·가용소득·별제권·우선변제·개시결정·인가·면책·보정권고·최저변제액 등 18개 이상 용어가 설명 없이 나오고, 용어 설명 장치가 없어요. 글자는 10~11px가 많고, 휴대폰에서도 데스크톱용 5탭 모달을 그대로 써요.
7. **기준값이 낡거나 고정이에요.** '2026년 기준 1인 약 154만원…', 소액임차 2026 금액, '2026 기준 중위소득 60%'가 고정 문장이고 2027로 바뀌지 않아요. 수임료 기본값(150만·30만·5회·예납 30만 '송달료 포함')과 FAQ 전화번호 '02-0000-0000', 사건번호 '2026개회'가 들어 있어요. '3년간 갚을 총 원금'은 48·60개월에도 '3년'으로 나와요.
8. **PDF가 그림이에요.** 2쪽·7쪽 PDF 모두 화면 캡처(html2canvas) 이미지라 글자 검색·복사가 안 되고, 본문 8.5~11px예요.

## 1. 지금 흐름

```
[변호사] 상담 요청 → '솔루션 및 비용 제안' → calculateRepayment(상담 때 입력값) → 제안서 스튜디오
          ├─ 왼쪽: 의뢰인 정보·질문 패널
          ├─ 오른쪽: 소견 템플릿 · 수임료 프리셋 · 특이사항 · 의뢰인 질문 답변 · [미리보기]
          ├─ [AI 분석] → 리포트 모달(변호사 수정 모드) → '즉시 반영' (소견만 반영됨)
          └─ [검수 완료 및 발송] → consult_requests.proposals 저장 + 채팅 메시지 2개
[AI 사건 분석] CaseReviewCopilot → 같은 스튜디오(aiAnalysis 있음) → 'AI 분석 리포트'로 발송
[의뢰인] 내 관리방 '제안서 보기' / 비교표(2건 이상) / 마이페이지 → PremiumProposalReportModal → PDF · 계약 진행
```

- 저장: `consult_requests.proposals`(서버, 5초 폴링). 일반 제안서는 비교표용 요약만 저장(입력값·계산 결과 미저장), AI 제안서는 입력값 전체(`rehabUserInput`·`rehabCalcResult`)를 저장.
- 알림톡 발송 없음, 유효기간 없음. 공유 링크(PIN)는 의뢰인 챗봇 결과용만 있고 **변호사 제안서는 공유 불가**(결정 "변호사가 보낸 보고서만 공유 가능"과 반대).
- 직원은 변호사 컨펌 요청만 가능(변호사법 준수, 정상). 컨펌 대기 목록은 `localStorage`(S 트랙 대상 추가).

## 5. 쉬운 말로 바꾸기

### 5-1. 원칙

- 첫 화면은 **법률 용어 없이** 읽혀야 해요. 용어가 꼭 필요하면 쉬운 말을 먼저, 용어는 괄호 안에: "갚지 않아도 되는 금액(면책 예정 금액)".
- 숫자 옆에 **뜻 한 줄**: "월 변제금 52만 원 — 앞으로 매달 법원 계좌에 내는 돈이에요."
- 단정 대신 **조건**: "서류 확인 뒤 바뀔 수 있어요", "법원이 최종으로 정해요".
- 용어 설명은 **눌러서 펼치기**(물음표 아이콘, 키보드·화면낭독기 지원). 같은 용어집을 리포트·챗봇·회복 아카데미·07의 작성 요청 화면이 함께 써요.

### 7-1. 새 리포트 구성 (휴대폰 우선, 한 화면씩 아래로)

2. **이 숫자는 이렇게 나왔어요** — 내 소득 − 법원 인정 생활비(가족 ○명, ○○년 기준) = 매달 내는 돈, 재산 값(청산가치) 확인 결과를 그림 한 장으로. 펼치면 계산 과정.
3. **계산에 쓴 내 정보** — 소득·가족·채무(종류별)·재산·주거. '다른 곳이 있어요' 버튼 → 변호사에게 질문으로 전달.
4. **변호사 의견** — 변호사가 쓴 소견 전문, 준비할 점(위험 요인을 쉬운 말로).
5. **비용** — 수임료(착수금·분납 일정표) + 실비 표(인지대·송달료·회생위원 보수 또는 파산관재인 예납금·서류 발급비: 금액·내는 때·내는 곳). B-3·BK-6 기준표 값 사용. 제안 유효기간.

7. **준비 서류** — 내가 뗄 서류(발급처 링크) / 사무소가 준비할 서류. 07 기획서 작성 요청 카드와 연결.

### 9-2. 문제

**구조**
1. **상세 분석 PDF는 의뢰인 챗봇용 '자동 계산 참고 리포트'를 그대로 써요.** 변호사 제안서인데 PDF에는 **변호사 이름·소견·수임료·질문 답변이 하나도 없고**, 꼬리말과 마지막 쪽에 "변호사가 작성하거나 검토한 법률의견서가 아닙니다", "진행 여부는 선택한 변호사와 상담한 뒤 결정하세요"라고 적혀 있어요. 화면(변호사 제안서)과 PDF(자동 계산 자료)가 서로 다른 문서예요. 입력값도 `result`·`userInput`만 받아서 변호사 확정값(B-5a)이 들어갈 자리가 없어요.
2. **두 PDF의 구성·디자인·숫자 표기가 서로 달라요.** 같은 사무소가 보낸 제안서인데 종류마다 다른 문서처럼 보여요.
3. **그림 PDF**라 글자 검색·복사·확대 선명도가 없고, 휴대폰에서 확대하면 흐려요. 파일도 쪽당 수백 KB예요. 문서 정보(제목·작성자)·책갈피·태그가 없어 화면낭독기가 읽지 못해요.
4. **쪽 수가 고정**이에요('/7'). 내용이 길면 잘리고(`overflow: hidden`, 높이 1123px 고정), 짧으면 빈 공간이 남아요.

- 존댓말 평서문, 한 문장 한 가지. 영문 병기·법 조문 부제 삭제(근거는 각주 '근거: 채무자회생법 제○조').

- '법률의견서'·'OFFICIAL'·'CONFIDENTIAL'·지어낸 문서번호 삭제 → 제목 '변호사 검토 제안서', 번호는 실제 제안 ID, 꼬리말 "수임 전 검토 의견이며, 실제 결과는 법원이 정해요".
- 용어는 5-2 용어집 단일 출처에서 가져오고, 이 문서에 나온 용어만 마지막 쪽에 풀이.

**품질 확인**
- PDF에서 '월 변제금' 검색이 되고, 화면 리포트와 PDF의 숫자가 원 단위까지 같다.
- 흑백 인쇄 시 다이어그램 라벨로 의미 구분 가능.
- 휴대폰 PDF 보기에서 본문이 확대 없이 읽힘(11pt 이상).
- 빌드 전 문구 검사(M-9)가 PDF 템플릿 문구도 검사.

### 9-4. 작업 항목 (B-5e 확장)

- **B-5e-1 PDF 통합:** `PrintableLawyerOpinionTemplate`·`PrintableReportTemplate`을 '변호사 검토 제안서' PDF 하나로 통합, 상세 분석은 추가 쪽. 챗봇용 자동 계산 PDF(의뢰인 본인 결과)는 별도로 두되 B-4·B-7 기준(수치 비노출·계산기 원칙)에 맞게 정리.
- **B-5e-2 글자 PDF:** H-7 엔진 공용, 흐름 쪽 나눔, SVG 다이어그램 4종, 문서 정보·책갈피·태그, 가명 파일명.
- **B-5e-3 문구 교체:** 9-2 목록 전부, 기준값은 B-3 기준표(생계비·소액임차·압류금지·최저변제액), 파산 PDF 문구(BK).
- **B-5e-4 확인:** 9-3 품질 확인 항목을 자동 점검(글자 추출로 금지어·숫자 대조).

### 9-5. 완료 기준

- 의뢰인이 내려받는 제안서 PDF가 1종(상세 분석은 추가 쪽)이고 변호사 이름·소견·비용·유효기간이 들어 있다.
- 글자 검색이 되고, 화면과 숫자가 같으며, 감면율(%)·금지어·영문 공문서 표기·연도 고정값이 0건이다.
- 흑백 인쇄에서 모든 다이어그램을 읽을 수 있고, 파일명과 본문에 계약 전 실명이 없다.
