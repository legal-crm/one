- **사용자 요청:** "사건 진행 중에 제일 중요한 부분 중 하나가 부채증명서야. 이 부분 프로세스가 정확해야 변제금도 정확한 계산이 되거든. 다른 경쟁 서비스에서 이 부분 자세히 조사해서 우리 부채증명서 부분이 적절한지, 수정이나 업그레이드할 부분이 있는지 확인해줘. 일반적으로 부채증명서는 대행업체에 맡기는 편이야."

## 0. 한눈에 보는 결론

1. **지금은 부채증명서 값이 변제금 계산에 들어가는 길이 없어요.** 채권자별로 증명서를 올리고 확정 원금·이자를 넣어 변제계획에 반영하는 화면(`DebtCertificateTab`)과 변제계획 편집기(`RepaymentPlanEditor`)가 코드에 있지만 **어디에도 화면에 붙어 있지 않아요**. 실제로 열리는 3단계 '부채증명서' 화면에는 금액 입력·파일 올리기·반영 버튼이 없고, 데이터는 그 브라우저에만 저장돼요. 법원 서식과 계산은 '채권자 관리' 창(`CreditorManagementModal`)에 사람이 직접 친 숫자만 읽어요. 이 창은 새 채권자 원금 기본값이 **1,000만 원**이에요.
2. **실제 실무는 채권자마다 산정기준일이 달라요.** 접수본 10건 중 9건이 한 사건 안에서 산정기준일이 2~6개였고, 채권자목록의 산정근거는 모두 "부채증명서 참조 (산정기준일 …)" 형식이에요. 디던비 출력물도 채권자마다 기준일을 따로 적어요. 우리 채권자목록(D5106)은 **모든 채권자에 신청일 하나**를 산정기준일로 찍고, 데이터 구조에는 기준일 칸 자체가 없어요.
3. **증명서의 금액 구성을 담을 칸이 부족해요.** 실제 증명서 10건 모두 기준일·이율·지연손해금·합계가 있고, 7건에 대위변제, 6건에 보증인, 4건에 양수(채권 양도)가 나와요. 우리 구조는 '원금·이자' 두 칸뿐이고 지연손해금·비용·합계·이율·대위변제·양도가 없어요.
4. **계산을 틀리게 만드는 결함이 더 있어요.**
   - 증명서 값이 없으면 상담 때 추정액을 조용히 확정값처럼 써요.
   - 담보 채권은 예정부족액까지 통째로 안분에서 빠져요.
   - 우선권(세금 등)을 채권자 이름 글자로 추측해요.
   - 반영하면 채권자 목록을 통째로 바꿔 사람이 입력한 부속서류·다툼·주소가 지워져요.
   - 부속서류 번호 뜻이 코드 안에서 서로 달라요(종류 정의는 '1 공탁·2 시효·3 전부·4 다툼', 서식 엔진은 '1 별제권·2 다툼·3 전부·4 보증'). 서식에는 코드 이름이 그대로 찍혀요.
5. **진행 표시가 실제와 달라요.** 3단계 체크 'c2 채권기관별 부채증명서 발급'은 목록이 비어 있으면 **완료**로 나와요. '대행사 발송 완료 마킹'은 실제 발송 없이 "발급을 정식 개시했습니다" 알림을 만들고 7일 카운트를 고정으로 시작해요.
6. **대행업체 흐름은 뼈대가 있어요.** 대행 신청서 엑셀(실무 서식), 위임장, 인감·신분증 묶음 ZIP, 대행사별 양식 선택이 있어요. 하지만 채권자별 요청일·수령일, 회신 파일을 채권자에 나눠 붙이는 기능, 실제 비용 기록이 없어요. 위임장은 그림 PDF이고 12곳까지만 적히며 회생 전용이에요.
7. **'부채증명서 OCR'은 없어요.** 05 기획서와 CF-Q3 결정은 "부채증명서 OCR 일부가 있다"고 전제했는데, 코드에 부채증명서 읽기 기능이 전혀 없어요(`/api/ocr`는 사건·가족관계·보정만). 05 기획서 해당 줄을 고쳤어요.
8. **경쟁 3사에 로그인해 직접 확인한 결과(2장), 세 곳 모두 대행업체 의뢰·수령 관리가 없어요.** 리걸프렌즈만 '부채증명서 발급 현황'(발급 여부 체크) 정도가 있어요. 값 입력은 디던비가 가장 앞서요. 증명서에서 금액 9항목·기준일·이율·보증 관계를 뽑아 '검수 필요'로 보여 주고, 부속서류 세부 칸도 가장 촘촘해요. 로패스는 채권자 DB(유동화·대부 회사 포함 약 100곳)와 산정근거 문서 종류 14가지가 강점이에요.
9. **개편 방향: 채권자별 '부채증명 장부' 하나.**
   - 장부는 채권자 후보 → 발급 요청(대행사·사무소 팩스·의뢰인 직접) → 수령 → 증명서 값 확인 → 대조 → 채권자목록 반영(덮어쓰지 않고 칸만 갱신) → 계산으로 이어져요.
   - 모두 서버에 저장하고 파일은 비공개 저장소에 둬요.
   - 개발 DC 트랙(DC-1~DC-15), 질문 DC-Q1~Q13.

## 1. 실무 흐름 (실제 접수본·대행 방식에서 확인한 것)

### 1-1. 대행업체에 맡길 때의 흐름

1. **사무소 → 대행사 의뢰:**
   - 의뢰서(엑셀): 의뢰인 이름·연락처, 채권자 목록, 채권자마다 부채증명·카드 거래·통장 거래 요청 여부, 기본 서류(신용정보 조회, 은행연합회, 생명보험협회, 건강보험, 국민연금, 국세, 지방세·주민등록·토지) 요청 여부.
   - 함께 보내는 것: 위임장, 인감증명서(채권자 수 + 여분), 신분증 사본.
   - 우리 코드의 대행 신청서 양식이 이 구조예요.
2. **대행사 → 채권자 찾기:** 대행사가 신용정보를 조회해 의뢰서에 없는 채권자를 더 찾아요. 우리 양식의 '발급 후 추가 채권자' 칸이 이 부분이에요. 채권은 2~3년 간격으로 다른 추심 회사에 팔리고 추심 회사가 생겼다 사라지기도 해서, 개인이 직접 찾기 어려운 채권이 많아요(모바일민원 앱 설명).
3. **대행사 → 채권자별 발급:** 은행·카드사는 본사에서 다시 확인한 뒤 발급해요. 부채증명 발급이 진행되면 **의뢰인의 신용카드·계좌가 정지**될 수 있고, **본인 확인 전화**가 갈 수 있어요. 대행 양식의 주의 문구에 있고, 의뢰인에게 미리 알려야 해요.
4. **대행사 → 사무소 회신:** 증명서 묶음(우편 원본 또는 스캔 PDF)이 와요. 우리 화면은 '약 7영업일'로 가정하고 있어요.
5. **사무소 → 확인·반영:**
   - 증명서마다 기준일·원금·이자·지연손해금을 읽어 채권자목록에 옮겨요.
   - 보증 채무는 보증기관을 '장래구상권'으로 가지번호(4-1 등)에 넣고, 대위변제가 끝난 채권은 보증기관을 채권자로, 양도된 채권은 양수인을 채권자로 적어요.
6. **발급이 안 되는 경우:** 폐업·소재 불명, 개인 채권자, 발급 거부. 차용증·판결문·지급명령·통장 내역 등 다른 자료로 소명해요. 보정권고에 '소액채무·부채증명' 항목이 자주 나와요(07 기획서 H-12 상위 10종).

### 1-2. 실제 접수본 10건에서 센 것

| 항목 | 결과 |
|:---|:---|
| 사건별 부채증명서 쪽 수 | 2~16쪽 |
| 채권자목록 산정기준일 | **9건이 한 사건 안에 2~6개의 서로 다른 기준일**(같은 사건 안 간격 최대 약 3주). 1건만 기준일 하나 |
| 채권자목록 산정근거 표기 | 10건 모두 "부채증명서 참조"(사건당 2~33회), "연체이자 계산서 참조"는 0건 |
| 채권의 내용 표기 | 10건 모두 "… 완제일까지 …" 문장 형식(사건당 1~21회) |
| 장래구상권 | 6건(사건당 2~8회) |
| 증명서에 나오는 항목 | 기준일·이율·지연손해금·합계 10건, 연체이율 9건, 대위변제 7건, 보증인 6건, 발급일 6건, 미수이자 5건, 대출일·대출 과목 5건, 비용 5건, 양수 4건, 가지급금 2건 |
| 산정기준일과 신청서 날짜 | OCR로 잡힌 신청서 쪽 날짜가 기준일보다 대략 2~3개월 뒤인 사건이 여러 건이에요. 신청 직전에 증명서를 다시 떼지 않고 기준일을 그대로 적는 것으로 보여요. OCR 한계로 정확한 간격은 C-1에서 확인해요 |

### 1-3. 디던비 채권자목록 출력물 (10-28 테스트 사건)

- 채권자마다 다음을 적어요.
  - "채권현재액(원금) … 부채증명서 참조 (산정기준일 : YYYY.MM.DD.)"
  - "채권현재액(이자) … 부채증명서 참조 (산정기준일 : …)"
  - 채권자마다 기준일이 달라요.
- 채권의 내용은 표준 문장이에요: "합계 ○원 및 이중 원금 ○원에 대한 (기준일 다음 날)부터 완제일까지 약정율의 비율에 의한 금원". 이자가 0이면 "○원 및 이에 대한 …"이에요.
- 이자 칸 = 증명서 합계 − 원금이에요(테스트 값으로 확인).
- 보증 채무 다음 줄에 보증기관을 '4-1 장래구상권'으로 넣고, 표준 문장("보증채무를 대위변제할 경우 대위변제금액 및 이에 대한 대위변제일 이후의 민사법정이율에 의한 이자")을 적어요.
- **부속서류 4는 '기타'**예요. 채무자가 보증인인 경우의 주채무 내용 등을 적어요.
- 디던비 작업 화면은 묶음 PDF를 쪽별로 나눠 부채증명서를 알아보고, 값을 뽑아 '검수 필요·발생원인 확인 필요·주소 확인 필요'를 표시해요(05 기획서).

## 2. 경쟁사 비교 (10-29 세 곳 로그인해 직접 확인)

### 3-2. 데이터와 저장

- `DebtCertificateItem`에 있는 칸:
  - 채권자명·계좌/관리번호·지점
  - 예상 원금·이자, 확정 원금·이자
  - 발급일(올린 날이 들어감)·유효기한(읽는 곳 없음)
  - 파일(base64)
  - 대행비 15,000·발급비 2,000(고정)
  - 보증 가지번호·이자 3회 미납·담보, 주소·대표자·사업자번호·차용원인·차용일
- 없는 칸:
  - **산정기준일**, 지연손해금, 비용·가지급금, 합계, 약정이율·연체이율, 대출 과목·최초 대출금
  - 대위변제(일자·대위변제자), **채권 양도(양수인·양도일)**, 채권 종류(대출·카드·보증·구상·조세 등), 인격 구분
  - 채권자별 요청일·수령일·발급 방법·발급 불가 사유
- 저장:
  - 주문 전체가 `localStorage['debt_cert_order_<사건>']`에 저장되고, 저장 오류는 콘솔에만 남아요.
  - 증명서 파일도 base64로 같은 곳에 들어가서 용량 초과로 저장이 실패할 수 있어요.
  - 서버 사본(`crm_clients` 확장 칸 `debtCertificateOrders`)은 화면에 없는 탭의 '동기화'에서만 생겨요. 파일 저장소(Supabase Storage)는 쓰지 않아요.

### 3-3. 반영과 계산

- 반영 함수 `convertDebtItemsToRepaymentCreditors`:
  - **원금:** 확정 원금이 없거나 0이면 **상담 때 추정 원금**을 써요.
  - **이자:** 확정 이자만 쓰고 추정 이자는 버려요.
  - **우선권:** 이름에 '세무서·구청·시청·국세·지방세·건강보험·국민연금'이 들어가면 우선권으로 봐요.
  - **차용일:** 없으면 발급일, 그것도 없으면 '2024-01-01'이에요.
  - **차용원인:** 없으면 '대여금 / 신용대출'이에요.
  - **미확정 표시:** 증명서가 없으면 미확정으로 표시만 하고 안분에는 그대로 넣어요.
  - **다툼·담보 세부:** 다툼 여부는 옮기지 않고, 담보는 여부만 옮겨요(예정부족액 없음).
- 반영 방식: `rebuildPlanWithAssets`로 **채권자 전체를 교체**해요. 채권자 관리 창에서 넣은 부속서류·다툼·주소·보증 정보가 사라져요.
- 서식·계산이 읽는 값: 법원 서식 엔진(`courtFilingEngine` 528~531)과 자동 초안은 `repaymentPlan.creditors`만 읽어요. 묶음 출력 창만 `repaymentPlan → 부채증명 주문 → 상담 진술액×10000` 순으로 대체해요.
- 계산 엔진:
  - 담보 채권은 원금 합계·안분에서 통째로 빠져요(`isSecured ? 0`, 293·675행). 예정부족액은 들어가지 않아요.
  - 이자는 '원금만' 모드(기본)에서 안분에 쓰이지 않아요.
- 채권자목록(D5106):
  - 머리의 산정기준일 = 신청일이에요.
  - 채권의 내용 = 차용원인 글자 + "(부속서류: ANNEX_4_DISPUTED)" 같은 코드 이름이에요.
  - 산정근거 기본값은 "부채증명서 참조"(기준일 없음)·이자 "연체이자 계산서 참조"예요. 실제 접수본에는 '이자 계산서' 표기가 0건이에요.
- 부속서류 번호 뜻이 서로 달라요.
  - 종류 정의(`repaymentTypes.ts` 255~): 1 변제공탁 · 2 시효완성 · 3 전부명령 · 4 다툼
  - 서식 엔진(`courtFilingEngine.ts` 412): 1 별제권 · 2 다툼 · 3 전부명령 · 4 보증
  - 실제 양식(디던비 출력물): 4 = 기타(보증인 등)
  - `isDisputedCreditor`는 4번을 다툼으로 봐요.

### 3-4. 진행 표시

- 3단계 체크 c2(`CrmTab` 1932): `debtCertificateOrders.every(완료)` → **빈 목록이면 완료**. 실제로 열리는 화면은 이 칸에 쓰지 않아서 늘 비어 있어요.
- 서류 체크리스트는 '부채증명서(채권사별 각 1통)' 한 줄이에요. 채권자별 줄이 없어요.
- 알림톡 '서류 요청 1차'는 "약 7일 소요"·"인감증명서 {채권자 수+5}부"를 안내해요.
- 할 일 템플릿 '부채증명서 발급 대행 신청(+3일)'이 있지만 연결돼 있지 않아요(CM-4).

## 5. 개편 설계 — 채권자별 '부채증명 장부'

흐름: **채권자 후보 → 발급 요청 → 수령 → 값 확인 → 대조 → 채권자목록 반영 → 계산**. 모든 단계는 사건(`cases.id`, CM-1)에 붙고 서버에 저장해요(S·RB-1). 정책·검사는 사용자 방침대로 **경고 + 확인 + 기록**이고 막지 않아요.

### DC-1 화면 하나로 합치기
- 3단계 '부채증명서'를 채권자별 장부 화면으로 바꿔요. 숨겨진 `DebtCertificateTab`의 쓸 만한 부품(파일 보기·가지번호·대행사 양식·위임장)을 옮기고, 남는 코드는 지워요(DC-13).
- 구성:
  - 위: 진행 요약("12곳 중 받음 9 · 값 확인 7 · 발급 불가 1"), 예정일·늦음 표시
  - 가운데: 채권자 표(번호·채권자·출처·발급 방법·요청일·예정일·수령일·상태·확정 원금·기준일·차이 표시)
  - 오른쪽: 증명서 보기 + 값 칸(DC-4)

### DC-2 서버 모델
- `debt_certificates`: 사건·채권자 줄(장부 행)·상태·발급 방법·요청/예정/수령일·발급 불가 사유·대체 소명 종류·값(DC-4)·확인자·확인 시각·버전.
- `debt_certificate_files`: 비공개 저장소 경로·SHA-256·쪽 범위(묶음 PDF에서 나눈 경우)·올린 사람.
- `debt_agency_orders`: 대행사·보낸 날·포함 채권자·첨부 목록·비용(대행비·발급비 실제값)·회신일.
- RLS는 담당 사무소만이고 관리자는 제외해요(제로날리지). 브라우저의 `debt_cert_order_*`는 처음 열 때 서버로 옮기고 지워요.

### DC-3 채권자 후보와 출처
- 후보를 한 표에 모으고 출처를 붙여요.
  - 의뢰인 진술(정리도우미)
  - 신용정보 조회서(NF-7)
  - 대행사 신용조회 '추가 채권자'
  - 통장·카드 내역
  - 사무소 직접 추가
- '누락 대조'를 보여 줘요: 후보에는 있는데 증명서가 없는 곳, 증명서는 있는데 채권자목록에 없는 곳.
- 같은 채권 이중 등록 경고: 원채권자와 양수인이 둘 다 있거나, 주채무와 대위변제 구상금이 둘 다 원금으로 잡힌 경우.

### DC-4 증명서 값 확인 화면
- 칸(디던비 추출 칸과 맞춤):
  - 기준일(필수) · 발급일
  - 현재 원금 · 이자 · 연체이자(지연손해금) · 기타이자 · 가지급금 · 법비용 · 수수료 · 기타비용 · 총채무액(합계)
  - 정상(약정)이율 · 연체이율 · 대출일(발생일) · 대출 과목(발생원인) · 최초 대출금 · 계좌/관리번호
  - 보증인 · 담보 여부
  - 대위변제(여부·일자·대위변제자)
  - 양도(여부·양수인·양도일)
- 검산: 원금 + 이자 항목 + 비용 항목 ≠ 총채무액이면 '합계 확인' 경고.
- 한 장에 채권이 여러 건이면(세금 여러 세목, 보증 증명서의 원채권 + 장래구상권 등) 줄을 나눠 각각 확인해요(디던비 방식).
- 분류: 주된 분류 하나(일반·조세/우선·물적담보·보증채무·장래구상권·미확정)와 겹칠 수 있는 속성(보증·장래구상권·물적담보: 예/아니오/미확정)을 따로 둬요(DC-Q13).
- 표시: '검수 필요'(값을 아직 사람이 확인 안 함), '발생원인 확인 필요', '주소 확인 필요', '합계 확인'.
- 칸마다 '확인' 표시와 확인자를 남겨요.
- OCR 초안은 DC-Q3 결정에 따라 붙여요(유료 키, 외부 전송본은 남기지 않음, 원본 증명서는 제출 서류라 비공개 저장소에 보관).

### DC-5 채권 관계 처리
- **보증 채무(신청인이 주채무자, 보증기관 있음):** 보증기관을 '장래구상권' 가지번호(4-1)로 자동 추가하고 표준 문장을 넣어요. 장래구상권 줄에는 보증기관·주채권자·보증잔액·보증일자·보증비율·보증기한과 '연결할 원채권'을 둬요(디던비 방식). 원채권의 보증인 칸에는 보증의 종류·대위변제 여부·관계·채무자 담보 제공을 둬요.
- **대위변제 끝남:** 채권자를 보증기관(구상금)으로 바꾸는 안을 보여 주고, 사람이 확인해야 바뀌어요. 원채권자는 메모로 남겨요.
- **양도:** 양수인을 채권자로 바꾸는 안을 보여 주고 원채권자를 메모로 남겨요. 둘 다 원금으로 잡히면 경고해요.
- **신청인이 보증인인 채무:** 부속서류 4(기타)에 주채무 내용을 넣어요.

### DC-6 채권자목록 반영 (덮어쓰지 않기)
- 확정된 증명서 값은 채권자목록의 **해당 칸만** 바꿔요(원금·이자·기준일·산정근거·채권의 내용). 사람이 넣은 부속서류·다툼·주소·메모는 그대로 둬요. 바뀐 칸은 이전 값과 함께 기록해요.
- 산정근거는 "○○ 참조 (산정기준일 : YYYY.MM.DD.)"로 자동 작성해요. ○○은 문서 종류를 골라요(로패스의 14가지: 부채증명서·부채증명원·부채잔액증명서·부채확인서·잔고증명서·대출증명서·채무확인서·채무승인서·금융거래확인서·자료송부서·채무잔액확인서·특수채권채무확인서·대출잔액증명서·직접입력 + 우리 추가: 차용증·판결문·지급명령·통장 내역·의뢰인 진술).
- 채권의 원인은 표준 문장으로 자동 작성해요: "YYYY. MM. DD.자 대출거래약정에 따른 최초 대출금 ○원"(대출일·최초 대출금이 있을 때). 카드·세금·구상금은 종류별 문장을 따로 둬요.
- 채권의 내용은 표준 문장으로 자동 작성해요. 기준일 다음 날·합계·원금이 들어가고, 이자가 0이면 "및 이에 대한" 형식이에요. 이율 표현('약정율'/'연체이율')은 DC-Q11대로 해요. '채권의 내용 직접 수정'을 켜면 사람이 쓴 문장을 그대로 써요(리걸프렌즈 방식).
- 머리 산정기준일은 DC-Q4대로 처리해요.
- 가짜 기본값을 지워요: 차용일 '2024-01-01', 차용원인 '대여금 / 신용대출', 새 채권자 1,000만 원·사용처. 빈 칸은 빈 칸으로 두고 '확인 필요'로 표시해요.
- 부속서류 번호 정의를 하나로 맞춰요(1 별제권부, 2 다툼이 있거나 예상, 3 전부명령, 4 기타). C-1 실제 접수본과 공식 양식으로 최종 확인해요. 서식에 코드 이름이 찍히지 않게 해요.

### DC-7 계산 연결
- 엔진에는 채권자목록 값만 들어가요. 증명서가 없는 채권자는 '추정'으로 표시하고, 서식 출력과 제안서 발송 전에 "추정 채권 ○곳"을 경고·확인·기록해요(DC-Q6).
- 이자 칸 구성은 DC-Q5대로 처리하고, 증명서 값은 나눠 저장해요.
- 담보 채권 예정부족액을 안분에 넣고 유보로 처리해요(DC-Q8, B-3에서 C-1 정답 데이터로 검증).
- 우선권은 채권 종류(조세·공과금 등) 값으로 정해요. 이름 글자 추측은 지우고, 공용 채권자 정보(NF-5)의 기본 종류를 처음 값으로 써요.

### DC-8 차이 경고
- 의뢰인 진술액과 증명액의 차이가 기준(DC-Q7) 이상이면 '차이 큼' 표시를 해요. 상담 때 보낸 제안서와 총액이 달라지면 변호사에게 "제안서 수치 다시 확인" 할 일을 만들어요(의뢰인에게 자동으로 알리지 않음).
- 기준일 간격 경고: 사건 안에서 가장 이른 기준일과 늦은 기준일, 신청 예정일과의 간격을 보여 줘요. 경고 기준은 사무소 설정이고 기본은 표시만 해요.

### DC-9 대행사 연결
- 사무소 설정에 '거래 대행사'를 둬요: 이름·연락처·이메일·건당 대행비·발급비·의뢰서 양식·평균 소요일. 대행사 계정·로그인은 만들지 않아요(SL-Q9과 같은 원칙).
- 의뢰 묶음:
  - 의뢰서 엑셀(대행사 양식), 위임장, 인감증명서·신분증(서류함에서 고름)을 하나로 묶어요.
  - 위임장은 글자 PDF(H-7)로 만들고, 12곳 제한을 없애 별지를 붙이고, 회생·파산 용도와 수임인(사무소/대행사)을 고르게 해요.
  - 주민번호 뒷자리는 출력할 때만 입력받고 저장하지 않아요(L8).
- 보내기: 출시 전에는 묶음 내려받기 + '보냄' 기록(보낸 날·방법)이고, 이메일 발송은 DC-Q2대로 해요.
- 회신 받기: 대행사가 보낸 묶음 PDF를 올리면 쪽을 나눠 채권자 줄에 붙여요(사람이 고르기, 쪽 미리보기). 원본 우편 수령 표시도 둬요.
- 비용: 실제 대행비·발급비를 기록해 계약 실비(계약 위저드)·수임료 수납(FE)·법원 비용 한 번에(T-6)가 같은 값을 읽게 해요. 고정 17,000원을 지워요.
- 사무소 직접 발급은 NF-4(팩스 일괄 발송)를 그대로 써요. 의뢰인 직접 발급(은행 앱 등)은 의뢰인 '서류 올리기' 요청(H-14)으로 받아요.

### DC-10 진행 표시·게이트·안내
- 채권자별 상태: 요청 전 → 요청함 → 받음 → 값 확인 → 반영. 예외 상태 '발급 불가(사유)'.
- 3단계 체크 c2 = 모든 채권자가 '반영' 또는 '발급 불가 + 대체 소명'일 때만 완료예요. 빈 목록이면 미완료예요.
- 서류 체크리스트의 부채증명서 한 줄은 장부 진행률로 바꿔요(DP-1과 함께).
- 가짜를 지워요: '발송 완료 마킹'의 "정식 개시" 알림, 7일 고정 카운트, "자동 반영됩니다" 문구. 예정일은 대행사 평균 소요일(기본 7영업일)로 정하고, 지나면 '늦음' 표시와 할 일을 만들어요.
- 의뢰인 화면(CM-11): "부채증명서 ○곳 중 ○곳 받음"과 발급 중 주의사항을 보여 줘요. 주의사항은 **카드·계좌가 정지될 수 있음, 본인 확인 전화가 올 수 있음, 인감증명서 부수**예요. 금액 표시는 DC-Q9대로 해요.

### DC-11 발급이 안 될 때
- 사유를 고르게 해요: 폐업·소재 불명·개인 채권자·발급 거부·양도 후 양수인 확인 중·기타.
- 대체 소명 종류를 고르게 해요: 차용증·판결문·지급명령·통장 내역·문자 등. 산정근거 문구가 자동으로 바뀌어요.
- 보정 연결: 보정권고에 부채증명 항목이 오면 해당 채권자 줄로 바로 가게 해요(CR-3 항목 나누기와 연결).

### DC-12 파산 사건도 같은 장부
- 파산도 같은 장부를 써요(BK-1). 파산 채권자목록 CSV 18열(BK-3)의 최초 채권액·차용일·발생원인·사용처는 증명서에 대출일·최초 대출금이 있으면 채우고, 없으면 '확인 필요'로 둬요. 회생에서 파산으로 바꿀 때 장부를 이어받아요.

### DC-14 서식 작성기 채권자 칸 보강 (경쟁사 비교에서 나온 것, H-10과 함께)
- **인격 구분**(자연인·법인·비법인·국가·지방자치단체)을 채권자마다 둬요. 전자소송 CSV 필수 칸이고 지금은 없어요. 공용 채권자 정보(NF-5)의 기본값을 써요.
- **부속서류 세부 칸**을 디던비 수준으로 채워요.
  - 1 별제권부: 담보설정일·담보권 종류·채권최고액·담보물 시가·담보권 순위·환가율·선순위 담보 채권최고액 합계·담보목적물 종류·별제권 미확정액
  - 2 다툼: 다툼 원인, 원금·이자·이율 다툼, 채권자 주장 원금·이자·이율, 소송 진행 단계(1~3심 법원·사건번호·결과)
  - 3 전부명령: 사건번호·제3채무자·피압류채권·확정 여부
  - 4 기타: 신청인이 보증인인 경우의 주채무자(성명·주소·전화·팩스·보증한도·관계), 물상보증
- **목록 정렬:** 자동(담보 → 우선 → 일반, 같은 묶음은 발생일순, 투더코어 기준)과 수동 끌기 중에 고르게 해요(05 기획서 채권자목록 고도화와 같음).
- **집계:** 원금·이자·담보/무담보 합계, 총 채권자 수와 **중복 제외 채권자 수**(같은 채권자의 여러 채권은 한 번). 중복 제외 수로 채권자목록 부본 수(채권자 수 + 2통)와 인감증명서 부수를 계산해요.
- **이자 처리 방식** 선택(원금 먼저 / 원리금 합산)은 이미 엔진에 있는 모드를 화면에 그대로 보여 줘요.
- **채권자 정보 수정 요청:** 작성기에서 채권자 주소·대표자가 틀리면 바로 공용 채권자 정보에 수정 제안을 보내요(리걸프렌즈 방식, NF-5).

### DC-15 증명서 자동 읽기 (DC-Q3에 따라)
- 디던비 흐름을 기준으로 해요: 묶음 PDF 올리기 → 쪽마다 문서 종류 분류 → 부채증명서는 DC-4 칸으로 추출(한 쪽 여러 채권 나누기, 보증 증명서는 원채권 + 장래구상권) → 검수 표시 → 채권별 반영·전체 반영 → 쪽을 채권자 줄에 붙이기 → 분류된 PDF 묶음 내려받기.
- 다른 문서 종류(해약환급금·계좌·급여)는 CF-Q3 자료 자동입력과 같은 엔진으로 이어요.
- 외부 AI 전송은 P 트랙 기준이에요(유료 키, 전송본 보관 안 함, 주민번호 칸은 읽지 않음).

### DC-13 정리
- 화면에 없는 `DebtCertificateTab`은 DC-1로 부품을 옮긴 뒤 지워요. `RepaymentPlanEditor`를 연결할지는 H-10·B-3에서 정해요.
- 의뢰인 '7대 실무 입력'은 H-14 의뢰인 작성 요청으로 옮기고, 옛 주소 링크는 지워요.
- '숨은 채무 조회'를 숨겨요(NF-7과 같음).
- 05 기획서의 "부채증명서 OCR 일부" 표기를 고쳐요(이번에 반영함).

## 7. 완료 기준

- 실제 열리는 화면 하나에서 채권자별로 요청 → 수령 → 값 확인 → 반영까지 끝나고, 새 탭·다른 기기에서도 같은 값이 보여요. 브라우저 저장소에 부채증명 데이터가 0건이에요.
- 시험 사건(채권자 8곳, 기준일 4개, 보증 1건·대위변제 1건·양도 1건)으로 다음을 확인해요.
  - 채권자목록에 채권자별 산정기준일과 표준 문장이 나와요.
  - 보증기관이 4-1 장래구상권으로 들어가요.
  - 대위변제·양도 채권이 한 번만 잡혀요.
  - 이자 칸이 DC-Q5 규칙과 같아요.
- 증명서가 없는 채권자가 있으면 서식 출력·제안서 발송 전에 경고가 뜨고, 확인 기록이 남아요.
- 반영을 두 번 해도 사람이 넣은 부속서류·다툼·주소가 그대로예요.
- 3단계 c2는 빈 목록에서 미완료예요. '정식 개시' 가짜 알림·7일 고정 카운트가 코드에 없어요.
- C-1 실제 접수본 중 3건을 장부에 넣어 만든 채권자목록의 원금·이자·기준일이 접수본과 모두 같아요.
- 부속서류 번호 정의가 한 곳에만 있고, 서식에 코드 이름이 찍히지 않아요.
- (DC-14) 모든 채권자에 인격 구분이 있고 전자소송 CSV에 그대로 나가요. 부속서류 1~3 세부 칸이 서식에 반영돼요. 중복 제외 채권자 수로 부본 수·인감 부수가 계산돼요.
