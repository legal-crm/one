## 0. 한눈에 보는 결론

1. **LeadMaster는 '영업 대행 1인 운영자'용 도구였어요.** 리드를 모아 1차 통화한 뒤 **거래처(법률사무소)에 텔레그램으로 넘기고 수임료에 따라 수당을 받는** 구조예요. 그래서 리드 데이터 모델의 중심은 '사건' 이름의 한 행(`cases`)이고, 담당자·권한·사무소 구분이 없고, 정산·세금 화면이 같이 있어요. 마이김변 영업 DB는 **사무소가 자기 광고로 모은 리드를 자기 직원이 걸러 자기 사건으로 넘기는** 구조라, 넘기는 쪽(거래처·수당·텔레그램 전달)은 필요 없고 거르는 쪽(통화 대기열·부재 재시도·종료 사유·담당자·통계)이 핵심이에요.
2. **마이김변 영업 DB는 화면만 있고 운영이 안 돼요.**
   - 리드·설정이 전부 **그 브라우저에만** 저장돼요. 사무소 직원끼리, PC와 휴대폰 사이에 공유되지 않아요. 설정 키는 사무소 구분도 없어요.
   - 광고 리드가 자동으로 들어오는 길이 없어요. 서버에 리드 테이블·접수 주소·웹훅이 없어요.
   - 통화는 '통화 결과' 버튼으로 손으로 적어요. 전화번호를 누르면 받든 안 받든 '연결됨'으로 기록되고, 부재 처리는 상태에 따라 바로 '부재 3차 이상'으로 건너뛰어요. 검색은 글자를 넣어도 아무것도 걸러지지 않아요.
   - 문자·전화 요청은 LeadMaster 앱이 읽던 테이블에 넣기만 해서, 화면엔 "앱에서 자동 발송됩니다"라고 뜨지만 실제로는 나가지 않아요.
   - 담당자 지정 화면이 없고, 통화한 사람은 늘 로그인한 변호사로 기록돼요. 화면 표시도 메뉴 권한을 확인하지 않아요(사이드바만 숨김).
   - 거래처·예상 수당·수임료/정산 탭·텔레그램 방 설정·구글 드라이브 녹음 같은 LeadMaster 전용 기능이 그대로 붙어 있어요.
3. **사용자가 말한 숫자대로라면 리드의 약 80%는 사건이 되지 않아요.** 그러니 영업 DB는 '모두 기록하는 곳'이 아니라 **'빠르게 걸러 끝내는 곳'**이어야 해요. 설계 중심:
   - **오늘 할 일 대기열:** 새 리드 → 재통화 약속 시각 → 부재 재시도 시각 순으로 자동 정렬.
   - **부재 자동 처리:** 업무폰 통화 기록으로 '연결 안 됨'을 알아서 부재로 적고, 다음 시도 시각을 규칙대로 정하고, 정해진 횟수를 넘기면 '연락 불가'로 끝내요(30%).
   - **한 번에 끝내는 종료 사유:** 단순 문의(20%), 대상 아님(사유 선택, 30%), 거절·다른 곳 선택, 중복, 수신 거부.
   - **이관:** 상담이 된 사람만 사건 관리로. 기록은 복사하지 않고 연결을 옮겨요.
   - **통계:** 매체별 리드 수·연결률·종료 사유 비율·이관률·광고비 대비 비용.
4. **새로 만들 것:** 서버 테이블(리드·이벤트·유입 경로·광고비·설정·수신 거부), 사무소 전용 리드 접수 주소(랜딩 폼·구글 광고 리드 양식·구글 시트·자동화 도구), 엑셀·붙여넣기 가져오기 개선, 담당자 배정, 업무폰 앱의 '영업 콜' 화면(대기열·통화 후 결과 화면·부재 자동 기록·부재 문자), 이관 서버 함수. LeadMaster에서 쓸 만한 것(부재 재시도 주기, 결과 코드, 18칸 요약, 이탈 사유, 매체별 광고비·리드당 비용)은 가져오고, 문제였던 것(공용 계정·전체 통화 업로드·공개 녹음 링크·브라우저 AI 키·이름으로 매칭)은 가져오지 않아요.

### 1-2. 안드로이드 앱

- **웹뷰 껍데기**예요. 리드 목록·상세·상태 변경은 모두 웹(GitHub Pages)이고, 앱은 전화 기능(걸려 온 전화 팝업, 통화 중 메모 팝업, 부재 콜 떠 있는 위젯, 통화·문자 동기화, 요청 폴링)만 해요.
- **부재 콜 위젯:** 상태 '부재' + 마지막 부재 후 N일(기본 3일) 지난 리드를 오래된 순으로 띄우고 이전/다음·전화 걸기·부재·연결·건너뛰기 버튼. 대기열 아이디어로는 좋지만, 담당자 구분이 없고 부재 +1을 기기에서 읽고 더해 써서 PC와 겹치면 숫자가 틀려요.
- **통화 후 메모가 사라지는 원인:** 통화가 끝나면 세 경로(통화 상태 변경 → 모든 떠 있는 창 닫기, 버튼 서비스의 1초 감시, 앱을 사건 화면으로 열기)가 메모 창을 닫고, 입력 중인지 확인하지 않고 임시 저장도 없어요. 메모 창에 결과 코드·다음 통화 시각도 없어요. 저장도 새 메모를 앞에 넣는데 읽을 때는 마지막을 최신으로 봐서 방금 쓴 메모가 안 보여요.
- **동기화:** 휴대폰 **전체** 통화·문자(인증번호 문자 본문 포함)를 15분마다 올리고, 실패한 묶음을 영원히 건너뛰는 기준점 버그가 있어요. 녹음 업로드 코드는 없어요.
- **자동 발신:** 코드는 있지만 시작하는 곳이 없고, 발신 직후 '통화 중' 상태를 '연결됨'으로 판단해 받지 않은 전화를 구분하지 못해요.
- **가져올 것:** 걸려 온 번호 확인 방식(통화 선별 서비스 + 번호 캐시), PC → 휴대폰 '걸기 요청', 유심 2개 선택, 부재 대기열 화면 구성. **가져오지 않을 것:** 공용 계정, 전체 통화 업로드, 떠 있는 창(오버레이), 1~3초 폴링, 자동 발신(CL 결정 '만들지 않는 것' 유지).

## 3. 목표 흐름

```
[유입]  사무소 광고 랜딩 폼 · 구글 광고 리드 양식 · 구글 시트 · 자동화 도구(사무소 전용 접수 주소)
        엑셀/CSV · 붙여넣기 · 단건 등록 · 업무폰 '모르는 번호 등록 요청'
          │  번호 정규화 → 중복 판정(같은 번호 열린 리드 = '재문의'로 합침,
          │  진행 중 사건·마이김변 상담 요청 = 연결 표시) → 수신 거부 번호 제외
          ▼
[배정]  담당자 자동 배정(순번/유입 경로별/수동) → 담당자 업무폰 알림(새 리드)
          ▼
[오늘 할 일 대기열]  새 리드(빠른 순) → 재통화 약속 시각 도래 → 부재 재시도 시각 도래
          │  업무폰에서 '걸기'(다이얼러) → 통화 종료 → 결과 화면(필수, 임시 저장)
          ▼
[결과]  연결 안 됨 → 부재 n차(자동 기록) → 다음 시도 시각 자동 / 정한 횟수 넘으면 '연락 불가' 종료
        연결됨 → ① 상담 중(확인 항목 체크) ② 재통화 약속 ③ 종료(단순 문의·대상 아님·거절·…)
          ▼
[이관]  상담이 된 리드 → '사건 관리로 이관'(서버 함수 1번에 사건 생성 + 연결 이동 + 리드 '이관 완료')
          ▼
[통계]  매체별 리드 → 연결 → 상담 → 이관 → (사건 쪽) 계약, 광고비 대비 비용, 담당자별 처리량
```

### 3-1. 리드 상태 (6개 + 종료 사유)

| 상태 | 뜻 | 들어가는 방법 | 대기열 |
|:---|:---|:---|:---|
| 신규 | 아직 연락 전 | 유입 | 맨 위(들어온 순) |
| 부재 | 걸었지만 연결 안 됨(1차·2차…) | 통화 기록 자동 또는 직원 선택 | 다음 시도 시각이 되면 |
| 재통화 약속 | 고객이 정한 시각에 다시 | 결과 화면 | 약속 시각 10분 전부터 |
| 상담 중 | 연결돼 확인 항목을 받는 중 | 결과 화면 | 다음 할 일 시각(선택) |
| 이관 완료 | 사건 관리로 넘어감 | 이관 | 없음 |
| 종료 | 더 연락 안 함 | 결과 화면·자동 | 없음 |

**종료 사유 (필수, 고정 선택지 + 메모):** 연락 불가(부재 n회) / 결번·잘못된 번호 / 단순 문의(정보만 원함) / 대상 아님(채무 금액 / 소득 / 재산 / 이미 진행 중인 절차 / 과거 이력 / 기타) / 거절·다른 곳 선택 / 시기 미정(장기 관리: 다시 연락할 날짜 지정 시 그날 '신규'처럼 대기열로) / 중복 / 수신 거부(번호를 수신 거부 목록에 넣음).

- '대상 아님'은 **사무소 직원이 변호사 지시에 따라 판단**하는 내부 기록이에요. 고객에게 '대상 아님'·'불가능' 같은 결과를 문자로 보내는 기능은 만들지 않아요.
- 기존 10개 상태(`no_answer_1~3`·`rejected`·`ineligible`·`wrong_number` 등)는 새 상태 + 부재 횟수 + 종료 사유로 옮겨요.

### 3-2. 부재 재시도 규칙 (SL-Q2 결정, 사무소 설정)

- 결정값: **1차 부재 → 같은 날 3시간 뒤**(근무 시간 안), **2차 → 다음 날 반대 시간대**(오전↔오후), **3차 → 2일 뒤**, **4차 → 4일 뒤**, **5차 부재면 '연락 불가' 자동 종료**(종료 전 마지막 부재 문자 1회 제안).
- 근거: 광고 리드는 문의 직후 연결률이 가장 높아서 첫 48시간에 3번을 몰아요. LeadMaster의 '등록 경과일별 주기'(2·5·14일)는 그 뒤 단계에 맞아 4·5차에 반영했어요.
- 2차 부재 뒤 '부재 문자'(템플릿, 업무폰 직접 발송) 1회를 제안해요. 문구는 금지 표현 검사(M-9)를 통과해야 하고 '무료상담'·'진단'·'전담' 같은 표현은 쓰지 않아요.
- 통화·문자 가능 시간 기본 09~20시(사무소 설정), 그 밖의 시간에는 대기열에 '내일'로 보여요.

### 3-3. 상담 확인 항목 (연결됐을 때)

- 18칸 요약을 줄여 **통화 중 체크하기 쉬운 10칸**: 대략 총 채무(구간 선택 가능), 월 소득(구간), 소득 형태(급여·사업·무직·기타), 4대보험, 재산(집·차·보증금 유무와 대략 금액), 주거 형태, 혼인·부양 자녀 수, 연체·추심 상태, 과거 회생·파산·신복위 이력, 희망 절차(회생·파산·모름).
- 모르면 '모름'으로 비워 두고 지어낸 기본값은 넣지 않아요.
- 화면은 입력값에 따라 '변호사 확인 필요'(예: 재산 큼, 이력 있음) 같은 **참고 표시**만 하고 자동으로 대상 여부를 정하지 않아요.
- 이 값은 이관할 때 사건의 기초 정보로 그대로 넘어가요(단위는 원으로 통일).

### 5-1. 영업 DB 목록 (지금 화면을 고쳐 씀)

- **머리 (10-29 사용자 확인: 지금 버튼 3개 유지):** **'경로/환경 설정' · '엑셀 대량 등록' · '+ 단건 DB 등록'은 이름·위치 그대로 두고 안을 고쳐요.** 붙여넣기는 '엑셀 대량 등록' 창 안 탭으로, 접수 주소 만들기는 '경로/환경 설정'의 유입 경로 안으로 넣어요. 앞에 '오늘 할 일 n건'(대기열 바로가기)만 추가해요.
  - 엑셀 대량 등록: 지금 3단계(파일 선택 → 열 맞추기·묶음 이름·기본 유입 경로 → 중복 검사), 양식 내려받기, 5MB·5,000행 제한, 중복 강제 등록 선택을 유지하고 SL-7 개선만 더해요.
  - 단건 DB 등록: 지금 입력 칸과 중복 경고를 유지하고, 필수 3개(이름·전화·유입 경로)·가짜 기본값 삭제·필드 아래 오류 표시만 바꿔요.
- **탭:** 오늘 할 일 / 신규 / 부재 / 재통화 약속 / 상담 중 / 이관 완료 / 종료. 각 탭 건수.
- **필터:** 담당자(기본 '내 리드', 대표·변호사는 '전체'), 유입 경로, 기간(들어온 날), 가져온 묶음, 종료 사유. 검색(이름·번호 끝 4자리·지역·메모).
- **열:** 이름·번호 / 유입 경로·들어온 시각(경과 시간 표시) / 담당자 / 상태(부재 n차) / 다음 할 일 시각 / 최근 통화 결과 / 작업(업무폰으로 걸기·결과 적기·⋯).
- **일괄 작업:** 담당자 배정, 종료(사유), 부재 문자, 내보내기(대표만, 내보내기 기록).
- 로딩은 표 모양 스켈레톤, 빈 상태는 '리드 가져오기·접수 주소 만들기' 버튼.

### 5-2. 리드 상세 (탭 5개 → 한 화면 + 오른쪽 패널)

- **왼쪽:** 기본 정보(이름·번호·유입 경로·캠페인·사전 정보·동의 기록), 상담 확인 10칸, 메모.
- **오른쪽:** CL-5 소통 기록 부품(통화·문자·녹음·대화록, 사건 화면과 같은 부품), 다음 할 일·일정.
- **위:** 상태·담당자·'결과 적기'·'사건 관리로 이관'.
- 삭제: 수임료/정산 탭, 예상 수당, 거래처(법률사무소) 선택, 텔레그램 방 복사, 구글 드라이브 설정, 1·2·3차 자유 상태, 전화번호 클릭 시 '연결됨' 기록.
- '요약문'은 '이관 요약'으로 바꿔요(사건으로 넘어갈 때 첫 메모로 자동 첨부, 복사 가능).

### 5-3. 결과 적기 (웹·업무폰 공통)

- 첫 질문 "연결됐나요?" → **아니요:** 부재(자동으로 n차·다음 시도 시각 표시, 부재 문자 보낼지) / 결번. **네:** 상담 중(확인 10칸 열기) / 재통화 약속(날짜·시간, 빠른 버튼 '1시간 뒤·오늘 저녁·내일 오전') / 종료(사유).
- 메모 한 줄, 저장하면 이벤트 기록(누가·언제·무엇), 다음 할 일 시각 갱신.
- 업무폰에서 통화 기록상 연결 안 된 전화면 '부재'를 **미리 골라 둔 채** 열려요(SL-Q4).

### 5-4. 업무폰 '영업 콜' (CL-3 앱에 추가, 단계 A7)

- **오늘 할 일:** 담당 리드만, 대기열 순서, 한 줄에 이름·유입 경로·경과 시간·부재 n차·약속 시각.
- **걸기:** 다이얼러에 번호만 넣어 열기(자동 발신·통화 걸기 권한 없음, CL 결정 유지). 웹 '업무폰으로 걸기'는 CL-2 기기 명령으로.
- **통화 뒤:** 통화 종료 방송 → 알림 → **결과 화면(앱 화면, 떠 있는 창 아님)**. 입력 중 내용은 기기에 임시 저장돼 앱이 닫혀도 남아요. 저장 뒤 '다음 리드' 버튼.
- **부재 자동 기록:** 발신 통화가 통화 시간 0초(또는 사무소가 정한 초 이하)면 서버가 부재 n차로 기록하고 다음 시도 시각을 계산해요. 직원이 결과 화면에서 바꿀 수 있어요. 횟수는 서버에서 한 번에 올려 PC·휴대폰이 겹쳐도 틀리지 않아요.
- **걸려 온 전화:** 리드 번호면 '영업 DB · 유입 경로 · 상태 · 다음 할 일' 알림(잠금 화면엔 이름 없이), 받은 뒤 결과 화면.
- **새 리드 알림:** 배정되면 푸시(FCM), 근무 시간 밖이면 다음 근무 시작 때.
- **부재 문자:** 템플릿 골라 앱이 직접 발송(CL-11), 실제 결과 뒤에만 기록.

### 5-5. 이관

- 버튼: '사건 관리로 이관'. 상담 중 상태에서만 기본 노출(다른 상태는 ⋯ 메뉴).
- 확인 창: 사건 유형(회생·파산·미정), 담당 변호사·직원, 이관 메모, 넘어갈 정보 미리보기(상담 확인 10칸·사전 정보·이관 요약).
- 서버 함수 하나로 처리: 같은 사무소 사건·상담 요청에 같은 번호가 있으면 막고 '기존 사건 열기', 사건 생성(사건 유형 값 통일, 금액 원 단위, 유입 경로 → 사건 유입 채널 분류), 소통 기록·녹음은 **복사하지 않고 연락처 연결을 사건으로 옮김**(CL-12), 리드 '이관 완료' + 사건 번호, 실패하면 전부 되돌리고 화면에 오류.
- 이관으로 만든 사건은 **사무소 자체 사건**(출처 '영업 DB')이에요. 마이김변 상담 요청 규칙(진행 중 3명·정리 자료 필수, LD-1)과 플랫폼 통계에서 빼요.

### 5-6. 통계 (영업 DB 안 '통계' 탭)

- **매체별 퍼널:** 리드 → 연결(1번이라도) → 상담 중 → 이관 → 계약(사건 쪽 계약 체결 수, 연결된 사건만).
- **종료 사유 비율:** 연락 불가·단순 문의·대상 아님(세부)·거절·중복. 사용자가 말한 30·20·30% 같은 숫자를 매체별로 확인해 광고를 고르는 근거로 써요.
- **광고비:** 매체·월별 입력(서버 저장) → 리드당 비용·연결당 비용·이관당 비용·계약당 비용.
- **속도:** 들어온 뒤 첫 연락까지 걸린 시간(중앙값), 첫 48시간 안 3회 시도 비율.
- **담당자별:** 처리 건수·연결률·이관 수. 담당자끼리 순위표는 만들지 않아요(사무소가 원하면 켜기).
- 기간 비교, 엑셀 내려받기.

### 5-7. 설정 ('경로/환경 설정' 개편)

지금 탭 5개의 처리: **인입 경로 관리 → 유지·확장**(아래 '유입 경로'), **상태 종류 관리 → 종료 사유·세부 사유 관리로 바꿈**(1차 자유 목록은 리드와 연결돼 있지 않아 삭제), **부재콜 알림 티어 → '부재 재시도'로 바꿈**(지금 값은 아무 데도 쓰이지 않음), **거래처/파트너사 → 삭제**(A-6 결정), **외부 연동(텔레그램) → 삭제**(거래처 전달용). 바꾼 내용은 지금처럼 바로 저장되고(서버로), '설정 저장 및 닫기' 버튼은 실제 동작대로 '닫기'로 이름만 바꿔요.

- **유입 경로:** 이름, 분류(검색 광고·SNS 광고·블로그·소개·DB·기타), 수집 근거, 접수 키(만들기·돌려 쓰기·폐기), 열 맞춤 규칙, 사용 여부, 삭제 시 다른 경로로 옮기기.
- **배정:** 방식(수동 / 순번 / 유입 경로별 담당), 대상 직원, 부재 중 직원 건너뛰기.
- **부재 재시도:** 3-2 규칙 편집, 자동 종료 횟수, 부재 판정 통화 초, 통화·문자 가능 시간.
- **문자 템플릿:** 부재 문자·약속 확인 문자(T-6 문구함과 같은 데이터, 금지 표현 검사).
- **보기 권한:** 상담 직원은 '내 리드만'(기본) / 전체.
- **보관:** 종료 리드 보관 기간(기본 마지막 활동 1년, 더 짧게 가능), 수신 거부 목록.
- **거래처(광고대행사):** 5-8장. '거래처/파트너사' 탭은 **'거래처(광고대행사)' 탭으로 바꿔 유지**해요(10-29 사용자 요청).
- 삭제: 거래처별 수당(수임료 구간 → 수당) 규칙, 텔레그램 방, 1차 상태 자유 목록, 부재 알림 단계(재시도 규칙으로 대체).

### 5-8. 거래처(광고대행사) 위탁 수집 (10-29 사용자 요청)

사무소가 광고대행사와 계약해 리드 수집을 맡기는 경우가 있어요. 이때 거래처는 **리드를 보내 주는 쪽**이에요. LeadMaster의 거래처(리드를 받아 가고 수당을 주는 법률사무소)와 방향이 반대라서, 수당 계산은 계속 만들지 않고(A-6) 거래처 관리를 새로 짜요.

**① 거래처 정보 (설정 › 거래처(광고대행사))**
- 상호, 사업자등록번호, 담당자 이름·연락처·이메일, 계약 기간(시작·끝), 상태(계약 중·종료).
- 맡긴 매체·유입 경로: 거래처 하나에 유입 경로 여러 개(예: A대행사 = 메타·네이버 파워링크). 유입 경로에 거래처를 붙이면 그 경로로 들어온 리드는 모두 그 거래처 리드가 돼요.
- **계약 방식 (SL-Q8 결정):** 월 정액 대행료 / 매체비 + 대행 수수료(%) / 리드 건당 단가 / 혼합(이 세 가지 조합). 금액·단가는 비용 계산에만 써요. **수임·계약·입금 같은 성과에 연동된 지급은 변호사법 위반이라 선택지에 넣지 않아요**(10-29 사용자 결정). 지급 조건 칸에 성과 연동 내용을 적는 메모 칸도 두지 않아요.
- **개인정보 수집 구조:** ⓐ 위탁 수집(대행사 랜딩·폼에 **사무소 이름으로** 수집, 대행사 = 수탁자) / ⓑ 제3자 제공(대행사가 **자기 이름으로** 수집한 뒤 사무소에 제공). 고른 구조에 맞는 서류를 올려요: ⓐ 개인정보 처리 위탁 계약서(또는 계약서의 위탁 조항), ⓑ 대행사 동의 문구 원본(제공받는 자에 사무소 이름이 있는지 확인 칸). 동의 문구 버전·적용일을 기록해요.
- **불량 리드 교체 규칙:** 계약서 기준 교체 기간(예: 접수 후 7일)과 교체 사유(결번·중복·본인 아님·허위 정보·수신 거부 등).
- 계약서·세금계산서 파일 보관(사무소 비공개 저장소).

**② 리드 받기 (대행사는 '보내기만')**
- 거래처마다 **전용 접수 주소·접수 키**(SL-6)를 발급해요. 대행사 랜딩 폼·구글 시트·자동화 도구가 이 주소로 보내면, 리드에 거래처·유입 경로·대행사 쪽 리드 번호·동의 문구 버전이 함께 저장돼요.
- 대행사가 엑셀로 넘기면 사무소가 '엑셀 대량 등록'에서 거래처를 골라 올려요(열 맞춤을 거래처별로 저장).
- **대행사 계정·로그인은 주지 않아요.** 대행사는 사무소 리드 목록·통화 기록을 볼 수 없어요. 접수 주소는 받기만 하고, 응답은 '받음/중복/거부'와 마이김변 접수 번호만 돌려줘요.
- 계약이 끝나면 접수 키를 자동으로 막아요(끝난 뒤 들어온 건은 '계약 종료' 기록만).

**③ 불량 리드 교체 요청**
- 교체 기간 안에 종료 사유가 결번·중복·본인 아님·허위 정보·수신 거부로 끝난 리드를 '교체 요청 목록'에 자동으로 모아요.
- 사무소가 확인해 '교체 요청 보내기' → **대행사 쪽 리드 번호·접수 일시·사유만** 담은 엑셀(이름·전화번호 없음)을 내려받아 대행사에 보내요. 대행사 리드 번호가 없으면 전화번호 뒤 4자리만.
- 결과(교체됨·거절·환불)를 기록하고, 교체로 다시 들어온 리드는 '교체분'으로 표시해 비용에서 빼요.

**④ 비용·정산**
- 월마다 거래처별 청구 금액 입력(매체비·대행 수수료·건당 단가 × 유효 리드 수 − 교체분), 세금계산서 파일 첨부, 지급일. 건당 단가 계약이면 시스템이 그 달 유효 리드 수와 교체분을 세어 '예상 청구액'을 보여 줘요(대행사 청구서와 맞춰 보기용).
- 이 금액이 통계(SL-11)의 광고비로 들어가요. 거래처가 없는 자체 광고는 지금처럼 유입 경로별로 직접 입력해요.

**⑤ 거래처별 성과**
- 통계 탭에 '거래처별' 보기: 리드 수, 유효 리드(결번·중복·본인 아님 제외) 비율, 연결률, 단순 문의·대상 아님 비율, 이관률, 계약 수, 리드당·유효 리드당·이관당·계약당 비용, 첫 연락까지 시간(사무소 쪽 속도).
- **거래처 품질 보고서:** 월 단위, 개인정보 없이 숫자만(종료 사유 분포·교체 요청 수) 내려받아 대행사와 협의할 때 써요.

**⑥ 법·광고 규정 안내 (막지 않음, 한 번 안내)**
- 계약 방식에서 '리드 건당 단가'를 고르면 한 번 안내해요: "[운영자 판단] 리드 건당으로 대행사에 돈을 주는 계약은 변호사법 제34조(소개·알선 대가) 문제가 될 수 있어요. 광고 대행 용역(정액·매체비 기준)으로 계약하는 방식이 덜 위험해요." 사무소가 정하고, 고른 기록은 남겨요. **성과 연동 지급(수임·계약·입금 결과에 따른 지급)은 선택지 자체가 없어요**(SL-Q8 결정).
- 수임·계약 결과로 대행사에 지급하는 금액을 **계산해 주는 기능은 만들지 않아요**(10-24 수당 삭제 결정 유지). 기록만 할 수 있어요.
- 개인정보: 위탁이면 사무소 처리방침에 수탁자(대행사)를 적어야 해요. 마이김변은 처리방침 예시 문구에 '광고 대행사(수탁자)' 칸을 넣고, 거래처를 등록하면 "처리방침에 이 업체를 넣었는지 확인해 주세요" 안내를 띄워요. 제3자 제공이면 동의 문구에 사무소 이름이 없을 때 경고해요.

## 7. 개인정보·법 점검

- **사무소 = 처리자, 마이김변 = 수탁자.** 처리방침·약관(A-3) 수탁 업무에 '영업 리드 관리'를 넣고, 통합관리자는 리드를 보지 못해요(RLS, 사무소 단위).
- **동의:** 랜딩 폼 동의 문구 예시(수집 항목·목적·보관 기간·상담 연락)를 제공하고 동의 문구 버전·시각을 리드에 저장해요. 엑셀로 들어온 리드는 수집 근거 칸으로 대신해요.
- **광고성 연락:** 문의에 대한 답 전화·문자는 문의자가 요청한 연락이에요. 종료된 리드에 다시 광고 문자를 보내는 기능은 만들지 않아요. 수신 거부는 즉시 목록에 넣고 다시 받지 않아요.
- **변호사 광고 규정:** 부재 문자·약속 문자에 '무료상담'·'전담'·'진단'·'100%' 같은 표현이 들어가면 M-9 검사로 경고해요.
- **보관:** 종료 리드는 마지막 활동 1년 뒤 자동 파기(L7, 사무소가 더 짧게), 파기 기록 보관, 이관된 리드는 사건 보관 기준을 따라요.
- **구매 DB:** 4장 '[운영자 판단]' 안내(SL-Q5).

## 10. 완료 기준

- 대표·직원 두 계정, PC·업무폰 두 기기에서 같은 리드·상태·메모가 보여요. 브라우저를 바꿔도 그대로예요. 다른 사무소·통합관리자는 볼 수 없어요(RLS 시험).
- 랜딩 폼·구글 광고 리드 양식 시험 접수·엑셀 100줄·붙여넣기로 리드가 들어오고, 같은 번호는 재문의로 묶이고, 오류 줄은 줄 번호·사유로 보여요. 수신 거부 번호는 들어오지 않아요.
- 업무폰에서 리드에 걸었다가 받지 않으면 부재 n차와 다음 시도 시각이 자동으로 바뀌고, 5회 부재면 '연락 불가'로 끝나요. 연결된 통화 뒤에는 결과 화면이 뜨고, 앱을 닫았다 열어도 쓰던 내용이 남아 있어요.
- 오늘 할 일 대기열이 신규 → 약속 시각 → 재시도 시각 순으로 보이고, 상담 직원은 자기 리드만 봐요.
- 이관하면 사건 관리에 사건이 1개만 생기고(두 번 눌러도), 금액이 원 단위로 맞고, 통화·문자 기록이 사건 화면에 이어져 보이고, 실패하면 리드가 그대로 남아요.
- 통계 탭에서 매체별 리드 → 연결 → 상담 → 이관 → 계약 수와 종료 사유 비율, 광고비 대비 비용이 보여요.
- 코드 검색에서 `calculateCommission`·`partnerId`(리드)·`telegram`(영업 설정)·`uploadRecordingToDrive`·`legal_sales_leads` localStorage 단독 저장·'무료상담'(문자 템플릿)이 0건이에요.
- (거래처) 거래처를 등록하고 접수 키로 시험 리드를 보내면 리드에 거래처·대행사 리드 번호·동의 문구 버전이 붙고, 계약 종료일 뒤에는 접수가 막혀요. 대행사 쪽에서는 리드 목록을 볼 방법이 없어요.
- (거래처) 7일 안에 결번으로 끝낸 리드가 교체 요청 목록에 모이고, 내려받은 요청 파일에 이름·전화번호가 없어요. 교체분은 비용 계산에서 빠져요.
- (거래처) 통계 '거래처별' 보기에서 유효 리드 비율·이관률·리드당/이관당/계약당 비용이 보이고, 건당 단가 계약은 예상 청구액이 대행사 청구서와 비교돼요.
