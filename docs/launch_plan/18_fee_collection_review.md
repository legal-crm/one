## 0. 한눈에 보는 결론

**지금 화면의 숫자는 실제 장부가 아니에요.**

1. **보이는 9건이 전부 시험 데이터예요.** 운영에도 들어가는 시험 사건 9건(`STAGE_TEST_REQUEST_IDS`)에, '개발 빌드에서만'이라고 적혀 있지만 실제로는 확인 없이 붙는 시연 수임료(`PREDEFINED_AMJONE_PROFILES`)가 채워져요. '당월 목표 80만·연체 2건·약정 총액 1,220만'과 사이드바 '수임료 수납 2'가 모두 여기서 나와요.
2. **서버를 읽지 않아요.** 이 탭은 그 브라우저 탭의 임시 사본(sessionStorage)만 읽어요. 새 탭·다른 기기·직원 PC에서는 시연값이나 0이 보여요.
3. **저장하다 진짜 기록을 덮어쓸 수 있어요.** 수임료 일정은 사건 행(`crm_clients`) 한 칸(jsonb)에 통째로 들어가고, 저장은 행 전체 덮어쓰기예요. 임시 사본이 없는 탭에서 '입금 확인'을 누르면 기본값·시연값으로 만든 행이 서버의 실제 행을 덮어요. 서버 저장이 실패해도 "입금 처리 완료"가 떠요.
4. **일정 원본이 세 곳이에요.** 계약 위저드, 2단계 수임료 계산기, 이 탭의 '분납 일정 등록'이 각자 일정을 만들어요(회차 번호 0부터/1부터, 원/만원 섞임). 계약이 다시 저장되면 이 탭에서 만든 일정이 계약 일정으로 바뀌고, 회차 번호로 짝을 맞춰 납부 기록이 엉뚱한 회차에 붙을 수 있어요.
5. **'입금 확인'은 한 번 누르면 끝이에요.** 금액·입금일·방법·입금자를 묻지 않고 '오늘, 회차 전액, 계좌이체'로 기록해요. 일부 입금·초과 입금·취소·누가 확인했는지·증빙이 없어요. 일정이 없는 사건의 '입금 확인'은 눌러도 "납부 대기 회차 없음"만 떠요.
6. **상태가 서로 모순돼요.** 일정이 없으면 '일정 미등록'인데 남은 회차 칸은 '완납', 수납이 끝난 사건은 '완납'이 아니라 '일정 미등록', '진행 9건'인데 '진행 중 0', 연체 금액은 지난 회차 합이 아니라 다음 회차 하나, 진행 막대 3개는 고정값(100%·60%·100%)이에요.
7. **안내가 자동으로 나가지 않아요.** 'D-3·당일·연체' 규칙은 그 브라우저에 저장만 되고 예약 발송기가 없어요. 수임료 알림톡 템플릿 4종(ATS_12~15)은 아직 심사 '대기'예요. 문구에 '독촉 고지', "원활한 사건 진행을 위해 기한 내 입금"(납부와 사건 진행을 엮는 표현), 없는 기능('마이페이지 납부 확인증'), '영수증'이 있어요.
8. **의뢰인은 보통 아무것도 못 봐요.** 마이페이지 수임료 카드는 의뢰인 기기 사본만 읽고, 서버 규칙(011)은 의뢰인 키(`req-…`)가 맞지 않아 막혀요. 입금 계좌는 사무소 브라우저에만 있어 의뢰인 화면에는 안 나와요. 의뢰인이 "입금했어요"를 알리거나 날짜 조정을 요청할 방법이 없어요.
9. **권한·내보내기 구멍:** 탭 본문은 권한 확인 없이 열리고, 내 사건이 아니라 **모든 상담 요청**을 넘겨받아요. 입금 처리·연기·일정 교체·CSV에 역할 제한이 없어요. CSV에는 실명·전화·사건번호가 그대로, 상태는 영어(`overdue`)로 나가고 엑셀 수식 주입 방지가 없어요.
10. **빠진 기능:** 실비(인지대·송달료·예납금)와 변호사 보수 구분, VAT, 계약 해지·환불 정산, 은행 입금 내역 대조, 현금영수증 발급 여부 기록, 사건 원장(입금·변경·안내 기록을 한눈에).

**개편 방향:** 수임료를 사건 행의 한 칸에서 꺼내 **서버 장부**(약정·회차·입금·변경·환불)로 만들어요. 약정의 원본은 계약서 하나로 두고, 입금은 '입금 기록'을 남긴 뒤 회차에 나눠 붙이는 방식으로 바꿔요. 의뢰인은 서버 기준으로 일정·계좌를 보고 "입금했어요"를 알릴 수 있게 하고, 안내는 G-1 스케줄러로 부드러운 문구만 보내요.

## 2. 데이터·연결 현황

- **저장 위치:** `crm_clients.total_fee`·`total_paid`·`fee_schedule`(jsonb) + 같은 내용이 `extension_data`에 한 번 더 + 브라우저 사본. 계약서 쪽(`electronic_contracts.fee_schedule`)은 처음 만든 일정 그대로 남고 납부 기록은 안 들어가요. 전용 테이블 없음. `fee_notification_settings` 테이블은 있지만 안 써요.
- **회차 구조(`FeeInstallment`):** 금액·단위(원/만원)·예정일·입금일·상태(대기/납부/연체)·항목 종류·연기 정보. **받은 금액(일부 입금)·입금자·증빙·확인자·취소·환불** 칸이 없어요. '연체' 상태는 어디서도 저장하지 않아(날짜로만 계산) '연체 2회 이상 = 집중 관리' 규칙은 시연 데이터에서만 동작해요.
- **단위:** 1만 미만이면 만원으로 보는 추측 규칙(`feeUnits.ts`)과 '나눠떨어지면 만원으로 저장'이 섞여 있어요. 대시보드 '연체 수납' 카드는 단위 변환 없이 더해요.
- **숫자 범위가 화면마다 달라요:** 사이드바 배지 = 내 사건의 연체·오늘 회차 수 / 탭 = 모든 상담 요청의 연체 사건 수(오늘 제외) / 대시보드 = 어제까지 미납 금액(단위 섞임).
- **의뢰인 화면:** `FeePaymentCard`는 서버를 안 읽고 기기 사본 → 계약서 사본 순. 원격 서명 화면에서만 계약서의 납부 일정·계좌가 보여요. 수임료 안내를 보내면 '의뢰인 알림'이 **변호사 브라우저**에 쌓여요(`clientNotificationService` 기기 저장). 회생동행의 '납부 기록'은 법원 **변제금** 회차라 수임료와 별개예요.
- **발송:** 수동 발송은 실제 `/api/alimtok`(팝빌)로 가고, 팝빌 미설정·오류는 실패로 보여요(가짜 성공 없음). 발송 기록은 `alimtok_logs` 서버 + 기기. 입금 계좌가 비면 안내를 막아요(좋음). 회차의 `lastNotifiedAt` 칸은 채우지 않아요.

## 3. 개편 설계

### 3-1. 서버 장부 (FE-2)

| 테이블 | 내용 |
|:---|:---|
| `fee_agreements` | 사건별 약정(버전): 변호사 보수 총액(원), VAT 포함/별도, 실비 예상액(인지대·송달료·예납금), 성공보수 조건(글), 출처(전자계약 id / 종이 계약 / 직접 등록), 현재 버전 여부, 바꾼 사람·사유 |

| `fee_refunds` | 해지·환불 정산: 받은 합계, 쓴 실비, 환불액, 근거 메모, 환불일·계좌, 처리자 |
| `fee_office_settings` | 사무소 설정: 입금 계좌(보수용·실비용), 기본 납부일, 주말·공휴일 처리, 안내 규칙(3-6), 발송 방법(KT-2), 입금 시 확인 안내 여부 |

- **규칙(RLS):** 사무소(RB-1 `has_office_permission`) / 의뢰인 본인은 자기 사건 약정·회차·입금 기록 읽기와 '입금했어요'·'일정 조정 요청' 쓰기만(의뢰인 키 연결은 H-14 방식, `req-…` 문제 해결) / 통합관리자 제외(제로날리지).
- **옮기기:** 기존 `crm_clients.fee_schedule`을 한 번만(멱등) 새 테이블로 옮기고, 단위를 원으로 고정, '납부'였던 회차는 입금 기록 1건으로 만들어요(출처 '이전 기록'). 시험 사건·시연 데이터는 옮기지 않아요(FE-1). 이후 `crm_clients`의 수임료 칸은 읽기 전용으로 두다가 삭제.
- 금액은 **정수 원**만, 계산은 서버 함수 하나(`fee_recalculate(사건)`)가 해요.

### 3-2. 약정 원본은 하나 (FE-3, FE-Q1)

- **계약서가 원본이에요.** 전자계약 체결(또는 종이·우편 계약 체결 기록) 때 서버 함수 `create_fee_agreement_from_contract`가 약정·회차를 만들어요. 계약 위저드·2단계 계산기·이 탭의 등록 창은 **공통 일정 생성기 하나**(`buildFeeSchedule`: 원 단위, 회차 1부터, 말일 보정, 마지막 회차가 나머지 흡수, 주말·공휴일 '그대로/다음 영업일' 선택)를 써요.
- **계약 없이 받는 사건**(외부·종이 계약 기록 전)은 이 탭에서 직접 등록하되 같은 테이블에 '직접 등록'으로 남겨요.
- **약정을 바꾸면 새 버전:** 이미 받은 입금은 그대로 두고, 새 회차에 다시 배분한 결과를 미리 보여 준 뒤 저장해요. "기존 납부 기록이 지워집니다" 같은 교체 저장은 없애요.
- 계약 다시 저장 → CRM 일정 덮어쓰기(`buildContractSyncPatch`의 회차 번호 짝 맞추기)는 없애고, 계약이 바뀌면 '약정 변경 제안'으로 수임료 화면에 알려요(사람이 확인).

### 3-3. 입금 확인과 사건 원장 (FE-4)

- **입금 확인 창:** 금액(기본 = 그 회차 남은 금액), 입금일(기본 오늘, 지난 날짜 가능), 방법, 입금자명, 받은 계좌, 증빙(통장 캡처 선택), 메모. 저장 전 "○회차에 ○원, 남은 금액 ○원" 미리보기.
  - 일부 입금 → 회차 '일부', 초과 입금 → 다음 회차로 넘길지 묻기(선납).
  - 잘못 누른 입금은 **취소(사유 필수)**, 기록은 남아요.
  - 현금·계좌이체 10만 원 이상이면 안내: "변호사업은 현금영수증 의무발행업종이에요. 발급은 사무소가 홈택스·단말기로 해요." + 발급 여부·승인번호 기록 칸(발행 기능은 만들지 않음, A-4). 세부 요건은 사무소 세무 담당 확인.
  - 저장 실패하면 실패로 보여 줘요(성공 안내 없음). 저장 뒤 '입금 확인 안내 보내기'는 묻고 보내요(지금처럼 바로 창 띄우기 대신 체크 칸).
- **사건 원장(지금 '수납 내역'):** 이 탭 안에서 오른쪽 서랍으로 열어요. 약정(버전), 회차표, 입금 기록, 일정 변경, 안내 발송(성공·실패), 환불을 시간순으로. 2단계 '수임료·분납' 화면도 같은 원장을 보여 줘요.
- **누가 했는지:** 모든 입금·취소·변경에 사람·시각을 남기고 활동 기록(RB-5 `office_audit_logs`)에도 넣어요.

### 3-4. 상태와 숫자 (FE-5)

| 사건 상태 | 조건 |
|:---|:---|
| 일정 없음 | 약정이 없거나 회차가 없음 (약정 0원이면 '수임료 없음'으로 따로) |
| 진행 중 | 남은 금액이 있고 연체 없음 |
| 이번 주 / 오늘 | 7일 안 / 오늘 예정 회차 있음 |
| 연체 | 예정일 지난 미납(일부 포함) 회차 있음 — 일수는 **가장 오래된 미납 회차** 기준 |
| 완납 | 남은 금액 0 (일정이 있든 없든, 받은 기록 기준) |
| 정산 종료 | 해지·환불로 끝남 |

- **숫자 카드:** ① 이번 달 받을 돈(예정 합계)·받은 돈(이번 달 **입금 기록** 합계) ② 연체: 지난 미납 **합계**·사건 수 ③ '확인 필요'(일정 조정 2회 이상 또는 연체 회차 2개 이상) ④ 남은 약정 잔액·진행 사건 수. 실비는 보수와 나눠 보여 주거나 필터로. 고정 막대는 지우고 실제 비율만.
- **같은 정의를 모든 곳에:** 사이드바 배지(HM-4) = 오늘 납부 + 연체 사건 수(내 범위), 대시보드 '연체 수납' 카드·업무함(HM-3)도 같은 함수. 업무함 항목: 오늘 입금 확인, 연체 n일, 의뢰인 '입금했어요' 확인 대기, 일정 조정 요청, 약속일.
- 문구: '즉시 독촉 안내 필요' → '연체 안내 확인', '집중 관리' → '확인 필요', 'D+24 (24일 연체)' → '24일 지남'.

### 3-5. 일정 조정 (FE-6)

- '납부일 연기' → **'일정 조정'**: 한 회차 미루기 / 남은 금액 다시 나누기(개월 수·납부일) 두 가지. 사유 필수(미리 채우지 않음), 요청 출처(전화·채팅·의뢰인 요청), 의뢰인에게 바뀐 일정 안내(선택).
- 의뢰인이 마이페이지에서 보낸 '일정 조정 요청'은 업무함으로 와서 승인·거절(사유)만 하면 반영돼요.
- 계약 특약에 분납 유예 조항(예: 'grace' 2회 유예)이 있으면 조정 창에 참고로 보여 줘요(판단은 사무소).

### 3-6. 안내 발송 (FE-7, FE-Q4)

- **예약 발송은 G-1 스케줄러:** 사무소 설정(서버)의 규칙대로 매일 대상 회차를 찾아 보내고, 같은 회차·같은 종류는 한 번만(발송 기록). 발송 방법은 KT-2 설정(알림톡/담당자 카톡/둘 다), 근무 시간 3시간 미처리 시 알림톡 대체(KT-Q2).
- **기본 규칙(추천):** D-3 사전 안내, 당일 안내, 지난 다음 날 1차 안내, 7일 뒤 2차 안내(일정 조율 제안). **회차당 연체 안내 최대 2번**, 그 뒤는 사람 판단. 발송 시간 09~20시(21~8시 금지 KT-2보다 좁게). '2차 연체 독촉 고지' 규칙은 삭제.
- **템플릿 문구 정정(C-5 심사 전):**

  | 지금 | 바꿀 것 |
  |:---|:---|
  | "원활한 사건 진행을 위해 기한 내 입금 부탁드립니다" | "납부 일정을 안내드려요. 일정 조정이 필요하시면 사무소로 연락 주세요" |
  | "마이페이지에서 납부 확인증을 조회하실 수 있습니다" | 실제 기능 이름('납부 내역', FE-8)으로 |
  | ATS_15 '수임료 정상 입금 확인 영수증', 버튼 '입금 영수증 확인' | '수임료 입금 확인 안내', 버튼 '납부 내역 보기' (세법상 영수증 아님) |
  | ATS_12 버튼 '계좌 및 영수증 확인' | '납부 일정·계좌 보기' |
  | '⚠️' 등 이모지, '미납 금액' 강조 | 이모지 없음, '남은 금액' |
  | 변수 '법무법인' 기본값 '법무법인' | 사무소 이름 없으면 발송 막기 |

- 연체 안내에 '법적 조치'·'추심'·'계약 해지' 같은 압박 표현은 넣지 않아요(문구함 금지 표현 검사, M-9 사전).
- 발송 결과를 회차에 남기고(`lastNotifiedAt` 대신 발송 기록 연결), 의뢰인 인앱 알림은 서버에 쌓아 의뢰인 마이페이지에서 보이게 해요.

### 3-7. 의뢰인 마이페이지 (FE-8, FE-Q2·Q5)

- **수임료 카드 서버 기준:** 약정 총액·받은 금액·남은 금액·회차표(완료·예정·지남), 사무소 입금 계좌(보수용·실비용 구분), 계좌 복사. 사무소 계좌가 바뀌면 "계좌가 바뀌었어요" 표시(사칭 계좌 주의 안내는 유지).
- **"입금했어요" 알리기:** 입금일·금액·입금자명(선택 사진) → 사무소 업무함 '입금 확인 대기'. 확정은 사무소가 입금 기록으로 해요(의뢰인 알림만으로 '완료' 표시 안 함, 그동안 '확인 중').
- **일정 조정 요청:** 원하는 날짜·사유 → 사무소 승인 후 반영.
- **납부 내역(PDF):** 사무소 이름으로 회차·입금일·금액 목록. 맨 위에 "세법상 영수증·현금영수증이 아니에요"를 적어요.
- 회생동행의 **변제금**(법원 변제계획) 화면과 이름·색을 나눠 헷갈리지 않게: '수임료(사무소에 내는 돈)' / '변제금(채권자에게 가는 돈)'.

### 3-8. 입금 대조 (FE-9, FE-Q3)

- **출시 전 — 거래내역 파일 대조:** 사무소가 인터넷뱅킹에서 내려받은 입금 내역(엑셀·CSV)을 올리면, 입금자명·금액·날짜로 회차 후보를 제안하고 사람이 하나씩 확인해요. 파일 원본은 저장하지 않고(확인한 줄만 입금 기록으로), 같은 거래는 두 번 넣지 않게 거래 지문을 남겨요. 비용 없음.
- **출시 후 — 계좌 자동 조회(사무소 선택):** 이미 쓰는 팝빌 SDK에 계좌조회(`EasyFinBankService`: 계좌 등록·기간 조회 작업·거래 검색)가 있어요. 사무소 계좌를 등록하면 매일 입금 내역을 가져와 같은 후보 제안으로 보여 줘요. 팝빌 연동회원(사무소 사업자번호)·계좌별 정액 요금이 필요해 요금·부담 주체를 확인한 뒤 결정해요.
- 가상계좌·자동이체(CMS)·카드 결제는 PG 계약·수수료가 사무소 몫이라 출시 후 검토.

### 3-9. 해지·환불 정산 (FE-10)

- 사건 종료(계약 해지·사임·의뢰인 철회) 때 '수임료 정산' 창: 받은 합계, 쓴 실비(인지대·송달료·예납금 등 입력), 계약 특약 원문 참고(예: '접수 전 철회 시 실비 외 전액 환불'), **환불액은 변호사가 입력**, 환불일·계좌, 남은 회차 '취소'. 결과는 원장·활동 기록에.
- 화면이 환불액을 자동으로 정하지 않아요(계약·사정마다 달라 변호사 판단). 2단계 특약 목록의 '기각 시 50% 환불'은 선택 항목으로만 남아 있어 기본값이 아님을 유지해요(Q25).

### 3-10. 확인이 필요한 법적 쟁점 (FE-Q7, R6에 추가)

- 개인회생 **개시결정 이후 남은 수임료 분납**을 받는 것이 문제 되는지(개인회생채권으로 보는지)와, 그 분납이 수입지출목록·변제계획 수행 가능성 판단에 어떻게 반영되는지는 법원·실무에 따라 달라 이번 조사로 확정하지 못했어요. 외부 자문(R6) 확인 항목에 넣고, 화면은 회차가 '신청일·개시결정일 이후'면 정보 배지만 보여 줘요(판단·차단 없음).

### 3-11. 권한·내보내기 (FE-11)

| 동작 | 대표 | 담당 변호사 | 경리 | 사무장·상담 직원 |
|:---|:---:|:---:|:---:|:---:|
| 보기 | 전체 | 담당 사건 | 전체 | 담당 사건(설정) |

| CSV 내보내기 | ○ | × | ○ | × |

### 3-12. 화면 품질 (FE-12)

- 로딩 스켈레톤(지금 `animate-spin`), 서버 오류 카드(다시 시도), 빈 상태 = "아직 수임료 일정이 없어요" + '계약에서 불러오기'·'직접 등록'.
- 이모지 상태 → 아이콘 + 글자 배지, 한글 표 머리 대문자 변환 삭제, 잘못된 클래스(`py-0.2`)·임의 값(`text-[11px]`) 정리, 브랜드 색 인라인(`#1E3A5F`) → 토큰, 버튼 44px·한 줄, 연기 창은 모달 포털·Esc·포커스, 쓰지 않는 체크박스 상태 삭제.

## 6. 완료 기준

- 운영에서 시험 사건·시연 수임료가 0건이고, 새 탭·다른 기기·직원 PC에서 같은 숫자가 보여요. 사이드바 배지·대시보드·탭 카드의 연체 숫자가 같아요.
- 전자계약을 체결하면 수임료 탭에 약정·회차가 바로 생기고, 계약을 다시 저장해도 받은 기록이 그대로예요. 약정을 바꾸면 이전 버전과 바뀐 내용이 원장에 남아요.
- 입금 확인에서 일부 입금(예: 40만 원 회차에 25만 원)·초과 입금·취소가 되고, 누가 언제 했는지 남아요. 저장이 실패하면 실패로 보여요.
- 일정이 없는 사건에 '완납'이 뜨지 않고, 수납이 끝난 사건은 일정 유무와 상관없이 '완납'이에요. 연체 금액이 지난 미납 합계와 같아요.
- 의뢰인이 다른 기기에서 로그인해도 수임료 카드에 일정·계좌가 보이고, '입금했어요'가 사무소 업무함에 와요. 다른 사건의 수임료는 못 봐요. 통합관리자는 수임료 장부를 못 봐요.
- 예약 안내가 규칙대로 한 번씩만 나가고(팝빌 테스트 모드 확인 후 운영), 21~8시·회차당 3번째 연체 안내는 나가지 않아요. 템플릿에 '독촉'·'영수증'·'원활한 사건 진행을 위해'·'납부 확인증'이 0건이에요.
- 거래내역 파일을 올리면 후보가 제안되고, 같은 파일을 다시 올려도 입금이 두 번 생기지 않아요.
- 경리 계정은 입금 확인·CSV가 되고 약정 변경·환불은 안 돼요. CSV에 영어 상태·수식 칸이 없고 내보낸 기록이 남아요.
