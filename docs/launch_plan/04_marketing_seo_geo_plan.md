## 2. 전략 원칙

1. **자체 도메인이 중심(Hub), SNS는 확산(Spoke).** 모든 콘텐츠의 원본은 mykim.kr 칼럼으로 남기고, 각 채널은 요약·변형본 + 원본 링크(UTM). 검색엔진과 AI가 인용하는 건 결국 자체 도메인 문서예요.
2. **두 종류의 주제를 섞어요.** ① 뉴스 반응형(지금 엔진, 하루 1건) ② 검색 수요형 상시 주제(키워드 은행, 주 3~5건). 상시 주제가 장기 유입을 만들어요.
3. **AI 답변에 인용되는 문서 구조 (GEO).** 질문형 제목, 첫 3문장 바로 답(Answer-First), 표·단계·FAQ, 근거(법령·법원 기준·공식 통계) 링크, 작성일·수정일, 운영 주체·검토자 명시, 구조화 데이터.
4. **법적 원칙은 생성 단계부터.** 결과 보장·수치 단정·전문 표시·알선·매칭 표현은 프롬프트·검사기·사이트 문구 검사 세 곳에서 같은 규칙으로 막아요.
5. **측정 → 학습 루프.** 성과가 다음 주제·채널·시간대·제목을 정해요. 측정이 없으면 자동화는 '많이 만드는 것'에 그쳐요.
6. **사람은 예외만.** 검사 통과분은 자동으로 흐르고, 표시된 항목만 운영자가 봐요(자동화 수준은 설정으로 조절).

## 4. 자체 사이트 콘텐츠 엔진 (SEO·GEO의 중심) — M-3

### 4-1. 칼럼 자동 발행
- 오토파일럿의 블로그 원고를 **사이트 칼럼 원본**으로 저장(`marketing_articles` 신규: 슬러그, 제목, 요약, 본문 블록, FAQ, 표, 이미지, 카테고리, 키워드, 작성일·수정일, 상태).
- 승인되면 Vercel Deploy Hook으로 재빌드 → `seo-build.mjs`가 DB의 발행 칼럼을 읽어 `public/articles/{slug}.html` 정적 페이지 생성 → sitemap·RSS·llms.txt 자동 포함 → IndexNow 전송.
- 네이버 블로그판은 같은 주제의 **다른 글**(구성·도입부·예시를 바꾼 변형)로 만들어 중복 문서 문제를 피하고, 하단에 원문 링크.
- 페이지 구성(GEO 템플릿): 질문형 제목 → 3문장 요약 박스 → 본문(H2 4~5개) → 비교 표 → 단계 목록 → FAQ 3~5 → 근거·출처 → 관련 가이드·계산기 링크 → 고지문. 구조화 데이터 `Article` + `FAQPage` + `BreadcrumbList` + `Organization`, 작성일·수정일.

## 6. GEO (AI 검색 최적화) — M-5

### 6-1. 대상 AI 검색
- 구글 AI 개요·AI 모드, 네이버 AI 브리핑(검색 결과를 요약하고 관련 콘텐츠를 연결), ChatGPT 검색·Copilot(빙 색인 기반), Perplexity, Gemini

### 6-2. 문서 측면 (모든 정적 페이지·칼럼에 적용)
- 질문형 제목·소제목, 첫머리 3문장 답, 표·단계·숫자는 출처와 함께
- 운영 주체·작성일·수정일 명시, **법률 검토자 표시**(실제 검토한 변호사가 있을 때만 `reviewedBy`) (MK-Q3)
- 구조화 데이터: `Article`, `FAQPage`, `BreadcrumbList`, `Organization`(sameAs: 관제센터에서 '운영 중'으로 표시한 채널만 빌드 때 자동 반영, 15-1), 계산기 페이지는 `WebApplication`
- `llms.txt` 사실 오류 정정 + **빌드 시 자동 생성**(가이드·칼럼·계산기·법원별 페이지 목록), `llms-full.txt`(주요 문서 본문 요약) 추가
- `robots.txt`의 AI 크롤러 허용 유지
- 회사 정보·연락처·설립 시기를 모든 곳(사이트·llms.txt·SNS 프로필·보도자료)에서 똑같이

### 6-3. 외부 출처 측면
- AI 답변은 자체 사이트 외 제3자 출처도 많이 인용해요 → 네이버 블로그(네이버 AI 브리핑 주요 출처), 유튜브 설명란, 보도자료(F-3), 공적 기관 자료 인용 문서
- 법률 Q&A 사이트에 플랫폼 계정으로 법률 답변을 다는 방식은 하지 않아요(비변호사 법률상담 소지)

### 6-4. AI 인용 자동 점검 (측정)
- **목표 질문 30~50개** 관리(지금 5개 → 확장): "개인회생 변제금 계산 방법", "가족 모르게 개인회생", "수원회생법원 개인회생 기간" 등, 질문마다 목표 페이지 지정
- **주 1회 자동 점검:** Gemini(구글 검색 근거 모드, 답변 출처 목록 반환)로 각 질문을 묻고 mykim.kr 인용 여부·순위·함께 인용된 출처를 기록. (선택) Perplexity API 추가
- 결과: 질문별 인용률 추이, 인용 안 되는 질문 → 해당 페이지 보강 과제 자동 생성
- 네이버 AI 브리핑·Copilot은 공식 API가 없어 월 1회 수동 표본 점검
