## 0. 한눈에 보는 결론

1. **변제금 결과가 아직 의뢰인에게 보여요.** 결과 리포트(`RehabResultReport`)는 관리자 설정 기본값이 '끔'이라 보통 안 열리지만, **대화창 마지막 말풍선이 "예상 감면율은 약 X%입니다"라고 늘 보여 주고**, 옆 패널은 "약 3분 안에 예상 변제금을 계산해 드립니다", 인사말은 "공개된 기준으로 계산한 참고용 추정치"라고 해요. 관리자가 설정을 켜면 월 변제금·감면율 도넛·'신청 가능성 있음'·제도별 적합도 점수·'AI 통계 인사이트'·'추천 변제기간'·'전담 변호사'가 모두 다시 나와요.
2. **질문은 꽤 촘촘하지만 중요한 몇 가지가 빠졌거나 버려져요.** 채권자 수, 연체 시점, 최근 대출 금액·시점, 직장 근속·4대보험, 배우자 소득(자녀 없는 기혼자), 부모 외 부양가족, 사별 선택지가 없어요. **과거 회생·파산 이력은 물어보고 저장하지 않아** 변호사 화면에 늘 '이력 없음'으로 가요. 위험 요인(최근 대출·투자·도박)은 하나만 고를 수 있어요. 파산 쪽 질문(지급불능 시점, 재산 처분 등)은 없어요.
3. **답변 처리에 빈틈이 있어요.** 금액·숫자 입력에 범위 확인이 없어 음수·잘못된 값이 그대로 들어가고, 출생연도를 잘못 넣으면 나이가 빈 채로 넘어가요. **무직·수급자는 월 소득을 200만 원으로 가정해 저장**하고(옆 패널에는 '소득 없음 / 200만 원'이 함께 보임), 임대차 명의가 가족·회사면 답을 '무상거주'로 바꾸고 보증금을 0으로 지워요. '모름'·'잘 모르겠어요' 선택지가 금액 질문에 없어요. 마지막에 전체 답변을 한 화면에서 확인·수정하는 단계가 없어요.
4. **변호사에게 가는 자료가 상당 부분 틀리거나 사라져요.** 종류별 채무 금액은 카드·세금·기타 3줄로 뭉치고, **세금 체납이 '개인 채무(personals)' 칸에** 들어가고, '총 재산'에는 원래 재산이 아니라 계산된 청산가치가 들어가요. 자가 주택 시세·담보대출·명의, 의료비·교육비 세부, 근로·사업 소득 구분이 사라져요. 무직은 '프리랜서'로 바뀌고, 채권자 수는 없으면 '3', 근속은 1년, 입사일은 상담일, 전화번호 기본값 '010-0000-0000'이 만들어져요. 한 객체 안에서 금액 단위가 만원과 원으로 섞여 있어요.
5. **계산 엔진이 4번 따로 돌아요.** 챗봇(`calculationService`) → 전달 직전 다시 `rehabEngine` → 변호사 쪽 역변환 후 다시 `calculationService`, 계산기는 또 다른 간이식. 변호사 쪽 역변환은 청산가치를 '내 재산'으로 다시 넣고 보증금·배우자 재산을 또 더해 **이중 반영될 가능성**이 있어요.
6. **완료 후 화면을 닫으면 상담 요청이 하나 더 생겨요**(완료 시 1번 + 닫을 때 1번, 대기 시간 제한에만 막힘). 상담 요청 제목은 늘 '개인회생 상담 요청'이고, 본문 제목은 '의뢰인 종합 사전 자가진단 리포트 / 가용 소득(예상 월납입금)'이에요. 공개 요청 분기 코드가 남아 있어요(A-6).
7. **계산기와 연결이 없어요.** 계산기 → 상담 요청으로 소득·채무·부양가족만 넘기고, 챗봇 ↔ 계산기 미리 채우기는 계획(B-7)만 있고 코드가 없어요.

### 2-3. 줄이거나 고칠 것

- 성별: 계산·서류 첫 검토에 쓰지 않으므로 **선택(건너뛰기 가능)**으로. 서류 작성 단계에서 다시 받아요.
- '정확한 상황 파악이 좋은 결과의 첫걸음이에요 ✨' 같은 결과 암시 문구, 이모지 선택지 과다 → 차분한 문구로.
- 배우자 재산 7종 하위 질문(대출 여부·금액 반복)은 길어서 중도 이탈 위험 → '대략 합계 + 큰 항목(집·차) 있음/없음'으로 줄이고, 자세한 항목은 변호사 상담 뒤 '작성 요청'(07 기획서 H-14)으로.
- 마지막 버튼 '자가진단 완료하고 분석하기' → '정리 마치기'.

### 3-3. 파산도 함께 볼 때 (새 분기, CK-Q3)

조건: 소득 없음·수급·소득이 가구 생계비 기준 이하(엔진 내부 판단, 화면에 판정 표시 안 함).

## 5. 계산기와 연동 — 어떻게 이어 줄까 (CK-Q1 결정 10-29: 아래 방식대로)

변호사법 쟁점(제109조)은 **'플랫폼이 개인 사건의 결과를 판단해 알려 주는 것'**이에요. 그래서 연동은 아래 선을 지켜요.

| 원칙 | 내용 |
|:---|:---|
| 정리도우미 안에서는 계산 결과를 보여 주지 않음 | 4장 그대로 |
| 계산기는 별도 화면, **의뢰인이 직접 누를 때만** 값을 불러옴 | 정리 확인 화면의 [제도 이해용 계산기에서 직접 계산해 보기] → 계산기가 열리고 "정리한 내용에서 불러온 값이에요. 직접 바꿔 볼 수 있어요" 표시 |
| 계산기 결과는 B-7 원칙 그대로 | 범위 표시, 감면율·감면액·가능성 표현 없음, 계산 과정 펼치기, 결과를 바꾸는 요인, "공개 기준을 적용한 일반 계산이며 개인 사건의 결과를 판단하지 않아요" |
| 계산기 결과는 저장·전송 안 함 | 변호사에게 가는 건 **정리도우미 답변(사실)**뿐. 계산기 값·결과는 상담 요청에 붙이지 않음 |
| 불러오는 값은 계산기 입력 항목만 | 소득·소득 형태·가족 수·지역·주거비·보증금·주요 재산 합계·채무 총액·세금 체납. 메모·법적 조치·과거 이력은 넘기지 않음 |
| 반대 방향 | 계산기 → 정리도우미: 계산기에서 넣은 값으로 정리도우미 질문을 미리 채우고 의뢰인이 하나씩 확인(B-7 계획) |
| 기기 안에서만 | 로그인 전에는 브라우저 메모리·세션에서만 넘기고, 로그인 후에도 계산기 쪽은 서버에 남기지 않음 |
| 외부 검토 | 이 연동 화면과 문구를 외부 자문 변호사 검토(L4·R6) 대상에 포함, 검토 전에는 '불러오기' 버튼 숨김 가능하도록 설정값 |

**하나의 입력 데이터 틀:** 정리도우미 답변, 계산기 입력, 변호사 자료가 같은 '의뢰인 정리 자료(v2)' 틀(원 단위, 항목 이름 통일)을 쓰면 연동·전달·역변환 버그가 한 번에 줄어요(6장).
