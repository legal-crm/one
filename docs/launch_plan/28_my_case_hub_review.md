# 28. 고객 '내 관리방'·'마이페이지' 구분 점검 (2026-10-29)

- **사용자 요청:** "고객 페이지에 내 관리방과 마이페이지의 구분이 모호해. 두 메뉴를 비교 분석해서 어떻게 구분할지 아니면 합치는 게 맞는지 조사 분석해줘."
- **조사 방법:** 코드 전체 흐름 추적(`client/clientTabs.ts`, `ClientHeader.tsx`, `MobileGNB.tsx`, `ClientRole.tsx`, `client/ChatView.tsx` + `room/*` 6개, `client/MyPageView.tsx` + `mypage/*` 18개, `companion/*` 12개, `alimtokService.ts`), 기존 기획서(01·08·14·06·작업 계획서·마스터) 대조, 다른 서비스 의뢰인 화면 구조 조사(Clio for Clients 공식 도움말, 10-29 로그인 조사한 리걸프렌즈·디던비 기록, 로톡 앱 스토어 설명).
- **관련:** CM(사건 등뼈, 의뢰인용 단계 이름), H-14(작성 요청), CR-5(의뢰인 '보정 할 일'), FE-8(수임료 카드), DC-10(부채증명 진행), BK-8(파산 회생동행), S(서버 저장), A-6(공개 요청 삭제), B-2·RP-Q1(의뢰인 화면 숫자 삭제), I-5(로그인 전 저장).

## 0. 한눈에 보는 결론

1. **두 메뉴는 '시점'으로 나뉘어 있는데, 이름은 그걸 알려 주지 않아요.** 코드 주석(`nextAction.ts`)의 의도는 '내 관리방 = 대화·제안·계약(계약 전)', '마이페이지 = 내 사건·회생동행·설정(계약 후)'이에요. 하지만 화면에서는 둘 다 '내 것'을 보여 주는 이름이고, 같은 기능이 양쪽에 있어요.
2. **겹치는 기능이 많아요.**
   - 제안서 보기·계약 시작: 내 관리방(전자·방문·우편 선택)과 마이페이지(전자만)에 따로 있어요. 마이페이지는 모든 요청의 제안서를 한도 없이 모아 보여 줘요.
   - 채무 정보 보기·고치기: 내 관리방 '내 채무' 탭의 수정 창은 **마이페이지 화면을 그대로 끼워 넣은 것**이에요(`ChatView` 769~793 → `MyPageView isCompact`).
   - 진행 단계: 내 관리방은 상담 요청 상태로, 마이페이지는 기기에 저장된 사건 사본(`getCrmClientSync`)으로 계산해서 둘이 다르게 나올 수 있어요.
3. **서로 떠넘겨요.** 마이페이지 '지금 할 일'은 계약 전 모든 단계에서 "내 관리방 보기·제안서 비교하기·상담방 열기"로 보내요. 내 관리방은 계약 후에 "마이페이지에서 진행 보기" 버튼 하나만 남아요. 마이페이지의 수임료·서류 문의는 "담당 변호사에게 채팅으로" 다시 내 관리방으로 보내요.
4. **막다른 곳이 있어요.**
   - 알림톡 버튼 링크 `https://mykim.kr/my`는 등록된 주소가 아니라서 **홈으로 떨어져요**(전자서명 버튼만 정상).
   - 오프라인 계약 알림(`linkTab:'diagnosis'`)을 누르면 '내 상황 체크'가 시작돼요.
   - 마이페이지의 사건 진행·서류·수임료는 그 브라우저 사본만 읽어서 다른 기기에서는 비어 보여요.
5. **로그인 규칙이 달라요.** 내 관리방은 로그인해야 열리고, 마이페이지는 로그인 없이도 열려 기기에 남은 기록을 보여 줘요.
6. **'회생동행'이 세 번째 입구예요.** 최상위 메뉴 '회생동행'(소개)과 마이페이지 하위 탭 '회생동행'이 따로 있어요.
7. **추천: 하나로 합치고, 계정만 떼어 내요.**
   - **'내 사건'** 하나: 상담 요청과 사건을 같은 곳에서 봐요. 계약 전에는 '대화·제안서·내 정리 자료', 계약 후에는 '할 일·진행·대화·서류·비용'으로 화면이 바뀌어요. 대화는 계약 뒤에도 같은 자리에서 이어져요. 회생동행은 사건 화면 안으로 들어가요.
   - **'내 정보'**: 가명·로그인·알림 받는 방법·동의 내역·1:1 문의·탈퇴처럼 계정에 관한 것만 남겨요.
   - 개발 MY 트랙(MY-1~MY-10), 질문 MY-Q1~Q7은 **10-29 모두 추천안대로 결정**(11장): 합침 · 이름 '내 사건' · 계약 후 대화는 사건 화면 '대화' 탭 · 계약 안 한 변호사 기록은 '지난 상담' 읽기 전용 · 회생동행 사건 화면 흡수 · 아래 탭 홈/상황 체크/변호사 찾기/내 사건/내 정보 · MY-1~10 출시 전.

## 6. 추천 설계 — '내 사건' 허브 + '내 정보'

### 6-1. 메뉴
- 휴대폰 아래 탭(5칸): **홈 / 상황 체크 / 변호사 찾기 / 내 사건 / 내 정보**. '내 사건'에는 할 일 수 + 새 메시지 점, '내 정보'에는 표시 없음.
- 데스크톱 첫 줄: 내 상황 체크하기 / 변호사 찾기 / 상담 사례 / **내 사건**. 오른쪽 계정 메뉴 = 내 정보·로그아웃. 알림 종(전체 알림함)은 머리에 그대로.
- 최상위 '회생동행'은 소개 페이지로만 남기고 '시작하기'는 '내 사건'으로 보내요(MY-Q5).
- 화면 이름은 하나만 써요: '내 관리방', '상담방', '마이페이지', 'Mypage', '나의 가계 재정 & 채무 진단서 원안' 같은 이름은 지워요.

### 6-2. '내 사건' 첫 화면 (목록)
- 상담·사건 카드 목록. 하나뿐이면 바로 그 화면을 열어요.
- 카드: 제목(의뢰인이 고른 관심 제도 또는 '채무 상담'), 의뢰인용 단계 이름(CM-2), 지금 할 일 수, 새 메시지, 출처 배지(마이김변 변호사 / 다른 사무소 / 직접 진행 — 회생동행 3종).
- '지난 상담' 묶음: 종료·취소된 상담, 계약하지 않은 변호사와의 상담 기록(읽기 전용, 삭제 가능, MY-Q4).
- 맨 위 공통 띠: 마감이 가까운 '보정 할 일'(CR-5)·납부일(FE)처럼 기한 있는 일만 모아 보여 줘요. 14 기획서의 '내 관리방 맨 위 띠'는 이 띠로 바꿔요.

### 6-3. 계약 전 화면 (상담)
- 맨 위 상태 줄(지금 단계·다음 할 일·주 버튼 1개) 유지.
- 탭 3개: **대화**(변호사별, 최대 3명) / **제안서**(비교표·카드·'변호사 더 고르기 N명 가능'·요청 취소) / **내 정리 자료**(정리도우미 답한 내용, 고치기 → 이미 보낸 변호사에게 '정보가 바뀌었어요' 알림, I-2·I-5).
- 숫자: 변호사가 보낸 제안서 값만(월 변제금·기간·총 변제액, RP-Q1). '내 채무' 탭의 예상 월 변제금·감면율·감면액과 대화창 머리의 '감면율 %'는 지워요(B-2).
- 계약 방식(전자·방문·우편) 선택은 여기 한 곳에만.
- 공개 요청 버튼·'공개 요청 중' 단계 삭제(A-6).

### 6-4. 계약 후 화면 (사건)
- 머리: 사건 이름, 담당 사무소·변호사(계약서 기준 하나), 의뢰인용 단계, 다음 일정, '누구에게 물어보나요'(CM-11).
- 탭 5개:
  - **할 일**(기본 탭): 작성 요청(H-14), 요청 서류·반려(DP), 보정 할 일(CR-5), 부채증명 진행·주의사항(DC-10), 납부 안내(FE), 면책 신청 준비 — 기한순.
  - **진행**: 단계표(서버 `cases`·`case_events`, CM), 법원 기일, 회생동행 진행(개시·집회·인가·변제·면책), 파산이면 파산 단계(BK-8).
  - **대화**: 계약 전 그 사무소와 나눈 대화가 그대로 이어져요(MY-Q3). 서류·할 일 카드에서 "이 일 물어보기"를 누르면 그 항목을 붙여 대화로 와요.
  - **서류**: 낸 서류·받은 서류(제출한 보정서 사본, 계약서, 결정문 등), 서류 작성 도구.
  - **비용**: 수임료(FE-8 '입금했어요'·일정 조정 요청·납부 내역 PDF)와 법원 변제금(회생동행 납부 기록)을 **나란히, 섞이지 않게**(01 기획서 결정 유지).
- 회생동행의 '공적 지원·회복 아카데미'는 사건 화면 '도움말' 칸(진행 탭 아래)과 상단 소개 페이지로 옮겨요. 면책신청서 작성기 입구는 진행 탭 면책 단계·할 일 카드 두 곳.
- 직접 진행·다른 사무소 사건(회생동행 직접 등록)은 같은 사건 화면을 쓰되 대화·수임료 탭은 없어요.

### 6-5. '내 정보' (계정만)
- 스텔스 가명(바꾸기), 로그인 방법·기기, 알림 받는 방법(앱 안·알림톡·이메일), **동의 내역**(변호사별 상담 정보 제공 동의·철회, 마케팅 수신), 1:1 문의, 인증서 금고(PIN 암호문만 서버, S), 로그아웃, 탈퇴(보유 기간 안내, OP-10).
- 알림함은 머리 종 하나로 합쳐요(마이페이지 '알림·설정' 탭 삭제).

### 6-6. 주소와 알림 링크
- 주소: `/my`(내 사건 목록), `/my/{사건ID}`(사건 화면), `/my/{사건ID}/todo|progress|chat|docs|fees`, `/me`(내 정보). `vercel.json`·`CLIENT_PATH_TAB_MAP`에 등록하고, 로그인 안 했으면 로그인 후 그 주소로 돌아와요(FH-Q2: 토큰만으로 개인정보 입력 받지 않음).
- 알림톡·알림 링크를 목적지 주소로 바꿔요(보정 → `/todo`, 납부 → `/fees`, 메시지 → `/chat`). `linkTab:'diagnosis'`·`'fees'` 같은 옛 값 정리.

### 6-7. 데이터 (서버만)
- 허브는 서버만 읽어요: `consult_requests`·`consult_messages`, `cases`·`case_events`(CM-1), `client_form_requests`/`submissions`(H-14), `fee_*`(FE), `correction_*`(CR), 회생동행 서버 저장(S·BK-8), 알림 서버화(ST).
- `getCrmClientSync`·`loadContractsLocal`·`loadFeeNotificationSettings`·`legal_crm_data` 읽기를 허브에서 없애요. 실패하면 화면에 알려요(6-1 원칙).
- 단계는 하나만: CM-2 단계표의 의뢰인 문구. 관리방 배지와 마이페이지 진행 카드가 따로 계산하던 것 정리.

### 6-8. 로그인·익명
- '내 사건'·'내 정보'는 로그인해야 열려요. 로그인 전에 정리도우미를 했다면 '이 기기에서 정리한 내용' 카드 + 로그인 안내만 보여 주고, 로그인하면 계정으로 옮겨요(I-5).
- 화면에는 스텔스 가명만. 실명은 계약서·서명 화면 안에서만.
- 계약하지 않은 변호사는 계약 뒤 그 사건에 접근할 수 없어요(지금 RLS 유지). '지난 상담' 기록은 의뢰인만 봐요.

## 10. 완료 기준

- 고객 사이트에 '내 관리방'·'마이페이지'·'상담방'·'Mypage' 이름이 0건이고, 메뉴는 '내 사건'·'내 정보'예요.
- 같은 기능(제안서 보기·계약 시작·채무 정보·진행 단계·알림함)이 화면 한 곳에만 있어요.
- 계약 전 대화가 계약 후 같은 사건 화면 '대화' 탭에서 이어져요.
- 알림톡 버튼 링크가 모두 목적지 화면(로그인 후)으로 열리고, 홈으로 떨어지는 링크가 0건이에요.
- 다른 기기에서 로그인해도 사건·할 일·서류·수임료·변제 기록이 같아요(기기 사본 읽기 0건).
- 의뢰인 화면에 변호사가 보내지 않은 월 변제금·감면율 숫자가 0건이에요.
