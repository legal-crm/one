## A. 변호사 어드민

### LA-Q1. 'AI 사건 분석'을 유료로 잠가 둘까요?

- **무엇인가요:** 변호사 어드민 사이드바 '상담 > AI 사건 분석'이에요. 의뢰인이 정리한 정보로 변제금 시나리오(보수·표준·적극 3안), 청산가치, 자격 요건을 검토하고 제안서 초안을 만드는 변호사용 도구예요. 외부 AI는 부르지 않아요.
- **지금 상태:** 기본으로 잠겨 있고 메뉴에 '유료' 배지가 붙어 있어요. 관리자가 변호사마다 켜 줘야 쓸 수 있어요. 결제 기능은 없어요.
- **왜 정해야 하나요**
  1. "플랫폼 수익은 정액 광고비뿐, CRM 이용료 0원"으로 정하셨고, 가입 안내 비용 카드도 그렇게 고쳤어요. '유료' 잠금은 이 약속과 어긋나요.
  2. 이번 기획의 'AI 진단 보고서 업그레이드'(변호사가 의뢰인에게 보내는 보고서)가 이 도구 안에서 만들어져요. 잠겨 있으면 대부분의 변호사가 보고서를 보낼 수 없어요.
- **선택지**
  - (a) **모든 승인 변호사에게 무료 개방** ← 추천
  - (b) 광고 상품을 산 변호사에게만 혜택으로 열기
  - (c) 별도 정액 유료 기능으로 유지 — 결제 기능·가격·약관이 필요하고 "CRM 이용료 0원" 문구를 고쳐야 해요. 상담·수임 건수와 무관한 정액이면 변호사법 문제는 없어요.
- **추천 이유:** 변호사 유치 초기에는 쓸 수 있는 기능이 많아야 가입 이유가 생기고, 보고서 기능이 막히지 않아요.
- **답해 주실 것:** a / b / c

### LA-Q2. 설정 화면의 '텔레그램 시뮬레이터'를 남길까요?

- **무엇인가요:** 변호사 어드민 '설정 > 알림 & 보안 연동' 화면이에요. 왼쪽에는 실제 텔레그램 봇·채팅방 연결 설정이 있고, 오른쪽에 휴대폰 모양으로 **가짜 알림 메시지 데모**가 있어요.
- **문제**
  - 데모 안에 "선착순 오픈 배정", "수임 배정 완료", "🙋 내가 즉시 담당자로 배정" 버튼이 있어요. 폐지한 공개 요청 구조이고, 금지어예요.
  - 버튼을 눌러도 실제로는 아무 일도 일어나지 않아서 실제 기능처럼 오해할 수 있어요.
- **선택지**
  - (a) **데모 삭제, 실제 연결 설정과 '테스트 메시지 보내기'만 남김** ← 추천
  - (b) 데모를 남기되 '화면 예시' 표시를 붙이고 문구를 고침
- **답해 주실 것:** a / b

## B. 통합어드민

### SA-Q1. 전자계약 '블록체인 기록'을 어떻게 할까요?

- **무엇인가요:** 전자계약을 체결하면 계약서의 전자지문(SHA-256 해시)을 Polygon 블록체인에 기록해서 "나중에 계약서가 바뀌지 않았음"을 증명한다는 기능이에요. 계약 검증 페이지(`?verify=`)와 통합어드민 '전자계약 블록체인 관제'가 이 내용을 보여 줘요.
- **지금 상태:** 운영 서버에 블록체인 설정이 없어서 **테스트넷(Amoy)** 기본값이고, 기록을 올릴 지갑 키도 없어요. 그래서 실제로는 **서버에 전자지문만 저장**되고 블록체인에는 아무것도 기록되지 않아요. 그런데 화면은 "블록체인 기록"이라고 표시해요.
- **왜 정해야 하나요:** 화면 설명과 실제 동작이 달라요. 출시하면 과장 표시가 돼요.
- **선택지**
  - (a) **Polygon 메인넷에 실제 기록** — 지갑 키를 서버에 안전하게 보관하고, 계약마다 아주 적은 수수료(가스비)가 들어요. 키 관리 책임이 생겨요.
  - (b) **서버 전자지문 보관만 하고, 화면 표현을 '전자지문 무결성 검증'으로 바꿈** ← 추천
  - (c) 테스트넷 유지 — 운영 계약을 시험용 네트워크에 기록하는 셈이라 권하지 않아요.
- **추천 이유:** 전자계약의 법적 효력은 본인인증(PortOne)·서명·감사 기록이 핵심이고 블록체인은 부가 증명이에요. (b)로 출시하고 나중에 (a)를 붙일 수 있어요.
- **답해 주실 것:** a / b / c

### SA-Q2. 광고 판매는 언제 시작할까요?

- **무엇인가요:** 광고 상품(메인 배너, 상단 노출, 지역 광고)을 변호사에게 팔기 시작하는 시점이에요. 홈 변호사 소개 배너는 이 상품을 사면 함께 노출돼요(결정됨).
- **고려할 점:** 오픈 직후에는 방문자와 변호사가 적어서 광고 효과가 약하고 불만·환불이 생길 수 있어요. 반면 플랫폼 수익은 광고비뿐이에요.
- **선택지**
  - (a) 정식 오픈과 동시에 판매
  - (b) 변호사가 N명 이상 모인 뒤 판매. 그 전에는 무료 기본 등록만 (홈 소개 배너는 등록 변호사로 채워져요)
  - (c) **오픈과 동시에 열되, 초기 혜택 기간(예: 첫 1~2개월 무료 또는 할인)** ← 추천
- **추천 이유:** 광고 신청 → 소재 심사 → 노출 → 세금계산서 흐름을 오픈 초기에 실제로 검증할 수 있고, 변호사 유치 혜택으로도 쓸 수 있어요.
- **이 답으로 정해지는 것:** 광고 노출 연결과 소재 심사 기능을 정식 오픈 범위에 넣을지 여부
- **답해 주실 것:** a / b(N명) / c(혜택 기간·방식)

### L8. 주민등록번호를 어떻게 다룰까요?

- **왜 정해야 하나요:** 법원 서식을 전부 자동으로 채우려면(H 트랙) 주민등록번호가 들어가요. 주민번호는 법령 근거가 있어야 하고, 저장한다면 **암호화가 의무**예요. 지금 CRM에는 주민번호 칸이 없어서 서식에서 직접 입력하고 있어요.
- **선택지**
  - (a) **서버에 암호화 저장:** 한 번 넣으면 모든 서식에 자동으로 들어가요. 암호화 설계, 열람 기록, 화면 마스킹(뒷자리 ●)이 필요해요.
  - (b) **저장하지 않음:** 서식을 출력할 때 한 번 입력하면 그 묶음(ZIP) 전체에 채워지고, 출력 후 지워져요. ← 출시 때 추천
- **추천 이유:** 일괄 출력을 하면 입력은 사건당 한두 번이라 불편이 크지 않고, 유출 위험이 없어요. 변호사들이 불편하다고 하면 출시 후 (a)로 바꿀 수 있어요.
- **추가 원칙:** 어느 쪽이든 의뢰인 화면에서는 주민번호를 받지 않고, 사무소 화면에서만 입력해요.
- **답해 주실 것:** a / b
