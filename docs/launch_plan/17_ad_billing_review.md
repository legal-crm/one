## 0. 한눈에 보는 결론

**지금은 광고를 팔 수도, 판 광고를 보여 줄 수도 없어요.**

1. **신청이 안 돼요.** '광고 상품'에서 '광고 신청하기'를 눌러도 신청 창이 뜨지 않아요. 창이 '사업자·세금계산서' 탭 안에 들어 있어서, 그 탭으로 옮겨야 갑자기 나타나요.
2. **금액이 틀려요.**
   - 소수점 할인가를 잘못 읽어 **메인 배너 12개월이 월 375만 원, 상단 노출 6개월이 월 255만 원**(정상 37.5만·25.5만의 10배)으로 계산돼요.
   - 화면은 'VAT 별도'인데 입금 금액에 VAT를 더하지 않고, 관리자 화면은 그 금액을 'VAT 포함'으로 보고 세금계산서 공급가를 ÷1.1로 계산해요. 받아야 할 돈과 세금계산서 금액이 어긋나요.
   - 남은 구좌(3/5·4/6·2/4)는 **고정된 가짜 숫자**이고, 구좌가 차도 계속 신청돼요. 무료 상품도 '신청하기'가 있어 0원 주문이 만들어져요.
   - 오픈 할인(첫 2개월 50%)은 구현돼 있지 않아요.
3. **주문이 그 브라우저에만 있어요.** 변호사가 신청한 주문은 브라우저에 먼저 저장되고, 서버 저장이 실패해도 "신청 완료"가 떠요. 변호사 화면은 서버를 읽지 않아서 **관리자가 입금을 확인해도 변호사 화면에는 반영되지 않고**, 다른 기기에서는 주문이 안 보여요. 같은 브라우저를 쓴 다른 변호사 주문도 섞여 보여요.
4. **입금을 확인해도 고객 사이트에 광고가 나오지 않아요.** 고객 화면은 `lawyers.ad_tier`만 보는데, 입금 확인은 주문 상태만 바꾸고 이 값을 바꾸지 않아요(관리자 화면에도 바꾸는 곳이 없음). 메인 배너 자리(Hero 슬라이더)는 없고, 홈 소개 배너는 DEV 전용 가짜 데이터('인가율 98%', '누적 842건')예요. 만료 처리·갱신도 없어요.
5. **세금계산서 흐름에 구멍이 있어요.**
   - 사업자 정보는 브라우저에만 저장되고 주문에 붙지 않아요. 주문의 사업자번호는 프로필 값에서 가져오는데 028이 그 값을 지워서 대부분 비어 있어요.
   - 변호사의 '세금계산서 보기' 버튼은 관리자 전용 API를 불러 **항상 403**이에요. "입금 시 자동 발행·국세청 자동 전송" 안내는 사실과 달라요(관리자가 수동 발행).
   - 관리자 세금계산서 합계는 숫자가 아니라 **글자를 이어 붙여** 계산돼요. 발행은 됐는데 주문 저장이 실패하면 되살릴 방법이 없어요.
   - 팝빌은 `POPBILL_IS_TEST`가 없으면 **운영 모드**가 기본이에요(테스트 점검 후 실발행 결정과 반대).
6. **문구가 광고 규정·결정과 어긋나요.** '"추천 변호사" 섹션', '지역 전담 변호사 영역', '우선 배치', '노출·클릭 리포트 제공', '2지역 동시 구매 10% 할인'(없는 기능), '채무 진단 리포트 열람'(폐지된 기능), 환불 '노출 100회 미만'(측정 불가)·'소재 심사 반려'(심사 없음).
7. **개편 방향:** 상품·가격·할인·구좌를 **서버 카탈로그**로 옮기고, 금액은 서버가 계산해요. 주문 → 입금 → 소재 승인 → 노출 → 만료의 **한 줄 상태 흐름**으로 만들고, 노출은 '지금 노출 중인 광고' 서버 목록에서 고객 사이트가 직접 읽어요. 변호사 화면은 서버 기준으로 다시 짜고, 소재 등록·미리보기·심사, 알림, 갱신, 정직한 환불 규정을 더해요.

## 3. 서버·고객 사이트 현황

- **`ad_orders`(024):** 변호사는 본인 대기 주문만 넣고, 수정·삭제는 관리자만. 넣을 때 **금액·상품을 검사하지 않아요**(0원·임의 금액 가능). 변호사가 입금 전 취소할 수 없어요. 024 실행 검증 기록 없음.
- **세금계산서 API:** 발행·수정·목록·보기·재발송은 관리자(2단계 인증)만. 관리키 `AD-주문번호`로 같은 주문 중복 발행은 막지만, 수정발행 관리키는 시각을 붙여 두 번 누르면 두 번 나가요. 발행 금액·공급받는자를 **요청 값 그대로** 써요(주문 DB 재확인 없음, 2-15). 사업자 확인(`check-corp`)은 로그인한 누구나 → 팝빌 비용. 공급자 업태·종목이 '서비스업/소프트웨어 개발 및 공급'으로 박혀 있어 사업자등록증과 맞는지 확인 필요.
- **고객 화면 노출:** `lawyers.ad_tier`만 읽음(028이 변호사 스스로 못 바꾸게 막음 — 좋음). 무료 'basic'도 광고 표시(LD-5), 지역 광고가 광고 지역을 안 읽음(LD-6), 같은 등급 무작위는 탭 열 때마다 바뀜(LD-5). Hero 메인 배너 슬라이더 없음, 홈 소개 배너 DEV 전용.
- **측정:** 노출·클릭 기록 전혀 없음.

## 4. 개편 설계

### 4-1. 상품·가격·할인 서버 카탈로그 (AD-1)

| 테이블 | 칸 |
|:---|:---|
| `ad_products` | 상품 코드, 이름, 노출 위치 설명, **월 공급가(원, VAT 별도)**, 판매 여부, 구좌 수(전국) 또는 지역당 구좌 수, 가능한 기간(개월 목록), 기간별 할인율(정수 %), 홈 소개 배너 함께 노출 여부, 설명·특징 문구(M-9 검사 통과본), 정렬 |
| `ad_promotions` | 이름(예: 오픈 할인), 할인율, 적용 기간(시작·끝), 적용 상품, 적용 방식, 다른 할인과 겹침 규칙(AD-Q2) |

- 금액은 **정수 원**으로만 저장해요(지금처럼 '월 37.5만원' 글자를 읽지 않음).
- 무료 '기본 등록'은 상품 목록에서 빼고 "승인되면 자동으로 변호사 찾기에 나와요" 안내로 바꿔요(신청 버튼 없음).
- 통합어드민에 **상품·가격·할인 관리 화면**: 가격을 바꾸면 이미 신청한 주문은 신청 당시 가격 유지, 바꾼 기록 남김. 오픈 할인은 오픈일을 넣으면 2개월이 자동 계산되고 끝나면 정가로.
- 가격 숫자 자체는 A-5 경쟁사 조사로 확정해요(Q17). 이번 점검에서 웹 검색으로 경쟁사 광고 단가를 확인하지 못했어요.

### 4-2. 금액 계산·구좌는 서버에서 (AD-2)

- 서버 함수 `create_ad_order(상품, 기간, 지역, 시작 희망일, 소재, 입금자명)`가:
  - 카탈로그·할인으로 **공급가·VAT(10%)·합계**를 계산하고(원 단위 반올림 규칙 하나), 화면 값은 쓰지 않아요.
  - 구좌를 확인해 남으면 **입금 기한 동안 예약**(기본 3영업일, AD-Q3), 차 있으면 '대기 신청'으로 받아요(자리가 나면 알림).
  - 사무소 사업자 정보(4-6)를 주문에 복사해 둬요(세금계산서용).
- 화면 금액 표시: "월 공급가 ○원 × ○개월 − 할인 ○원 = 공급가 ○원 + 부가세 ○원 = **입금하실 금액 ○원**". 가격 표기는 'VAT 별도'를 유지하고 입금 금액은 VAT 포함으로 분명히 보여 줘요(AD-Q1).
- **남은 구좌** = 전체 − (노출 중 + 시작 예정 + 입금 대기 예약). 지역 광고는 지역별로.
- `ad_orders` 직접 넣기는 막고(RLS) 이 함수로만 만들어요.

### 4-3. 주문 상태 흐름 (AD-3)

```
신청(입금 대기, 구좌 예약) ──입금 기한 지남──▶ 자동 취소(구좌 반환)
   │  변호사 '신청 취소' / 관리자 '거절(사유)' ─▶ 취소
   ▼ 관리자 입금 확인(금액 VAT 포함 일치·입금일)
입금 완료 ──소재 반려──▶ 소재 수정 대기(변호사 수정 → 다시 심사)
   ▼ 소재 승인
시작 예정(시작일이 미래) ──시작일──▶ 노출 중 ──만료일──▶ 만료
                                        │ 만료 7일 전·1일 전 갱신 안내
                                        └─ 환불(전액/일할) ─▶ 환불 완료(수정세금계산서·이체 기록)
```

- **노출 시작일** = 입금 확인과 소재 승인이 모두 된 날(또는 그 뒤 변호사가 고른 시작일). **만료일** = 시작일 + 개월 수(말일 보정), 서버가 계산해요. 지금처럼 '버튼 누른 시각'으로 계산하지 않아요.
- **갱신:** 만료 전 '연장 신청' = 같은 상품·지역으로 새 주문(구좌 우선 유지, 만료일 다음 날 시작).
- 매일 서버 작업(Vercel Cron, Pro 전환 후)이 시작·만료·자동 취소·안내를 처리하고, 고객 화면은 읽을 때도 기간을 다시 확인해 늦어도 만료 광고가 보이지 않아요.

### 4-4. 노출 연결 (AD-4)

- 서버 뷰 `active_ad_placements`(지금 노출 중인 광고: 상품, 변호사, 지역, 기간, 승인된 소재)를 고객 사이트가 직접 읽어요.
  - **홈 Hero 슬라이더:** 메인 배너 광고 소재 + 브랜드 배너(01 1-B), 광고 비율 상한.
  - **홈 변호사 소개 배너:** 메인 배너·상단 노출 광고 변호사 → 빈자리는 실사진 있는 승인 변호사 '등록 변호사'(01 1-C).
  - **변호사 찾기 상단:** 상단 노출 광고(최대 구좌), **지역 광고:** 고른 지역 = 광고 지역일 때만 그 지역 결과 맨 위(LD-6).
- `lawyers.ad_tier`는 이 목록에서 자동으로 맞추는 값으로만 쓰고(트리거·매일 작업), 관리자가 손으로 바꾸는 화면은 만들지 않아요.
- 같은 등급 안 순서는 무작위(방문 세션 고정, LD-5). 모든 광고에 '광고' 글자 표시, 정렬 기준 고지("광고는 무작위 순서").

### 4-5. 광고 소재 등록·심사 (AD-5)

- **소재 종류:** ① 메인 배너(1040×780 이상 WebP, 모바일용 선택, 대체 텍스트) ② 카드(본인 실사진 3:4 600×800 이상·자르기, 한 줄 소개 40자, 분야 태그 3개). 상단 노출·지역 광고·소개 배너는 카드 소재를 같이 써요.
- 신청 마법사 2단계에서 새로 만들거나 기존 승인 소재를 골라요. **실제 노출 모양 그대로 미리보기**(Hero·소개 배너·변호사 찾기 카드).
- 자동 확인: M-9 금지 표현 사전(결과 보장·성공률·수임 건수·'최고/1위'·'전담'·'추천'·'무료상담' 등)으로 경고, 사진 규격·얼굴 여부 경고. 경고는 막지 않고 관리자 심사로 넘겨요.
- 표시 필수: '광고', 광고책임 변호사 이름·사무소명(변호사 광고 규정, 마스터 4-1).
- **관리자 심사:** 승인 / 반려(사유 선택 + 글) / 수정 요청, 기록. 승인된 소재를 바꾸면 다시 심사, 그동안은 이전 소재로 노출.
- 저장: `ad_creatives`(버전·상태·사유) + Supabase Storage 공개 버킷(승인본만 공개 주소).

### 4-6. 사업자 정보·세금계산서 (AD-6)

- **사무소 사업자 정보 서버 저장**(`office_billing_profiles`, 사무소 단위·대표만 수정): 사업자번호(체크섬)·상호·대표자·업태·종목(기본 전문서비스업/법률서비스, 수정 가능)·주소·세금계산서 이메일 2개(형식 확인)·휴폐업 확인 결과와 날짜. 기존 브라우저 저장분은 첫 로그인 때 옮겨요.
- **발행은 서버가 주문을 보고:** `issue`는 주문 번호만 받고 금액·공급받는자·품목을 **주문 DB에서 다시 읽어** 발행하고, 결과(승인번호·관리키·발행일)를 **서버가 주문에 바로 저장**해요(화면 저장 실패로 기록이 사라지지 않음). 이미 발행된 주문이면 팝빌을 조회해 다시 붙여요.
- 수정발행 관리키는 `MD-주문번호-회차`로 고정(두 번 눌러도 한 번), 부분 환불은 '환불(부분)' 상태로 구분.
- **변호사 '세금계산서 보기':** 본인 사무소 주문만 여는 서버 소유권 검사 API(2-15). 발행 내역은 사업자 등록과 상관없이 보여요.
- 문구: "광고비 입금이 확인되면 마이김변이 전자세금계산서를 발행해요(팝빌, 국세청 전송)".
- 팝빌: `POPBILL_IS_TEST` 기본 **테스트**, 운영은 명시적으로 켤 때만. 공급자 정보(업태·종목 포함)는 환경변수 필수, 비면 '미설정'. 엑셀 공급자 정보도 환경변수에서. 금액은 숫자로 저장(합계 버그 수정). 팝빌 목록 조회로 국세청 전송 상태 표시(🟡). `check-corp`는 변호사 계정만 + 하루 횟수 제한.

### 4-7. 변호사 화면 개편 (AD-7)

- **광고 현황:**
  - 노출 중 광고 카드(상품·지역·기간·남은 일수·소재 썸네일·노출 위치 바로 보기), 시작 예정, **다음 할 일**(입금하기: 계좌·금액·기한·복사 / 소재 수정하기 / 연장하기).
  - 숫자: 노출 중·입금 대기·이번 달 결제액(실제 입금 기준, VAT 포함/별도 구분).
  - 빈 상태: "아직 광고가 없어요" + '광고 상품 보기', 무료 노출 안내("승인되면 변호사 찾기 기본 목록에 나와요").
- **광고 상품:** 서버 카탈로그, 실제 남은 구좌(다 차면 '대기 신청'), 정가·기간별 할인·오픈 할인(남은 기간), "홈 변호사 소개 배너 함께 노출" 표기, 노출 위치 그림. '광고 신청'은 **같은 탭에서** 3단계 마법사(① 기간·지역·시작 희망일 → ② 소재 → ③ 금액·입금자명·사업자 정보 확인).
- **내 광고 주문:** 단계 표시(신청 → 입금 → 소재 → 노출 → 만료), 입금 기한, 신청 취소(입금 전), 세금계산서 보기, 연장, 환불 요청(사유) — 서버 기준·실시간(Realtime).
- **사업자·세금계산서:** 4-6.
- **권한(RB-4):** 광고 신청·결제는 대표만, 경리는 보기·세금계산서, 담당 변호사는 보기. 탭 본문도 같은 판정. 권한 라벨 '수임료/회계' → '광고·결제'.
- **사무소 기준:** 주문·사업자 정보·광고는 사무소(RB-1) 단위, 소재는 변호사 개인 단위(담당 변호사 각자 광고 가능 여부는 대표가 승인).

### 4-8. 통합어드민 개편 (AD-8)

- 주문 목록 서버 기준 + 실시간, 상태 필터 전부, **입금 대기 거절·취소**, 입금 확인(입금액 VAT 포함 일치 확인 칸·입금일), 처리 순서 표시(입금 → 소재 → 노출).
- **소재 심사함**(4-5), **구좌 현황표**(상품·지역별 노출 중·예정·예약·대기), **노출 구성 미리보기**(Hero·소개 배너·변호사 찾기, 03 7장).
- **환불 도우미:** 규정(AD-Q4)대로 금액 계산(일할), 수정세금계산서 발행, 환불 이체일·계좌 기록.
- **상품·가격·할인 관리**(4-1), 광고 배너 화면은 '브랜드 배너'(01 1-B)만 남기고 광고 소재는 심사함으로.
- 매출 대시보드: 공급가·VAT 분리, 환불 차감, 미발행 계산서 수.

### 4-11. 환불 규정 다시 쓰기 (AD-11, AD-Q4)

## 7. 완료 기준

- 변호사가 '광고 상품'에서 바로 신청하고(창이 같은 탭에서 열림), 서버가 계산한 공급가·VAT·입금액이 화면·주문·세금계산서에서 모두 같아요. 12개월 메인 배너가 월 37.5만 원 기준으로 계산돼요(정가 확정 전 현재 값 기준).
- 남은 구좌가 실제 주문으로 계산되고, 다 차면 신청 대신 대기 신청이 돼요. 0원 주문·임의 금액 주문이 서버에서 거절돼요.
- 관리자가 입금을 확인하고 소재를 승인하면 **그 시각부터 고객 사이트 해당 위치에 '광고' 표시와 함께 나오고**, 만료일 다음 날 자동으로 사라져요. 변호사 화면(다른 기기 포함)에도 바로 반영돼요.
- 입금 기한이 지나면 주문이 자동 취소되고 구좌가 돌아와요. 변호사는 입금 전 신청을 취소할 수 있고, 관리자는 대기 주문을 거절할 수 있어요.
- 세금계산서가 주문 DB 기준으로 발행되고 결과가 서버에 저장돼요. 변호사가 자기 계산서를 열 수 있고 다른 사무소 계산서는 못 열어요. 관리자 합계가 숫자로 맞아요. 팝빌 테스트 모드에서 발행·수정발행·이메일 수신을 확인한 뒤에만 운영 모드로 바꿔요.
- 신청·입금·소재·노출·만료 알림이 변호사에게 가요.
- 광고 상품·소재·화면 문구에서 '추천'·'전담'·'우선 배치'·'리포트 제공'·'채무 진단 리포트'·'절대 없음'·'노출 100회' 0건.
