## 0. 한눈에 보는 결론

1. **오늘의 업무 숫자 대부분이 실제와 달라요.**
   - 화면이 사건 정보를 **서버가 아니라 그 탭의 임시 사본**(`loadCrmExtMap`, 세션 저장소)에서만 읽어요. 새 탭·다른 기기에서는 사본이 비어 있어 '7일 내 기한 0건', '연체 수납 ₩0'처럼 대부분 0이 돼요.
   - 숫자 정의가 화면마다 달라요. '새 상담 요청 5건'은 정보가 없는 요청을 모두 '신규'로 세서 나오고(사이드바·업무함은 1건), '답변 대기 채팅 3건'은 읽지 않은 채팅이 아니라 상담 중인 요청 전체예요.
   - 업무함의 '기한 지남'은 진짜 기한이 아니에요. 상담 요청이 2일 넘게 지나면 무조건 '기한 지남'으로 보내요(첨부 화면의 '27일 전' 건).
   - 업무함 버튼 3종('제안서 작성'·'수납 열기'·'서류 검토')이 없는 화면 이름으로 연결돼 모두 1단계 요약으로 열려요.
   - 사이드바 '사건 관리 14'에는 **운영에서도 시연용 테스트 사건 9건**이 들어 있고, '수임료 수납 2'는 시연용 수납 일정에서 나와요. 'AI 사건 분석 1'은 상담 요청 수를 그대로 다시 보여 줘요.
2. **상단 'NEW UPDATE' 배너 문구가 사실과 달라요.** "전자소송 13종 실시간 양방향 매핑, 법원 규격 A4 PDF 직접 다운로드, 8대 공공기관"은 지금 기능(그림 PDF·빈 HWPX·글자만 끼워 넣는 서식)과 다르고 날짜·관리 주체가 없어요. '실무 개선 제안'은 그 브라우저에만 저장되는데 "플랫폼 고도화에 즉시 반영하겠습니다"라고 안내해요.
3. **지금까지 기획한 새 업무가 오늘의 업무에 하나도 없어요.** 보정 기한·의뢰인 미응답 항목(CR), 의뢰인이 보낸 서류·작성 요청 검토(DP·H-14), 상담 요청 응답 기한 2영업일(LD), 영업 DB 오늘 할 일(SL), 업무폰 등록 요청·올리지 못한 녹음·기기 승인(CL), 담당자 카톡 미발송(KT), 계약 서명 대기, 수임료 D-3·당일, 제안서 유효기간(B-5), 서버 일정(`calendar_events`)·할 일(`task_tickets`) 모두 빠져 있어요.
4. **직원·권한은 화면이 약속한 것과 실제 동작이 크게 달라요.**
   - '역할별 권한 체계표'는 **손으로 적은 표**예요. 실제 권한 설정과 연결돼 있지 않고, '상담 단계 수정'·'서류·보정 수정'·'전자계약 최종 승인'·'열람 전용' 같은 칸은 코드에 없어요. 개별 권한 토글 12개 중 6개(고객 정보 수정·상태 변경·사건 배정·직원 관리·메모 작성·수임료 관리)는 아무 데서도 확인하지 않아요.
   - 탭 권한표에 없는 메뉴 6개(상담 요청·상담 채팅·일정·기한·계약 현황·공개 Q&A·마이김변 문의)가 **대표를 포함한 모든 사람의 데스크톱 사이드바에서 숨겨져요.** 첨부 화면 사이드바에도 이 메뉴들이 없어요. 반대로 메뉴만 숨기고 화면 자체는 권한 확인 없이 열려요(직원·권한 탭만 예외).
   - 서버에서는 **직원이 대표 사무소 데이터를 볼 수 없어요.** 상담 요청은 '승인된 변호사 본인'에게 온 것만 보이고, 직원 계정은 승인된 변호사가 아니라서 0건이에요. 사건 기록도 사무소 단위 규칙이 없어요. 사무소 단위 규칙은 할 일·일정·메신저·알림에만 있어요.
   - 직원 초대를 수락하면 **변호사 가입 신청으로 처리돼** 통합어드민 변호사 심사 목록에 올라가고 "자격 서류 제출 후 관리자 승인이 필요합니다"라는 안내가 떠요.
   - 직원 기록을 찾지 못하면(첫 로딩 네트워크 오류 포함) **대표 권한으로 간주**해요. 정지·탈퇴는 1분마다 확인하는 화면 쪽 점검으로만 막혀요.
   - 활동 로그·커스텀 역할·제안서 컨펌 대기 목록이 모두 브라우저 저장이라, 직원이 컨펌을 요청해도 다른 기기의 변호사는 알림만 받고 내용을 열 수 없어요.
5. **개편 방향.**
   - 오늘의 업무: 서버 데이터로 만든 **업무함 하나**(진짜 기한 규칙, 올바른 바로가기, 미루기·넘기기) + 역할별 카드 + 서버 일정 + '의뢰인 회신 대기' 묶음 + 대표용 사무소 현황. 배너는 통합어드민 공지로.
   - 직원·권한: **사무소(tenant) 기준 데이터·권한 구조**로 바꾸고, 권한 목록 하나(코드)에서 화면 표·메뉴·버튼·서버 규칙을 함께 만들어요. 변호사만 할 수 있는 일은 고정해요. 직원 계정은 변호사 가입과 분리하고, 활동 기록은 서버에 쌓아요.

| 사건 관리 | '배정 사건 수정'·'상담 단계 수정'·'서류·보정 수정'·'열람 전용' | '전체 고객 조회'와 '삭제'만 확인. 나머지 없음 |
| 전자계약 | '최종 승인'·'초안 작성'·'권한 없음' | 승인 단계 없음, 누구나 가능 |
| 서류 번들·보정 | '검토 및 제출'·'작성 및 첨부' | 확인 없음 |
| 수임료 | 담당 변호사 '내 사건 열람' | 담당 변호사도 전체 |
| 광고·세금계산서 | 담당 변호사 '열람 제한', 경리 '세금계산서 발급' | 담당 변호사·경리 모두 전체 |
| (표에 없음) | — | 영업 DB(상담·사무 직원 가능), AI 사건 분석, 설정(모두 가능), 일정, 데이터 백업(대표만) |

### 2-3. 서버·계정

- **사무소 구분:** 사무소 = 대표 변호사 ID(또는 `law_firm_id`). 사무소 판정 함수(020: `current_tenant_ids`·`tenant_role`·`is_tenant_member`)가 있지만 할 일·일정·메신저·알림·세션에만 써요. 상담 요청(012)·사건(011)·계약(011)에는 없어요.
- **사건 기록 규칙(011):** 로그인 계정 ID(`auth.uid()`)와 배정 칸(변호사 ID·`staff-…` ID)을 비교해요. 값의 종류가 달라 의뢰인 본인 외에는 맞지 않을 수 있어요(운영 DB에서 확인 필요, A-1).
- **직원 계정:** 초대 수락 = OAuth 로그인 → 변호사 계정 신청(`claim_lawyer_account`, 승인 대기) + 직원 기록(승인 대기). 그래서 직원이 '승인된 변호사'가 아니라 상담 요청이 0건이고, 회사 단위 설정(AI 사건 분석 과금 모드·승인 여부)을 **직원 자기 계정**에서 읽어요.
- **세션 종료:** 대표가 직원을 정지하면 세션 종료를 요청하지만 관리자 전용 함수라 실패할 가능성이 높고 실패는 숨겨요. 실제 차단은 1분 점검과 일부 테이블 규칙뿐이에요.
- **2단계 인증·새 기기 승인:** 변호사·직원 모두 없음(A-2 미구현).
- **020 마이그레이션:** 실행·검증 기록 없음(A-1 G1). `staff_members` 생성문은 배포 묶음 파일에만 있어요.

## 4. 직원·권한 개편 설계

### 4-1. 사무소 기준 데이터 구조 (RB-1, 모든 새 테이블의 바탕)

- **사무소 = `office_id`(tenant).** 지금처럼 대표 변호사 ID를 사무소 ID로 쓰되, 이름을 하나로 정해 모든 업무 테이블(`crm_clients`·`consult_requests` 사무소 연결·`electronic_contracts`·`sales_leads`·소통 기록·보정·작성 요청·감사 기록)에 넣어요.
- **서버 판정 함수 하나:** `office_role(office_id)`(대표/담당 변호사/상담/사무/경리/없음)와 `has_office_permission(office_id, 권한, 대상)`. 모든 RLS·서버 함수가 이 둘을 써요. 020의 `current_tenant_ids`·`tenant_role`을 바탕으로 넓혀요.
- **상담 요청:** 의뢰인이 고른 변호사 → 그 변호사의 사무소 구성원이 볼 수 있게(직원은 권한에 따라). 지금 '승인된 변호사 본인만'(012)을 사무소 기준으로 바꿔요. 다른 사무소는 계속 못 봐요.
- **사건 기록:** 배정 칸 비교(011)를 `office_id` + 권한 + (담당 사건만 범위면) 배정 칸으로 바꿔요. 관리자 제외(제로날리지)는 그대로.
- 회사 단위 설정(AI 사건 분석 과금 모드, 승인 상태, 광고)은 **사무소(대표)** 기준으로 읽어요.

### 4-2. 직원 계정 (RB-2, RB-Q1)

- 직원 초대 수락은 **변호사 가입 신청과 분리**해요. 직원 계정은 변협 서류·통합어드민 심사 없이, 대표 승인만으로 쓰기 시작해요. 통합어드민 변호사 심사 목록에 올라가지 않아요.
- **담당 변호사(LAWYER) 역할**은 마이김변 **승인된 변호사 계정**만 받을 수 있어요(변협 등록 확인). 승인 전이면 '변호사 승인 대기'로 두고, 그동안은 상담 직원 권한으로만 써요.
- 직원 기록을 찾지 못하면 대표로 간주하지 않고 '연결 확인 중' 화면 + 다시 시도. 대표 판정은 '승인된 변호사이면서 다른 사무소 직원 기록이 없음'일 때만.
- 정지·탈퇴는 서버에서 즉시 막아요(모든 판정 함수가 상태 확인) + 세션 종료를 사무소 대표가 할 수 있는 서버 함수로(관리자 함수 재사용 안 함). 화면은 실시간 알림을 받아 바로 잠가요.

### 4-4. 화면 구성 (탭 5개)

1. **구성원:** 대표 포함 카드, 역할·상태·마지막 접속·2단계 인증 여부·연결된 업무폰·담당 사건/리드 수·열린 업무 수. 감독 변호사는 **우리 사무소 변호사**만. 역할 변경·범위 조정(서랍)·정지·탈퇴. 빈 상태 = '첫 직원 초대하기' 버튼과 설명.
2. **초대:** 역할·이메일 제한·유효기간(24시간/48시간/7일)·보내기(복사 / 문자·알림톡 / 이메일), 초대 목록(상태·다시 보내기·만료).
3. **배정:** 미배정 사건·리드 목록과 '배정' 버튼, 자동 배정 규칙(새 상담 요청 → 요청받은 변호사, 이관 사건 → 이관한 직원, 리드 → SL-8 규칙), 직원별 업무량(열린 업무·기한 지남), 일괄 이관(사건·리드·할 일·업무폰 기기 함께).
4. **보안:** 사무소 정책(2단계 인증 필수 대상, 새 기기 대표 승인, 해외 로그인 차단, 동시 접속 수, 자동 로그아웃 시간), 기기·세션 목록(브라우저·업무폰)과 원격 종료, 새 기기 승인 대기. (A-2를 이 탭에 구현)
5. **활동 기록:** 서버 기록(4-6), 사람·종류·기간 필터, 대표 내려받기, 월 1회 점검 알림.

- 통합관리자는 사무소 활동 기록 내용을 보지 않아요(건수 통계만).

## 7. 완료 기준

- **오늘의 업무:** 새 탭·다른 기기·직원 계정에서 같은 숫자가 보이고, 카드·업무함·사이드바 배지 숫자가 같은 정의로 맞아요. 운영에서 테스트 사건·시연 수납 0건. 업무함 '기한 지남'은 근거(응답 기한·법원 기한·사무소 마감 등)가 있는 항목만이고, 모든 바로가기가 해당 단계·섹션으로 열려요. 보정·서류·영업 DB·업무폰·카톡·계약·수납 항목이 각 트랙 기능과 함께 나타나요. 배너 문구 0건(공지만), 빈 상태에 버튼, 첫 로딩 스켈레톤.
- **직원·권한:** 직원이 초대 링크로 들어와 대표 승인 뒤 **대표 사무소의 상담 요청·배정 사건을 서버에서** 볼 수 있고, 다른 사무소 자료는 못 봐요(RLS 시험). 직원 계정이 통합어드민 변호사 심사 목록에 올라가지 않아요. 권한 표가 실제 설정에서 만들어지고, 표에 '없음'인 기능은 메뉴·버튼·서버 모두에서 막혀요. 대표 데스크톱 사이드바에 메뉴 14개가 모두 보여요(지금은 8개). 🔒 변호사 전용 일은 직원 계정으로 API를 직접 불러도 거절돼요. 정지하면 수 초 안에 직원 화면이 잠기고 서버 요청도 거절돼요. 활동 기록이 다른 기기에서도 보이고 수정·삭제가 안 돼요. 2단계 인증·새 기기 승인이 동작해요.
