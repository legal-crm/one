> **문서 버전**: v1.1 (기획 v1.0 + 1·2단계 구현 결과)
> **작성일**: 2026-09-30
> **대상**: 변호사 어드민 `상담 채팅` 탭 (`src/components/LawyerRole.tsx` → `src/components/lawyer/chat/`)
> **근거**: 화면 캡처·코드 읽기, 로컬 dev 서버(더미 Supabase)에서 puppeteer 화면 확인. 운영 DB·실기기 확인은 하지 않음.

## 1. 문제와 방향

- **영역 구분**: 세 패널이 한 카드 안에서 1px 선으로만 나뉘었고, 대화창 접수 카드의 수치 4개(총 채무·소득·관할·추심)가 우측 분석서와 중복됐다. 우측은 같은 모양 카드 6개가 이어져 위계가 없었고, 수임 전환 버튼·메모는 맨 아래에 있었다.
- **가독성**: 10·11px 글자 25곳, 대비 미달 `text-slate-400` 13곳, 의미 없는 색·이모지, 말풍선 줄바꿈 소실, 날짜 구분 없음, 같은 가명 스레드 구별 불가.
- **방향**: 영역 하나에 역할 하나 — 메시지함은 고르기, 대화는 대화만, 가계 진단 분석서는 판단 근거와 행동. 같은 수치는 한 화면에 한 번만. 색은 의미가 있을 때만 (빨강 = 법적 위험, 주황 = 확인 필요, 초록 = 결과·완료).

**결정 사항 (2026-09-30)**: 내 말풍선 연한 네이비 / 분석서 탭 3개 / 중간 폭은 분석서 서랍 / '자주 쓰는 답변' 기본 문구 3종 사용 / 1·2단계 한 번에 반영 (1단계 수정 사항을 새 구조에 바로 적용).

## 2. 구현 결과

### 2-1. 레이아웃

| 작업 영역 폭 (사이드바 접힘 반영) | 해당 화면 예 | 구성 |
|:---|:---|:---|
| 1360px 이상 | 1920 | 메시지함 320 / 대화 / 분석서 400 |
| 1100~1359px | 1440, 1280(사이드바 접힘) | 288 / 대화 / 360 |
| 720~1099px | 1280(펼침), 1024 | 272 / 대화 + 분석서 서랍(380), 대화 헤더 아래 핵심 수치 1줄 |
| 720px 미만 | 모바일 | 한 화면씩 (목록 → 대화 → 분석서) |

- 폭은 `ResizeObserver`로 작업 영역을 재서 정한다 (`useElementWidth`).
- 패널 3개를 12px 간격으로 분리, 채팅 탭 바탕 `slate-100`, 대화 캔버스 `slate-50`, 헤더 56px 정렬.
- 모바일: 하단 탭바 높이만큼 아래 여백 (`--mobile-gnb-height`), 높이 `100dvh` 기준.

### 2-2. 영역별

- **메시지함**: 검색(가명·요청번호·내용), 필터(전체 / 답변 필요 N / 상담 중 / 수임 후), 3줄 항목(가명·`#번호`·시각 또는 '대기 N시간' / 미리보기 / 상태 칩·채무), `<button>` + ↑/↓ 이동. `#번호`는 같은 가명이 2건 이상일 때만.
- **대화**: 헤더(가명·#번호·상태 칩·상담 요지·접수일·안심 가명 상담), ⋯ 메뉴(사연 원문 보기·고객관리에서 열기·요청 번호 복사). 신청서 카드는 사연만(수치 칩 삭제). 날짜 구분선, 같은 발신자 5분 이내 묶음, 줄바꿈 보존, 긴 URL 줄바꿈, `https` 링크(`noopener noreferrer`), `[제목]` 굵게, 시스템 이벤트 색 구분, `✓` 삭제. 열면 최신 메시지 위치, 새 메시지는 맨 아래 근처일 때만 따라가고 아니면 '새 메시지 N개' 버튼.
- **작성창**: 1~6줄 자동 높이, Enter 전송·Shift+Enter 줄바꿈, 한글 조합 중 Enter 무시, 터치 기기는 Enter = 줄바꿈. 스레드별 임시 입력 보관. '자주 쓰는 답변' 3종은 입력창에 넣기만 한다. 미승인 계정은 입력·전송 비활성 + 안내.
- **가계 진단 분석서**: 탭 [요약 | 채무·재산 | 메모]. 요약 = 핵심 지표 2×2 → 확인 필요 사항 → 변제 시뮬레이션 → 인적 사항. 채무·재산 = 채권자 표·유형 구성 막대·재산·생계비. 메모 = 고객관리 상담 메모(`crmExt.notes`)와 같은 저장소.

### 2-3. 함께 고친 결함

| 결함 | 조치 |
|:---|:---|
| 채팅 탭 전송이 승인 확인(`handleSendChat`)을 우회 | `handleSendChat(reqId, text)`로 통합, 모든 전송이 승인 확인·활동 로그를 거침 |
| 한글 조합 중 Enter 처리 없음 | `isComposing`·`keyCode 229` 확인 |
| 스레드를 열어도 최신 메시지로 이동하지 않음 | 스레드마다 타임라인을 새로 마운트해 맨 아래에서 시작 |
| 상태 라벨 누락 (개시 결정·변제 중·면책·종결이 '상담중') | `src/constants/consultStatus.ts` |
| 라벨 폴백 오류 (무직 → 프리랜서, 사별·미기재 → 이혼) | `src/constants/clientProfileLabels.ts`, 값이 없으면 '미기재' |
| 내부 비망록이 메모리에만 있어 새로고침 시 유실 | 메모 탭이 `crmExt.notes`에 저장 (저장 직전 `loadCrmData()`로 최신 데이터 기준) |
| 채팅 시뮬레이션 입력을 따로 조립해 엔진이 읽지 않는 필드명 사용 (월세·의료비·교육비·사행성 손실 누락) | `mapToRehabUserInput`으로 통일 |
| `mapToRehabUserInput`에 24개월 특례(`specialCondition`) 누락 | 추가 — **제안서 워크스페이스 수치도 특례 해당자는 달라질 수 있음** |
| 채팅 탭이 `getDisplayClientName`을 거치지 않음 | 목록·헤더·말풍선 이름 모두 표시 규칙 적용 |
| 입력 글자마다 LawyerRole 전체 재렌더 + 스레드 필터 반복 계산 | 입력 상태는 작성창 안, 스레드 목록은 `useMemo`로 한 번 계산 |

`filterAndSanitizeMessagesForLawyer`(다른 변호사 정보 차단)는 동작 변경 없이 `chatSelectors.ts`로 옮겼고, 옮기기 전 코드와 정규화 비교로 동일함을 확인했다.

## 4. 기획 대비 변경점

- **분석서 주요 버튼 위치**: 하단 고정 바 → **분석서 헤더 오른쪽**. 실무 퀵툴 버튼 기본 위치(화면 우측 하단)가 하단 바를 가렸다. 헤더의 소득 유형 칩은 인적 사항 '직업'과 중복이라 뺐다.
- **서랍 모드(720~1099px) 작성창**: 전송 버튼이 퀵툴 기본 위치에 가려서, 단축키 안내를 입력창 아래로 옮기고 아래 여백을 두었다.
- **실무 퀵툴 헤더 버튼(A7)**: 작업 중 다른 세션이 `quickdock/` 파일을 동시에 수정하고 있어 이번에는 퀵툴 파일을 건드리지 않았다. 채팅 쪽은 `onOpenQuickDock` 연결 지점과 `data-quickdock-trigger` 표시만 준비했고, 넘기지 않으면 헤더 버튼은 나오지 않는다.
- **필터 칩**: 좁은 폭에서 한 줄에 들어가도록 건수는 '답변 필요'에만 표시, '수임 이후' → '수임 후'.

## 5. 검증

- `npx tsc --noEmit`: 오류 229건으로 작업 전 기준선과 같음 (오류 목록 동일, 새·수정 파일 0건).
- `vite build`: 통과.
- 로컬 dev 서버(더미 Supabase 주소, 실제 DB 미접속) + QA 픽스처로 puppeteer 확인 24항목 통과: 최신 메시지 위치, 총 채무 수치 1회, #번호, 12px 미만 글자 0건, 한글 조합 Enter, Shift+Enter, 전송, 자주 쓰는 답변 삽입, 메모 저장·건수, 긴 URL, 링크 속성, 라벨 폴백, 상태 라벨, 서랍 열기·Esc, 분석서 접기·다시 열기·설정 저장, ↓ 키 이동, 미승인 계정 비활성, 1920/1440/1280 주요 버튼·전송 버튼 가림 없음, 모바일 작성창이 탭바 위.
- 확인하지 못한 것: 실제 Supabase 저장·조회, 실기기(iOS/Android) 한글 입력, 스크린리더.

## 6. 남은 일

- **실무 퀵툴 헤더 버튼 연결** (A7): `LegalQuickDock`에 외부 버튼으로 메뉴를 여는 모드를 추가하고 `LawyerChatWorkspace`에 `onOpenQuickDock`을 넘긴다.
- **3단계 (선택)**: 스레드별 미확인 수, 자주 쓰는 답변 편집·저장, 전송 실패 재시도(`saveConsultMessage`가 성공 여부 반환), 로딩 스켈레톤(App의 첫 동기화 신호 필요).
- **체험 모드 배너**: 미승인 계정의 상단 배너 높이만큼 채팅 화면 아래가 잘린다 (기존 동작, 모든 탭 공통).
- **범위 밖 발견 사항**
  - `targetLawyerId`가 서버에 저장되지 않는다 (`saveConsultMessage`·`loadConsultMessages`에 필드 없음, 컬럼 없음). 비교 상담에서 의뢰인이 특정 변호사에게 보낸 메시지를 가리는 필터가 서버에서 불러온 데이터에서는 동작하지 않아, 참여한 다른 변호사에게 보일 수 있다. 코드상 확인, 재현 안 함.
  - 제안서 계산의 24개월 특례 반영은 이번에 고쳤으므로, 특례 해당 의뢰인의 기존 제안서 수치와 새 계산이 다를 수 있다.
